# E3 retrospective · Training core

2026-10-19 → 2026-10-20 · `v0.3.0` · held 2026-10-20

## What worked

- The delivered functionality was excellent after the checkpoint feedback, and a large feature took about one day.
- After the workflow changes of the E2 retrospective, speed and token usage per task improved; no change to the Claude workflow is required.

## What did not work

1. **Checkpoint E3-A was proposed but the PM carried on with the next tasks**, so the user effectively got a single checkpoint for the whole epic. That produced one large round of feedback and many fixes. The hard gate already exists in `CLAUDE.md` (an open 👤 checkpoint blocks the next task), so the rule alone did not hold. The user will review the checkpoints more closely at the epic-planner stage; the PM must not skip them.
2. **E3 consumed 38% of the weekly limit in a day and a half.** Acceptable for the size and result, but at this pace the weekly limit runs out around Wednesday (as the week before) and work waits until Monday. E4 and E5 fit in a week; more epics per week would not.

## Usage data (`/usage` and `/context`)

- Subagents by share of usage: frontend-developer 24% (legacy agent, since split), compose-ui-developer 21%, kotlin-core-developer 17%, planner 6%, pr-reviewer 3%, backend-developer 3%, ux-reviewer 2%, pr-creator 2%. **Developer agents are about 65%; planning and review about 11%.** Splitting the developer agent did not reduce usage.
- 25% of usage happened at more than 150k context; 12% went to always-on context over 40k.
- Empty-session baseline is 39k tokens: system tools 22.5k (not trimmable), memory and CLAUDE.md 5.6k, skills 6k (31 skills), MCP 0.6k (loaded on demand). Only about 12k is under the user's control, so trimming has a small payoff and is low priority.

## Decisions

- **ADR-41: switchable executor.** Implementation (developers and PR creation) can be handed to an external free-tier model in opencode, driven manually by the user, while planning and review stay in Claude; the user switches per task (typically above ~70% weekly usage) and can return to the current flow at any time. One review round with opencode, then Claude takes over. Prepared on branch `docs/opencode-executor-mode` (ADR-41, root `AGENTS.md`, `CLAUDE.md`, `planning/06` §2.5, planner and pr-reviewer notes), **not merged**.
- **E4 runs with the current flow** (executor `claude`). The branch is applied when the user asks, planned for E5, with the first opencode task as a pilot on a small task (compare review findings and time against E3).
- Checkpoint E3-A was merged into E3-B earlier by user decision; the lesson is recorded in the working rules (checkpoints per functionality, hard gate).
