# E4 retrospective · Food diary

2026-10-20 → 2026-10-21 · `v0.4.0` · held 2026-10-21

## What worked

- Token usage per task improved a lot compared with E3; the user is happy with it.

## What did not work

1. **Repeated UX defects and inconsistent UI between screens.** The result felt like a patchwork of screens and functionalities, not the professional app the user expects. Feedback given at one checkpoint had to be repeated at later ones. Examples the user had to repeat:
   - Icons instead of text for actions such as remove or add.
   - No "Deshacer" confirmation when a delete is done by swipe.
   - Tapping a food or an exercise must open its detail.
2. **Suspected cause: the `ux-reviewer` agent is not doing its job.** It reviews each task plan in isolation, so conventions already decided in earlier tasks and checkpoints are not carried forward.

## Decisions

- **The `ux-reviewer` fix is deferred to the UI-refinement epic (E8), by user decision.** Goal: later changes never repeat the same mistakes and the app stays professional and modern through small iterations. Recorded as a work item in `planning/epics/E8-finalization.md` ("UX consistency guardrails"). The agent file is not changed before then.
- Until E8, the PM keeps appending UI feedback to the E8 table and fixes only functional bugs now.

## Actions

- E8: collect every UX convention the user has stated (checkpoint feedback in `tasks/todo.md` and the E8 table), consolidate them in the design system, make `ux-reviewer` check plans against them, and verify with a cross-screen consistency audit.
- E5 planning: the epic-planner confirms the 👤 checkpoints with the user as usual.
