# Coach design: evidence base and default rules

Design base of the performance assistant (E13) and of the data it needs (E10-E12). Decisions: ADR-76 (coach), ADR-77 (AI provider and cost), ADR-78 (profile and catalogue).

**Principle:** every rule has a source, a common practice or a "design decision" label. No figure exists for convenience. Every source was checked before the E13 breakdown (2026-10-29, §10); the cardio and trainer-journey sources on 2026-11-01 (§10 29-66).

## 1. What the coach does

**User inputs:**
- **Intention:** "Ganar fuerza", "Ganar musculatura", "Perder grasa", "Recomposición" or "Mantenimiento".
- **Static preferences** (Preferencias): training place (home, gym, other), available equipment and, optionally, days per week and session length.
- **Discomfort:** logged per exercise when it happens (E12). It blocks load increases (§7) and, at levels 4-5, keeps the exercise out of the next block's proposal (§7, §12.4).
- **Intake ("Para conocerte", user decision 2026-11-01, §12.1):** training age, current situation (first time, training continuously, returning after a break, returning after an injury), injury status and affected area, best lifts before the break or injury, known maintenance and cutting calories, and free text. Every answer is a **provisional prior**, labelled "según lo que nos contaste", that measured data replaces (§2, §12.1). Editable at any time.
- **Feedback at the end of a block:** "¿Cómo te ha ido?" and, optionally, "Priorizar" / "Mantener" per muscle group (§12.4).
- **Self-reports kept minimal:** RPE per set and the discomfort log, plus the block feedback; no pump, soreness or readiness questionnaires. *Common practice in leading apps* (product benchmark); soreness is a poor signal anyway (§7).

**Phase:** each block runs in one phase (cut, gain, maintenance, recomposition, regain, minimal; §12.3). The coach proposes a phase change **only at the end-of-block review**; the user accepts or keeps the current phase.

**Output:** a plan in 4-week blocks (design decision, §9) with:
- the routines of each week, using the existing routine model;
- calories and macros;
- progression per exercise;
- expected outcomes (weight, body fat, circumferences or e1RM) **only when the plan can justify them**. The user never enters target numbers.

**Review:** at the end of each block; earlier only if the preferences change or the user asks.

**One behaviour, "Entrenador" (user decisions 2026-11-01; no mode selector; amends ADR-76's "adjustments are proposals accepted one by one", "suggestions never rewrite planned values" and "nothing is applied without acceptance"):** the user accepts or edits the whole plan (new block) and any phase change; **everything inside an accepted block applies on its own**, each change visible with its reason and undoable:
- load progression: the §3 increase and the 5 % drop, written to the next session of that exercise, with "Deshacer";
- weekly calorie changes inside the safe band of §4, with "Deshacer";
- deloads, scheduled or triggered (§3), which the user can cancel, or start one himself.
Autonomy support, which includes explaining the rationale and offering choice, is associated with better health behaviour [Ntoumanis et al. 2021; *strong* for the mechanism, small-to-medium effects]; which changes a trainer makes without asking has no evidence (*common practice*), so the split is a *design decision*: automatic changes are small, bounded, explained and reversible; the long-term direction (phase, block) stays the user's.

**Grounding:** the model only describes app features, screens and data that exist; the server validates its output against the list of features and the summary, and drops any text that mentions anything else (anti-pattern seen in AI coaches: inventing features). *Common practice in leading apps* (product benchmark, not science).

**Division of work:** every calculation (BMR, activity, adaptive expenditure, weight trend, progression, e1RM, adherence, deload trigger, phase triggers) is deterministic, in SQL or TypeScript, and testable. The model only selects within validated options and explains; its output is structured (JSON schema) and validated before it is shown. The model never writes to the database. §12 marks, per stage, what is a rule, what is model judgement and what the user decides.

## 2. Derived values (confirmed by the user)

| Value | How it is computed | Confidence without history |
|---|---|---|
| Basal expenditure | Mifflin-St Jeor with sex, age, height and weight (profile, `04` §1) | High (validated equation) |
| Activity level | Starts from `profiles.activity_level` (ADR-78); the coach proposes a change from Health Connect steps (bands of Tudor-Locke et al. 2011), active calories when there are no steps, and the completed sessions per week (3 or more raise a measured level by one). Exact mapping in `04` §7.1. Sessions alone never change the profile level (it already includes training) | Low: shown as provisional |
| Total expenditure | BMR × activity factor (`04` §1.3) without a reliable diary; with one, the capped 28-day intake, plus a weight-change term only when the trend has 4 weekly averages and 8 weigh-in days, clamped to one top-of-range rate (`04` §7.2-§7.3; *design decision*, T-180) | Improves with months of data |
| Weight trend | Slope of weekly averages, with its confidence interval (§5) | Depends on the number of weigh-ins |
| Experience | The **higher** of the self-reported training age (intake) and the app history class (`04` §7.5). Self-reported consistent lifting: under 6 months beginner, 6 months to under 2 years intermediate, 2 years or more advanced. ACSM: intermediate "approximately 6 months of consistent RT experience", advanced "years of RT experience" [ACSM 2009; *strong*, expert-based]; the 2-year cut for "years" is a *design decision* | Self-reported until the history class is equal or higher; shown as "según lo que nos contaste" |
| Situation | Intake answer: first time, continuous, returning after a break, returning after an injury. "Returning" is also set by the app after 28 days with no completed session (§12.5) | Self-reported; ends when the regain phase ends (§12.3) |

**Returning lifters keep their experience class (amends the earlier "without history: beginner").** ACSM 2009 counts people "who have not trained for several years" as novices, but retraining is faster than first-time training: after 10 weeks of detraining, losses "were regained rapidly", with larger leg-press strength and muscle-area gains in the first 5 weeks of retraining than in the same weeks of first-time training [Halonen et al. 2024; *moderate*, RCT, 55 untrained adults]; women detrained 30-32 weeks lost strength "but not to pretraining levels" and fibre area rose significantly within 6 weeks of retraining [Staron et al. 1991; *moderate*, small n, women]. The evidence is on short breaks and on people who were trained for months, not years-long layoffs; so this is a *design decision built on that evidence*. **What experience drives (one rule):** the gain rate and protein (`04` §8) and the default number of days when the user sets none (beginner 3, intermediate and advanced 4, `04` §9.1; inside ACSM's 2-3 / 3-4 / 4-5 days by status [ACSM 2009]). It does **not** change the volume: every class, the returning lifter included, starts at the 10 weekly sets of §3 (no verified source for a lower beginner dose: *none*; the former "beginner 8 sets" is dropped). It never sets starting loads (§12.2).

**Intake priors and their handover (*design decision*, §12.1):** self-reported values are labelled provisional and replaced by measured ones as soon as the measured rule's own threshold is met. Self-report is biased: athletes under-reported energy intake by 19 % against doubly labelled water (11 studies) [Capling et al. 2017; *strong*, athletes]. No study gives a correction factor or a weighting between a remembered maintenance and an equation (*none*), so the app applies no correction: the known maintenance replaces BMR × factor as the expenditure prior until the adaptive expenditure qualifies (28-day diary at 70 % logged days, 4 weekly averages and 8 weigh-in days), then the adaptive value replaces it and the card says so once ("Ahora usamos tus datos reales: tu gasto medido es de 2.450 kcal."). Known cutting calories are shown as context only, never used in a calculation.

**Intake extraction (user decision 2026-11-01, PM on the fitness-scientist's recommendation):** the user may answer the intake in his own words; the model extracts a structured profile (training age, situation, injured area, pre-break bests as weight × reps per lift, known maintenance and cutting calories) as JSON, which the server validates (allowed values, plausible ranges, catalogue lifts) and shows as a filled form the user confirms or corrects field by field. Nothing extracted is used until confirmed; empty fields stay empty (never guessed). The free text itself is also sent verbatim later (§8). *Common practice in leading apps* (product benchmark, not science).

**Confirmation rule:** each block shows a card with the derived values, their source and the missing data. The user accepts or edits them. A value is not used until confirmed; until then it is shown as provisional. A confirmed value is asked again only when its new estimate falls outside the uncertainty of the confirmed one.

**Intake completeness:** adaptive expenditure uses only days with a logged diary; days without entries are excluded, not counted as zero. Below 70 % logged days in the window (design decision) the estimate is shown as unreliable and the coach does not propose calorie changes from it.

**Data cleaning before any calorie change (*common practice in leading apps*, product benchmark; thresholds are *design decisions*):** a day counts as logged only if it looks complete: a day under 40 % of the median of the logged days of the 28-day window is partial and is excluded from the expenditure anchor **and** from every count of logged days (the 70 % reliability, the weekly gate below). One rule for the whole app, the one already built for the anchor (`04` §7.3, T-180); it replaces the earlier "50 % of the target" draft, which had no target before the first plan. No "incomplete day" control is added (scope). Missing weigh-ins are never filled in; the trend uses the weigh-ins that exist (§5). A week with fewer than 5 complete diary days (70 % of 7, the rule above applied per week) or fewer than 3 weigh-ins changes no calories; the report says why ("Esta semana faltan registros: no cambiamos tus calorías.").

## 3. Training

- **Frequency:** each muscle group at least twice a week when the available days allow it (two or more training days); with one day, one full-body session. When weekly volume is equated, frequency itself shows no clear hypertrophy difference [Schoenfeld, Grgic, Krieger 2019]; twice a week is the practical way to spread the volume [Schoenfeld, Ogborn, Krieger 2016]. *Common practice built on that evidence.*
- **Volume:** starting point of 10 weekly sets per muscle group. Dose-response is positive [Schoenfeld, Ogborn, Krieger 2017], with diminishing returns at higher volumes, much more pronounced for strength than for hypertrophy [Pelland et al. 2026].
- **Intensity:**
  - Strength ("Ganar fuerza"): heavy loads on the main lifts, undulating by session within the week: heavy 3-5, medium 5-6, light 6-8 reps (`04` §9.5); isolation 10-15. No singles or doubles are planned (recreational lifters logging their own RPE; *design decision*). Replaces the earlier "1-6 reps".
  - Hypertrophy: 6-15 reps. Low and high loads give similar hypertrophy when sets are taken close to failure [Schoenfeld, Grgic et al. 2017].
- **Proximity to failure:** 1-3 reps in reserve on main work. Training to momentary failure shows no hypertrophy advantage over stopping short of it, and set failure only a trivial one [Refalo et al. 2023]; the 1-3 range is *common practice built on that evidence*. Reps in reserve are derived from the logged RPE (RIR = 10 − RPE); there is no separate RIR field (ADR-76).
- **Progression:** double progression. Work inside the rep range; when every working set reaches the top of the range at RPE 8 or less, raise the load to the next available increment. ACSM: a 2-10 % load increase when the individual can perform the current workload "for one to two repetitions over the desired number" [ACSM 2009; *strong*, position stand, expert-based]; double progression is that rule applied to a rep range. With light dumbbells the next available increment can exceed 10 % (equipment limit, *design decision*: still the next increment). **Applied automatically** to the next session, with its reason and "Deshacer" (§1). **Where it lives and who computes it:** inside an accepted block, when a session completes, the **server** computes the decision and the step (the increment from the user's plates and handle, `04` §4.9, so the plate settings must be readable on the server) and writes the new weight to the planned sets of the block's routines that hold that exercise with the same rep range (a routine serves every week, so the new planned weight is the baseline from the next session on; ADR-50 planned values); on a raise the planned reps go to the bottom of the range. If the user's "Actualizar automáticamente" (ADR-70) is on, it runs first and the coach's change is applied on top. "Deshacer" restores the planned weight and reps from before the coach's write. Outside a block it stays a live-session suggestion. Example reason: "Subimos a 62,5 kg: la última vez hiciste 12 repeticiones en todas las series."
- **Failed sessions:** when most working sets miss the bottom of the range in two consecutive sessions of the exercise, lower the load 5 %, rounded to the available increment. *Design decision.* Applied automatically, like the increase.
- **Rest between sets:** 2-3 min on main multi-joint lifts, 1-2 min on isolation exercises. Trained lifters need more than 2 min to maximise strength [Grgic et al. 2018]; 3 min beat 1 min for strength and thigh hypertrophy [Schoenfeld et al. 2016]; for hypertrophy alone the difference is small [Singer et al. 2024]. The block creator writes these rests into the routines.
- **Exercise order:** the priority multi-joint lifts go first in the session; strength improves most on exercises done early, hypertrophy is similar in any order [Nunes et al. 2021].
- **Periodization ("Ganar fuerza"):** load and reps vary within the week across the block (undulating) instead of one fixed range; a small strength benefit, larger than linear periodization in trained lifters, and no hypertrophy difference [Moesgaard et al. 2022; Williams et al. 2017]. Other intentions keep one rep range per exercise.
- **Range of motion:** full range by default; differences against partial range are small [Pallarés et al. 2021; Wolf et al. 2023]. A technique note, not a computed rule.
- **Cardio:** concurrent aerobic training does not compromise whole-muscle hypertrophy (SMD -0.01) or maximal strength (SMD -0.06); only explosive strength is attenuated (SMD -0.28), more when both are in the same session than 3 h or more apart; training status, cycling vs running, more or fewer than 5 sessions a week and age did not moderate it [Schumann et al. 2022, 43 studies; *strong*]. At fibre level there may be a small negative effect (SMD -0.23), possibly only with running [Lundberg et al. 2022; *moderate, preliminary*]. So the coach does not reduce cardio or steps for strength or muscle goals.
- **Cardio prescription (proposed, ADR-85; every source re-checked online on 2026-11-01, §10 29-50; E13 Q23-Q29 resolved 2026-11-01: Q27 and the placement inside the routine by the user, the rest by the fitness-scientist on this evidence).** The coach prescribes cardio as a trainer would. Every figure is computed by the server's rules, never by the model (§1). Grades: *strong* = guideline or meta-analysis of trials; *moderate* = single trial or review; *weak* = observational or expert opinion.
  - *Dose (weekly minutes of moderate aerobic work):* the adult guideline is 150-300 min moderate or 75-150 min vigorous per week (so one vigorous minute counts as two moderate), and bouts of any duration count [WHO 2020, Bull et al.: strong recommendation, moderate-certainty evidence; ACSM 2011, Garber et al.: ≥ 30 min on ≥ 5 days, ≥ 150 min]. More than 300 min may add benefit (WHO, conditional). **"Perder grasa": band 150-300**: aerobic exercise lowers weight 0.52 kg, waist 0.56 cm and body fat 0.37 % per 30 min a week, linearly up to 300 min, with clinically important waist and fat changes from about 150 min [Jayedi et al. 2024, 116 RCTs; *strong*, but in adults with overweight or obesity (mean age 46) and supervised aerobic training of 8 weeks or more]; 150-250 min gives only a modest loss and adds to the diet only with moderate (not severe) restriction, more than 250 min a clinically significant one [Donnelly et al. 2009, ACSM; *strong*]. **Every other intention: 150**, the guideline minimum: it is there for health, not for the goal; it does not compromise hypertrophy or maximal strength (above). An older meta-analysis links more frequent and longer endurance work to smaller strength and hypertrophy gains (r -0.26 to -0.75) [Wilson et al. 2012; *moderate*, correlational], a frequency effect the newer one did not find [Schumann 2022]: evidence is mixed, so the non-fat-loss intentions stay at the minimum. **Resolved (E13 Q23):** the coach proposes 150 for every intention, inside the band 150-300 for "Perder grasa" (the diet carries the deficit, Donnelly 2009; the lowest dose with clinically important fat and waist change, Jayedi 2024); the user edits it freely. The default is a *design decision*.
  - *Intensity:* moderate = the user can still talk comfortably; the last talk-test stage with comfortable speech tracks the ventilatory threshold [Foster et al. 2008, healthy young adults; *moderate*] and is proposed for aerobic prescription [Vieira et al. 2022, systematic review in cardiopulmonary patients; *moderate*, other population]. Shown as the pace word "suave" with that explanation; no heart-rate zones (no verified source for a zone formula here).
  - *Type:* continuous moderate work only in this pass. Intervals give similar fat loss (SMD -0.82 vs -0.85 in running programmes) with about 40 % less time [Wewege et al. 2017; *strong*, adults 18-45 with overweight or obesity], but intervals added to lifting reduce lower-body strength gains (ES -0.248) [Sabag et al. 2018; *strong*, small effect]; so intervals are not prescribed (E13 Q28, resolved: continuous "suave" only, no heart-rate zones). Cycling vs running: *mixed* (running interfered more in Wilson 2012 and, for type I fibres, in Lundberg 2022; no difference in Schumann 2022; in Wewege 2017 cycling programmes showed no fat loss). So "low-impact machines first" is a *design decision* (joint comfort, availability), not an evidence rule. The exercise comes from the catalogue's `cardio` pattern, filtered by place and equipment like any other slot; walking needs no equipment.
  - *Modality and swap (E13 Q28b, resolved by fitness-scientist, 2026-11-01; user requirement: the user switches between the cardio he has):*
    - *Equivalence:* WHO defines moderate intensity by absolute (3 to < 6 METs) or relative effort (5-6 on a 0-10 scale) and lists walking, running, swimming and cycling as aerobic activity; slow walking is light [WHO 2020, glossary; *strong*, definition]. The dose is minutes at relative moderate effort ("suave", talk test), so **a minute counts the same on any cardio exercise and a swap never changes the minutes**; walking counts only at a brisk pace ("a paso ligero"). Fat-loss trials did not report a credible difference by intensity, and the modality subgroups were not reported in the main text [Jayedi 2024]; Wewege 2017's cycling subgroup showed no fat loss (*mixed*, one subgroup), not enough to adjust the minutes per modality. No adjustment factor per modality (none verified).
    - *Cardio equipment (user decision 2026-11-01: cardio machines leave `machine` and form their own category; details resolved by fitness-scientist, E13 Q28b):* five new values of `public.equipment` (precedent: `band_long`, ADR-83), one per real machine so "bike and treadmill, no lifting machines" is expressible: `cardio_bike` ("Bicicleta estática": `stationary-bike`, `air-bike`), `treadmill` ("Cinta": `incline-treadmill-walk`, `treadmill-running`), `elliptical` ("Elíptica": `elliptical-trainer`), `rower` ("Remo": `rowing-machine`), `cardio_other` ("Otra máquina de cardio": `ski-erg`, `stair-climber`). Those catalogue rows are re-tagged from `machine`; `walking` and `running` stay `bodyweight` (no machine, always available). `machine` then means lifting machines only. In "Mi entrenamiento" ("Equipamiento") the five chips sit in their own group titled "Cardio", under the lifting chips, with the helper "Sin máquinas de cardio, el entrenador te propone caminar a paso ligero."; place seeds as today ("Gimnasio" selects every value, "Casa" none of the cardio ones); "Antes de empezar" (T-176) shows a "Cardio" summary row ("Bicicleta estática, Cinta" or "Sin máquinas · caminar") that opens "Mi entrenamiento" (E13 Q17 pattern). **Existing rows:** the migration adds no cardio value to any saved equipment list (no silent gain), and the coach does not treat an old `machine` as cardio (the row reads "Sin máquinas · caminar" until the user picks); "a gym with none selected: everything" (`04` §9.4) is unchanged.
    - *Default (ranked, design decision: low impact, steady pace, and running and the HIIT-style moves interfere more or are intervals):* the most-logged cardio exercise of the last 8 weeks (`coach_summary`) if it is inside the equipment; else, by the selected machines, `stationary-bike` (bike), `elliptical-trainer` (elliptical), `incline-treadmill-walk` (treadmill: walking is its default, running only by swap), `rowing-machine` (rower); with no cardio machine (or only `cardio_other`), `walking` outdoors at a brisk pace. Never by default: `running`, `treadmill-running`, `air-bike`, `ski-erg`, `stair-climber` and the non-continuous moves (burpees, jumping jacks, jump rope, battle ropes, high knees, mountain climbers, heel flicks).
    - *Swap:* on a cardio slot the alternatives are every catalogue `cardio` exercise with a duration metric whose equipment is one of the user's cardio values or `bodyweight` (so walking and running are always offered; a treadmill adds incline walk and treadmill running; a bike adds stationary and air bike), not the `exercise_alternatives` pairs (only 2 cardio pairs exist); only cardio is offered there, and a lifting slot never offers cardio. The minutes, the position (last) and the reason stay; the swap applies to every week of that routine (T-179 rule). Copy: the row "Bicicleta estática · 25 min · suave"; the swap list title follows T-179; one line under it "Cuentan los mismos minutos con cualquier cardio, a ritmo suave."; walking reads "Caminar a paso ligero".
  - *Placement:* in a session that has both, cardio goes **after** the lifting, in every session (simpler than only before leg work, and the order costs nothing for the aerobic side): lifting first gives more lower-body dynamic strength (+6.91 %, 95 % CI 1.96-11.87) with no effect on hypertrophy, static strength, aerobic capacity or body fat [Eddens et al. 2018; *strong*]; lower-body 1RM +3.96 kg (0.81-7.10) and no effect on VO2max [Murlasits et al. 2018; *strong*]. Separate days (or 3 h or more apart) would also avoid the small explosive-strength attenuation [Schumann 2022]; the user chose cardio inside the routine (2026-11-01), which costs only that.
  - *In the routine (E13 Q26, resolved; design decision on the evidence above):* cardio is the **last exercise of each lifting routine** of the block, never a separate day. The weekly minutes are split evenly across the week's routines in whole 5-minute units (remainder to the first routines), at most 60 min per routine; minutes that do not fit under that cap are shown as "por tu cuenta" (any cardio exercise the user logs that week counts, `04` §4.6). Cardio does **not** use "Duración de la sesión" (recommended; the user confirms in E13 Q30): the lifting keeps the time and volume of §3, and the preview shows each routine's total time with the cardio. One cardio exercise per routine, one set of planned minutes only (no reps, no RPE, no rest timer).
  - *Daily steps:* a target next to the cardio minutes = max(28-day average rounded down to 500, floor), never below the current average (the existing "never reduce steps" rule, *design decision*). Floor candidates: all-cause mortality falls until about 6 000-8 000 steps a day from 60 years and 8 000-10 000 under 60 [Paluch et al. 2022, 15 cohorts]; 7 000 vs 2 000 steps: HR 0.53, inflection around 5 000-7 000, 10 000 "viable for those who are more active" [Ding et al. 2025, dose-response meta-analysis]; 8 000 vs 4 000: HR 0.49 [Saint-Maurice et al. 2020]. *Weak* (observational, mortality only; no verified evidence for a goal-specific steps target, so none is set). Step cadence added nothing once total steps were counted [Paluch 2022; Saint-Maurice 2020], so no pace target for steps. **Resolved (E13 Q24):** floor 7 000 for every age (Ding 2025's target; inside Paluch's 6 000-8 000 from 60, at the lower edge of the evidence under 60, where a higher average is kept anyway); the target is not editable. Mapping to the activity level stays `04` §7.1 (Tudor-Locke bands).
  - *Calories:* the planned cardio is **not** added to the expenditure at plan time. Exercise energy is partly compensated (mean 18 % ± 93 %, approaching 84 % in ~80-week interventions) [Riou et al. 2015; *moderate*, very variable], and no wrist device estimated energy expenditure with an error below 20 % [Shcherbina et al. 2017; *moderate*]. The adaptive expenditure (§2) absorbs the cardio actually done, and the in-block change (§4) corrects a rate outside the trend. *Design decision built on that evidence* (E13 Q25, resolved).
  - *Cardio by phase (§12.3; user request 2026-11-01):* the weekly target follows the **intention**, not the phase, except the minimal phase:
    - cut, gain, maintenance, recomposition, regain: 150 min proposed; "Perder grasa" keeps its 150-300 band in every phase, regain included (cardio does not impair hypertrophy or maximal strength [Schumann 2022], so it does not compete with regaining). The cut does **not** raise the proposal: 150-250 min add only modestly to a diet and only with moderate restriction [Donnelly 2009], the per-30-min effect is about half a kilo [Jayedi 2024, other population], and the deficit is carried by the calories capped at 500 kcal (§4); the user may raise it up to 300 inside the band (*design decision*, unchanged from E13 Q23).
    - minimal: 100 min a week (one third less), at most 30 min inside each routine, the rest "por tu cuenta". Endurance was kept up to 15 weeks with 33-66 % less volume at the same intensity [Spiering 2021; *moderate*]; bouts of any duration count [WHO 2020], so brisk walking in short bouts fills the rest. After 4 minimal blocks (about Spiering's 15 weeks) the target returns to 150. The 30-min cap, the one-third cut and the 4 blocks are *design decisions*; the plain "under the recommendation" note of the cardio row applies.
    - deload weeks and diet-break weeks: cardio unchanged (the deload cuts lifting sets; the break changes calories only; no source for cutting cardio in either; *design decision*).
    - **Who changes it:** the minutes are part of the block, so they change only with a new block or a phase change the user accepts, or when the user edits them; the "Entrenador" behaviour never changes cardio minutes on its own (no automatic ramp, above).
  - *Progression and safety:* someone not meeting the guideline starts small and raises frequency, intensity and duration gradually [WHO 2020: "some physical activity is better than none"]; screening depends on current activity, known cardiovascular, metabolic or renal disease or its symptoms, and the intended intensity [Riebe et al. 2015, ACSM]. The coach does not ramp the minutes automatically (no verified ramp figure); the user lowers them if needed. Discomfort on a cardio exercise follows §7 like any other exercise. **No medical line (user decision 2026-11-01, reverses E13 Q29):** the static sentence built on the ACSM screening factors [Riebe 2015; *weak*, consensus] is removed from the cardio `?` sheet: the app shows no generic disclaimer. The only health note is the data-triggered one of §7.
  - *What the user sees (ux-reviewer finalises the copy within the glossary):* in the plan, "Actividad" with "Cardio · 150 min por semana · ritmo suave" and "Pasos · 7.000 al día", each with a `?` reason in plain Spanish: base "La OMS recomienda al menos 150 minutos a la semana de actividad moderada para tu salud. Ritmo suave: respiras más fuerte, pero puedes hablar con frases completas."; "Perder grasa" adds "En los estudios, cada 30 minutos semanales de cardio suman de media medio kilo menos; la mayor parte de la pérdida viene de tu dieta."; strength and muscle add "Esta cantidad de cardio no frena tu ganancia de músculo ni de fuerza máxima. Va al final de la rutina, después de las pesas, para no restar fuerza a las piernas."; calories "No sumamos calorías por el cardio: los relojes fallan al calcularlas y el cuerpo compensa una parte. Tu plan se ajusta con tu peso real." (no medical line). Steps "Caminar unos 7.000 pasos al día se asocia con mejor salud a largo plazo. Si ya caminas más, mantenlo." No tip lines. Never "previene lesiones", never a mortality figure in the copy. **The user can change:** the weekly minutes, freely (the coach proposes a value inside the band; a value below 150 shows a plain note that it is under the recommendation, never blocks), the cardio exercise (swap, T-179) and each routine's planned minutes in the routine editor. **Not editable:** the steps target (a plain note says it comes from the user's average and the recommendation; the user may simply not follow it). **Safety limits:** discomfort on cardio follows §7; no heart-rate zones, no intervals, no automatic increase of minutes.
- **Warm-up:** the coach does not plan, generate or mention warm-ups (no ramp-up sets, no warm-up exercise, no tip, no copy); the user adds warm-up sets to a routine himself if he wants (user decision 2026-11-01, E13 Q27). Evidence for reference only (§10 35, 47-49): mixed for lifting, no injury-prevention evidence.
- **Exercise selection:** the catalogue is filtered by place and equipment; substitutions keep the muscle group and the movement pattern (`exercises.movement_pattern`, ADR-78). Candidate order by equipment (T-179): barbell, dumbbell, machine, cable, kettlebell, bodyweight, band, band_long, other; the user can swap a proposed exercise for an alternative in the preview (`04` §9.7b).
- **Main lifts:** the "main" or "priority multi-joint" lifts are the exercises whose `movement_pattern` is squat, hinge, lunge, horizontal or vertical push or pull. *Design decision* (user, 2026-10-29, E13 Q3).
- **Rep range:** each routine exercise carries an optional rep range, per session (so undulating weeks keep their ranges); without one, no progression is suggested (user, 2026-10-29, E13 Q2).
- **Deload (applies on its own, user decision 2026-11-01; the user can cancel a planned deload or start one for the next week):** triggered when no main lift (done in each of the three weeks) improved its e1RM over the last three weeks of sessions, and only inside an accepted block; **scheduled** in week 4 of a block when no deload ran in the previous 7 training weeks (weeks count as plan weeks: a paused calendar week does not count, §12.5; so at most every 8 training weeks; *design decision*, inside the 5.6 ± 2.3-week practice below; not in the minimal phase, which already trains 1 set). A block has at most one deload, always week 4 (trigger and schedule land on the same week). It may coincide with a diet-break week: one cuts sets, the other sets calories to maintenance, they do not conflict. The end-of-block review runs after week 4; its e1RM trend uses weeks 1-3 when week 4 was a deload (lower volume, same weights), while adherence counts week 4 normally. The deload week keeps the weights and cuts working sets by 40 %, rounded to the nearest whole set and at least 1 per exercise. *Design decision* (thresholds from common practice; scope and rounding by the user, 2026-10-29, E13 Q3). Soreness is not a signal (§7). Implementation (T-165, `04` §9.10): a lift improved iff `max(w2, w3) > w1` over the weekly best e1RM of plan weeks `c-2..c` (strict, ties are not improvement); it is evaluated in week `c >= 3` and targets week `c + 1`, so a 4-week block can only get a deload in week 4 (evaluated in week 3). Evidence (checked 2026-11-01): competitive strength and physique athletes deload about every 5.6 ± 2.3 weeks for 6.4 ± 1.7 days, mostly cutting sets (78.9 %) and keeping frequency (63.0 %); 54.1 % deload when performance stalls [Rogerson et al. 2024; *weak*, survey, 246 athletes]; a full week off at mid-programme gave no hypertrophy benefit and smaller lower-body strength gains in trained adults [Coleman et al. 2024; *moderate*, RCT, n = 39, full cessation]. So the deload is reduced volume (triggered or scheduled), never a week of full rest. Copy: "Semana de descarga: mismos pesos, menos series. Llevas 3 semanas sin mejorar en los básicos." (scheduled: "Llevas 7 semanas entrenando sin descarga.", counted in training weeks) with "Cancelar descarga"; outside a deload, "Hacer descarga la próxima semana".

## 4. Energy and macros

- **Calorie floor:** a plan never goes below 1200 kcal (women) / 1500 kcal (men) (ADR-25).
- **Protein:** at least 1.6 g/kg, plateau around 2.2 g/kg [Morton et al. 2018]. In a deficit with high lean mass, the upper end: 2.3-3.1 g/kg of fat-free mass [Helms, Zinn, Rowlands, Brown 2014]. Shown as guidance, not a meal plan: about 0.4 g/kg per meal over at least 4 meals [Schoenfeld, Aragon 2018].
- **Fat:** at least 20 % of calories; usual range 20-35 %; below 20 % gives no performance benefit [Rodriguez, DiMarco, Langley 2009, ADA/DC/ACSM position]. (The 2016 update [Thomas, Erdman, Burke 2016] could not be checked for these figures, so it is not cited for them.)
- **Rate of loss:** 0.5-1 % of body weight per week [Helms, Aragon, Fitschen 2014]; default 0.5 %. (ACSM 2009 states 0.5-1 kg per week for the general population; the percentage suits lean trainees better.)
- **Rate of gain:** 0.25-0.5 % of body weight per week [Iraki et al. 2019; slower for advanced lifters].
- **Energy constant:** 7 700 kcal per kg is an approximation, used only without history; with history the adaptive estimate is used [Hall 2008; Hall et al. 2011].
- **Target check (T-180, *design decision*):** the target must stay within the rate range of the intention measured from the user's capped intake (`04` §8.7), so a surplus or deficit is never stacked on top of an expenditure that already absorbed it.
- **Adjustment inside a block (applies on its own inside the safe band, user decision 2026-11-01):** made only when the plan's target rate is outside the confidence interval of the weight trend for two consecutive weeks, and only on clean data (§2 data cleaning); one change moves calories by at most 10 %, at least 14 days apart. **Safe band (*design decision*):** automatic changes inside one block add up to at most ±10 % of the block's accepted calories (net: an undone change does not count), never cross the floor (ADR-25), the 500 kcal deficit cap or the intention's rate range (target check above); a change that would leave the band waits for the end-of-block review, where it needs the user's OK. **Reference expenditure:** the total expenditure in use at the moment of the change (`04` §7.2: adaptive when reliable, else the intake prior or BMR × factor). Regain: the target never goes below it (no deficit). Maintenance, recomposition and minimal: the target stays within ± the energy of 0.25 %/week of body weight around it (the no-change range of `04` §8.7), so a maintenance user gaining faster than the trend allows **does** get a decrease, down to the bottom of that range; if the gain persists there, the adaptive expenditure will move and the review takes over. **Undo:** each change shows its reason and "Deshacer"; undoing restores the previous calories, does not count towards the band and restarts the 14-day clock (the user's decision is respected for two weeks); after two undos in one block, no more automatic calorie changes until the review (*design decision*). This matches "the smallest possible deficit that yields appreciable weight loss", adjusting intake when loss plateaus [Trexler, Smith-Ryan, Norton 2014; *moderate*, review, athletes].
- **Deficit cap (cut phase):** the daily deficit below the expenditure in use is at most 500 kcal, even when the rate (0.5 %) would ask for more; then the slower rate is kept. Energy deficit impaired lean-mass gains during resistance training (ES -0.57) but not strength (ES -0.31, n.s.); "an energy deficit of ~500 kcal · day-1 prevented gains" in lean mass, and the authors advise avoiding deficits above 500 kcal a day to preserve it [Murphy, Koehler 2022; *strong*, meta-analysis; the 500 figure is a meta-regression reading]. Slower loss preserves lean mass better in leaner people [Aragon et al. 2017, ISSN; *strong*].
- **Phase calories (§12.3):** cut by the rate and the cap above; gain by the existing rate by experience; maintenance, recomposition and minimal at rate 0; regain at rate 0, or +0.25 %/week when the intention is "Ganar musculatura" or "Ganar fuerza" (the bottom of the sourced gain range [Iraki et al. 2019]). Avoiding "prolonged energy deficiency" while building lean mass [Murphy, Koehler 2022] is why regain never runs in a deficit; maintenance versus a small surplus has no direct evidence in returning lifters (*design decision*).
- **After a cut:** the next phase starts at the measured maintenance in one step. Reverse dieting (raising calories gradually) is unproven, "research is needed to evaluate its efficacy" [Trexler 2014], so it is not prescribed; the in-block adjustment above corrects drift.
- **Diet breaks (optional, *mixed* evidence):** inside a cut the user may choose "Con semana de descanso": weeks 1-3 of the block in deficit, week 4 at maintenance. In resistance-trained adults, 3-week deficit blocks separated by 1 week at energy balance gave the same fat and fat-free mass loss as continuous dieting, with lower hunger (P = 0.002) [Peos et al. 2021; *moderate*, RCT, n = 61]; in men with obesity, 2 weeks on / 2 off lost more weight and fat (14.1 vs 9.1 kg) with a smaller adjusted drop in resting expenditure [Byrne et al. 2018; *moderate*, other population]; the ISSN finds "no significant advantage over daily caloric restriction" for body composition [Aragon 2017; *strong*]. So it is an adherence and hunger tool, not a faster cut: default off, the cut simply takes longer; only deficit weeks count towards the cut's length (§12.3). Refeeds are not prescribed ("more research is needed", Trexler 2014).

## 5. Weight and measurements

- **Daily weigh-in** recommended: day-to-day changes of 1-2 kg from water, glycogen and gut content make a single weigh-in uninformative.
- **Trend:** slope over weekly averages, shown with its confidence interval computed from the real spread of the user's weigh-ins. There is no minimum of data to use the app; data only changes the confidence shown.
- **Reminders (E10):** weight after 2 days in a row without a weigh-in; circumferences after 14 days without measuring (*design decision*: circumferences change slowly).
- **Body composition:** impedance body fat is unreliable; circumferences are a secondary reference and their uncertainty is shown.

## 6. Outcomes set by the coach

- Weight, body fat, circumferences or e1RM per lift, depending on the intention and the plan. (T-161 ships weight and e1RM per lift: the figures are derived by the server from the summary and the model only picks, explains and sets the deadline; body fat and circumferences wait for data the summary does not carry.)
- Each outcome carries its reason and its deadline (normally the end of the block).
- The user cannot set an outcome's value; they can turn an outcome off. `profiles.target_weight_kg` stops being a user input (ADR-78).

## 7. Discomfort and safety

- Logging discomfort on an exercise (E12) blocks load increases for that exercise for 7 days, or until the user confirms "Ya no me molesta" (**open** discomfort, `04` §4.12).
- **Unresolved severe discomfort (*design decision*, separate from "open"):** a level 4-5 discomfort stays **unresolved**, whatever its age, until the user taps "Ya no me molesta" or completes step 3 of the graded return below. While unresolved it stays visible on the exercise with "Ya no me molesta", keeps the exercise out of the next block (§12.4) and drives the health note (14 days unresolved). The 7-day "open" window still governs only the load block of levels 1-3.
- The user picks a **level** (1 to 5, ADR-81) when logging a discomfort; the two highest levels (swelling, tingling or numbness; sharp pain or injury) are severe. The level, not the text, drives the coach. Levels 1-3 block load increases only (the reps rule and the 5 % drop still apply) and the suggestion's reason states neutrally that the load is kept because of the open discomfort; levels 4-5 give no suggestion for that exercise (E13 Q1, user 2026-10-29). No diagnosis and no medical advice.
- **Scope of "no generic disclaimers" (user rule 2026-11-01):** it covers the whole app, not only the coach. A health line is allowed only when it comes from the user's own data **and** goes with a decision the app takes. So the pre-E13 `metric_disclaimer` (T-081) and the underweight "consulta con un profesional" line in the goal sheet go, unless the app attaches a decision to that underweight state (it does not today). Owner: PM, as a fix task.
- **Train around the affected area (intake injury area or an unresolved level 4-5 discomfort):** the next block keeps every exercise that does not load that area and leaves out the exercises the user flagged at level 4-5 (the model picks replacements among the validated alternatives of §3, never an exercise the user flagged). Stopping training reduces every component of strength (submaximal SMD -0.62, maximal force -0.46, power -0.20), with a dose-response on the length of the stop, larger in people over 65 and in inactive people [Bosquet et al. 2013; *strong*, meta-analysis]; so keeping the healthy areas trained has a cost-of-not-doing argument; which exercises "load the area" is model judgement over the catalogue, shown to the user, who can put any exercise back. *Common practice built on that evidence.*
- **Graded return after an injury (*common practice in leading apps*, product benchmark, about 6 weeks; no sourced ramp figure, steps are *design decisions*; no treatment):** for the flagged exercise, three steps, each lasting at least one week: (1) a substitute of the same movement pattern the user has not flagged; (2) the original exercise at the last load before the discomfort, with a routine note to use only the range that does not bother ("Rango sin molestia"; partial and full range differ little, see §3 "Range of motion"); (3) full range with normal progression. The app offers the next step after a week with no new discomfort on it; **the user decides when to move on**. A new discomfort at the same level or higher sends it back one step; at level 4-5, back to step 1. The level is the only signal.
- **Health note from the user's own data (user decision 2026-11-01; amends ADR-81's "nothing else is shown"):** no generic disclaimers anywhere in the app. A specific note is shown **once per discomfort** when a level 4-5 discomfort persists: still unresolved 14 days after it was logged, or logged at level 4-5 on the same exercise in 3 sessions. It states the fact and the decision the coach already took: "Esta molestia sigue ahí desde hace 14 días. Seguimos entrenando el resto sin cargar esta zona. Puede merecer la pena que te lo revise un profesional." Shown in the coach's report and on the discomfort row, dismissible, never blocking. Trigger and wording: *design decision, grade none*: no verified threshold for when persistent exercise pain warrants a check (clinical pain-monitoring trials use clinician-set thresholds that could not be verified, §10 note); 14 days matches two 7-day blocks of §7's first bullet.
- Free text (intake, check-in and discomfort notes, "¿Cómo te ha ido?") reaches the model as context (§8), shown to the user exactly as sent. It is **never matched against terms**, never triggers a health message (the note above is triggered by levels and dates only), never used to diagnose, and never changes a figure by itself: every number and trigger uses structured fields (intake fields extracted from text count only once the user confirms them, §2).
- Muscle soreness is not collected: it is a poor indicator of recovery or of adaptation [Schoenfeld, Contreras 2013; Nosaka et al. 2002].

## 8. Data, privacy and cost

- Personal use: no prior consent screen, by user decision. Before distributing the app to other people, each must accept the use of their data and the coach provider's terms; this condition is written, not implemented.
- The `coach` Edge Function sends a compact summary (last 8 weeks at most), never raw tables or photos. `coach_summary` (`04` §7.8) caps it at 16 384 bytes (about 4 000 tokens) and excludes raw rows and photos; exercises go by catalogue key or custom id. **Free text (user decision 2026-11-01, reverses the earlier exclusion of all free text):** the summary carries one block "Lo que el entrenador sabe de ti": the intake free text (up to 500 characters), and the check-in notes, discomfort notes and "¿Cómo te ha ido?" answers of the last 8 weeks, newest first, verbatim, cut at 2 000 bytes in total (*design decision*). The user sees that block exactly as sent, in the Trainer tab, and can leave any line out of what is sent (the original note is kept). Set and routine notes, food names and custom exercise names stay excluded. Use limits in §7.
- Cost control by money, not by calls (ADR-77, ADR-90): 3 € per user and 5 € in total per calendar month, plus a spending limit on the Anthropic account.
- Deleting the account deletes the coach's plans, recommendations, outcomes, usage and conversations (ADR-29); "Eliminar historial del entrenador" deletes the plans, recommendations, outcomes, reports and conversations without deleting the account; the confirmed derived values and the AI usage stay (E13 Q5, Q13).

## 9. Design decisions without evidence backing

Defaults chosen for this app; adjusted with real data, not scientific figures:
- Block length: 4 weeks (planning convention).
- Load increments: those available in the user's equipment (plates or dumbbells, E6).
- Place defines the default equipment; the user can change it.
- 5 % load drop after two failed sessions; 40 % fewer sets in a deload; three weeks without e1RM improvement as the deload trigger; at most 10 % calorie change per adjustment; 70 % logged days for a reliable intake; 14 days between circumference reminders; sleep below 6 h mentioned in the report (below the 7 h adult recommendation).
- Activity level (T-157, `04` §7.1): the active-kcal bands (150 / 300 / 500 / 750 per day), the 28-day window with 7 days minimum per source, the +1 level for 3 or more sessions per week, and the uncertainties 0.1 (data) and 0.2 (profile only). The step bands are published (§10, ref. 28).
- Experience (T-157, `04` §7.5): 24 sessions and 12 weeks for intermediate, 150 sessions and 52 weeks for advanced.
- Nutrition plan (T-161, `04` §8): rate 0 and adjustment 0 for strength, recomposition and maintenance; gain rate by experience 0.5 / 0.35 / 0.25 % per week (the range 0.25-0.5 is sourced, the split by experience follows "slower for advanced"); protein 2.2 / 2.0 / 1.8 g/kg by case (the lean-mass formula of §4 is not used: there is no body-fat input); fat default 25 %; 7 700 kcal per kg for every rate-to-deficit conversion (§4 "only without history" is read as: the adaptive expenditure of `04` §7.2 replaces BMR x factor when available); minimum change 50 kcal; at least 14 days between calorie changes (so the two weeks restart after a decision); a floor-limited plan keeps its slower rate instead of failing.
- Outcome candidates (T-161, `04` §8.4): weight only for loss and gain; e1RM per main lift by a 4-week extrapolation of the user's own least-squares slope over at least 3 weeks with data; body fat and circumferences are deferred (nothing to derive them from in the summary).
- Cardio (ADR-85, E13 Q23-Q29 resolved 2026-11-01): default 150 min for every intention (inside the sourced 150-300 band for fat loss); one steps floor of 7 000 (the ranges are sourced, the single number is chosen); "never below the current 28-day average", rounded down to 500; low-impact machines first (modality evidence is mixed) and the default ranking bike, elliptical, incline walk, rower, walking, with the most-logged cardio of the last 8 weeks first; no per-modality minute adjustment; no automatic ramp; cardio as the last exercise of each routine, split evenly in 5-minute units, at most 60 min per routine, the excess "por tu cuenta", outside "Duración de la sesión". **Removed after the 2026-11-01 check:** every warm-up element (the ACSM "5-10 min" figure was not found; then the user decided the coach ignores warm-ups), the age split 8 000 / 6 000 as a sourced figure, "cycling interferes less" as a rule (mixed evidence), "cardio before upper-body lifting is fine" (cardio is always last), separate cardio days (user decision), and the "start small" tip line (no tip lines).
- Coach summary: 16 384-byte cap and the 12 main lifts / 10 discomforts / 8 muscle groups per week lists (`04` §7.8); fallback trend uncertainty of 0.5 kg per week without an interval.
- Trainer journey (§12, user-approved direction 2026-11-01): one "Entrenador" behaviour, with load progression, the 5 % drop, weekly calories inside the safe band (±10 % per block in total, one change ≤ 10 %, 14 days apart, floor, 500 kcal cap, rate range) and deloads applying on their own, and only phase changes and new blocks needing acceptance; scheduled deload in week 4 when none ran in the previous 7 weeks; data cleaning (partial day under 40 % of the 28-day median, excluded from every count; no calorie change in a week with fewer than 5 complete diary days or 3 weigh-ins); "Mantener" muscle groups at 4 weekly sets (6 from 65), "Priorizar" groups +2 sets per block up to 20, at most 3 prioritised groups; graded return in 3 steps of at least a week each; breaks pause the block (a calendar week with no session does not count) and resume at the next planned session; after a gap of 14 days or more, one failed session (instead of two) triggers the 5 % drop; experience = the higher of self-reported and history class, 2 years of consistent lifting for "advanced"; returning lifters keep their class; no correction of self-reported maintenance, replaced by the adaptive expenditure at its existing thresholds; cutting calories as context only; "returning" set after 28 days with no completed session; pre-injury bests as an exit reference only, never as starting loads; deficit weeks only count towards a cut; maximum cut of 3 deficit blocks before a maintenance block is proposed, and at least 1 maintenance block after it; regain at rate 0 or +0.25 %/week by intention, ending at the bests, at a stalled block or after 3 blocks; "¿Seguimos?" after 6 blocks of gain, maintenance or recomposition; minimal phase at 1 session (2 from 65 years) with 1 set (2 from 65) of the previous block's main lifts, ending by the user or proposed after 8 blocks; session adherence 80 % as "high"; +2 weekly sets for a stalled muscle group, at most once per block, never above 20 sets; one session without discomfort before a returned exercise progresses; the health note at 14 days or 3 sessions at level 4-5, once; free text capped at 500 characters (intake) and 2 000 bytes (total). Audit pass (2026-11-01): unresolved level 4-5 discomfort until "Ya no me molesta" or graded-return step 3; volume 10 sets for every experience class (beginner 8 dropped); strength undulating 3-5 / 5-6 / 6-8, no singles or doubles; server-computed progression written to the block routines' planned sets, after ADR-70's update; one deload per block, always week 4, e1RM review trend on weeks 1-3 after a deload; calorie reference = expenditure in use, maintenance-type phases within ±0.25 %/week of it, regain never below it; an undone calorie change is outside the band and restarts the 14-day clock, two undos stop automatic changes until the review; minimal-phase cardio 100 min, 30 per routine, 4 blocks; cardio unchanged in deload and diet-break weeks. Life changes (§12.8): "Revisar el bloque" with deterministic "Adaptar el bloque" (same week, phase, sets, ranges; swaps by group and pattern, else by group, else the slot is dropped), "Bloque nuevo" (early review) and "Solo unos días" (temporary swaps, the minimal routine if fewer days); new exercises load from own history or by RPE 7-8 at the bottom of the range, never converted; level 4-5 mid-block swap offer; a reached outcome changes nothing until the review; no weekly report for a week with no data; the user's swaps are kept in the next block; age rules from the next block after turning 65.

## 12. Long-term follow-up: the trainer journey

User-approved direction (2026-11-01). How the coach follows one person for months or years. **Evidence caveat:** the coaching *process* (intake, weekly review, when to change phase) has almost no outcome trials; the evidence covers the levers (energy, volume, deloads, detraining, retraining) and two behavioural mechanisms (self-monitoring [Burke et al. 2011], autonomy support [Ntoumanis et al. 2021]). Sequencing phases over a year has no trial in recreational lifters (*none*): §12.3's durations are *design decisions* anchored where stated. Every figure is computed server-side (§1).

**Who decides:** *Rule* = deterministic server code (all numbers and all triggers). *Model* = the LLM chooses among server-validated options and explains, reading the structured summary and the free-text block (§8). *User* = accepts or edits phase changes and new blocks; undoes or cancels any automatic change (load, calories inside the safe band, deload), or starts a deload (§1).

### 12.2 First block (cold start)

The first block starts from the priors, conservatively inside the ranges of §3-§4: 10 weekly sets per muscle group, the intention's rep ranges, RIR 1-3. Starting loads come only from the user's own logged sessions or the load the user enters; pre-break bests never set a load (the user's current capacity is below them, and how far is unknown). After 14 or more days without a completed session, the first session of each exercise keeps the last load, with no increase, and one failed session (instead of two) triggers the 5 % drop, so loads re-adjust from the first sessions back (*design decision*; §12.5). Retraining at ordinary doses regains quickly [Halonen 2024; Staron 1991], and no study prescribes a different dose for retraining (*none*), so the returning lifter gets the normal ranges.

### 12.3 Phases

One phase per block. Triggers are evaluated **only at the end-of-block review**, on measured data (weight trend vs target rate, time in phase, main-lift e1RM, session adherence, calories at the floor); free text never triggers a phase change. A declined proposal is offered again at the next review. The intention is the user's long-term goal; the phase is how the current block gets there.

**The user's case (returning lifter who lost muscle):** the first block is regain, at maintenance if the intention is "Perder grasa", "Recomposición" or "Mantenimiento", and the cut is proposed when regain ends. Grade: the "no deficit while regaining" part is *strong* evidence on a related question (deficits impair lean-mass gains, Murphy 2022) applied to a returning population that was not studied; maintenance vs small surplus is a *design decision* (taken 2026-11-01 by the PM on this recommendation; the user may override it at PR review).

### 12.5 Busy periods and breaks

- **Busy or travelling:** the user asks for a minimal block or changes days or place; the existing re-plan on a preference change applies and the coach proposes the minimal phase when one day a week is chosen. The user ends it by asking for a new block.
- **Breaks follow the plan, not the calendar (*common practice in leading apps*, product benchmark):** a calendar week with no completed session does not count as a block week, so the block pauses and the user resumes at the next planned session, where he left off (the end-of-block review and the week-3 deload evaluation move with it). Loads re-adjust from the first sessions back (§12.2: no increase on the first session, one failed session triggers the drop after 14 or more days off).
- **Long break:** after 28 days without a completed session the situation becomes "returning"; the paused block still resumes, and at its review the regain phase is proposed. Losses scale with the length of the stop and are larger over 65 [Bosquet 2013; *strong*]; retraining recovers them quickly and "trainees should not be too concerned about occasional short-term training breaks" [Halonen 2024; *moderate*]. The 14- and 28-day thresholds and the absence of a sourced load cut on return are *design decisions*.
- **Illness:** no rule (none verified).

### 12.6 Weekly follow-up

The weekly report shows the weekly average weight and trend against the target rate, logged diary days, sessions done against planned, open discomforts and the loads changed automatically that week, each with its reason. Self-monitoring of diet and self-weighing are consistently associated with weight loss (Class IIa, Level A; self-weighing at least weekly may help) [Burke 2011; *moderate*]; explaining the rationale is part of the autonomy support associated with better health behaviour [Ntoumanis 2021]. Weekly changes are limited to calorie changes inside the §4 safe band (only on clean data) and the §3 deload, both applied on their own with "Deshacer" or "Cancelar descarga"; phase and volume change only at the end-of-block review, with the user's OK.

### 12.8 Life changes

User-approved design (2026-11-01). How the coach reacts when the user's life changes in the middle of a block. **Evidence caveat:** apart from the rows that cite a source, these are *design decisions*: how a trainer handles each event is *common practice* with no outcome trials. Every row follows the "Entrenador" split (§1): small, reversible changes apply on their own; a new block or a phase change needs the user's OK. Free text never triggers anything (§7).

**"Revisar el bloque" (mechanism for rows 1-3, 5 and 7).** When the user saves a new place, equipment, days per week or session length in "Mi entrenamiento" during an accepted block, the Trainer tab offers "Revisar el bloque" with three choices:
- **"Adaptar el bloque"** (default; *rule*, no model call, free). It keeps the block week, the phase, the sets per muscle group and the rep ranges. Exercises the new equipment cannot do are swapped by the server to a candidate with the same muscle group and movement pattern, in the order of §3 "Exercise selection" (T-179). With no such candidate it takes any candidate of the same muscle group; with none at all, the slot is dropped and the preview says so. The cardio exercise is re-picked by the §3 default ranking, with the same minutes. The user sees the preview and applies it with one tap.
- **"Bloque nuevo"**: an early end-of-block review (§12.4; *model*, a paid call). It needs acceptance like any new block.
- **"Solo unos días"**: the user picks an end date. The swaps apply only to sessions until then, and then the original routines and their loads return untouched. If he will also train fewer days, those days use the minimal-phase routine (1 full-body session, 1 set of the main lifts; 2 sessions and 2 sets from 65 [Spiering 2021; *moderate*]). The block's phase and calories do not change.

**Loads for an exercise new to the block (every row):** the planned weight is the user's last working weight on that exercise (his own history). Without history there is no planned weight, and the first session finds it by RPE: the user picks a weight he can lift for the bottom of the range at RPE 7-8 (RIR 2-3, §3). A load is never converted from another exercise: no conversion between exercises was verified (*none*). Double progression starts from that session.
