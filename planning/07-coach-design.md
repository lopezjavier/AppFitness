# Coach design: evidence base and default rules

Design base of the performance assistant (E13) and of the data it needs (E10-E12). Decisions: ADR-76 (coach), ADR-77 (AI provider and cost), ADR-78 (profile and catalogue).

**Principle:** every rule has a source, a common practice or a "design decision" label. No figure exists for convenience. Every source was checked before the E13 breakdown (2026-10-29, §10); the cardio and trainer-journey sources on 2026-11-01 (§10 29-66); the complete-routine sources on 2026-11-02/03 (§10 71-83, T-202).

## 1. What the coach does

**User inputs:**
- **Intention:** "Ganar fuerza", "Ganar musculatura", "Perder grasa", "Recomposición" or "Mantenimiento".
- **Static preferences** (Preferencias): training place (home, gym, other), available equipment and, optionally, days per week and session length.
- **Discomfort:** logged per exercise when it happens (E12). It blocks load increases (§7) and, at levels 4-5, keeps the exercise out of the next block's proposal (§7, §12.4).
- **Intake ("Para conocerte", amended by ADR-91, user 2026-11-02, §12.1):** training years ("Tiempo entrenando"), known maintenance calories and free text, nothing else. (The situation, injured area, pre-break bests and cutting calories were removed by T-198/T-200; injuries come only from logged discomforts, §7.) Every answer is a **provisional prior**, labelled "según lo que nos contaste", that measured data replaces (§2, §12.1). Editable at any time.
- **Feedback at the end of a block:** "¿Cómo te ha ido?" and, optionally, "Priorizar" / "Mantener" per muscle group (§12.4).
- **Self-reports kept minimal:** RPE per set and the discomfort log, plus the block feedback; no pump, soreness or readiness questionnaires. *Common practice in leading apps* (product benchmark); soreness is a poor signal anyway (§7).

**Phase:** each block runs in one phase (cut, gain, maintenance, recomposition; §12.3; the regain phase "Recuperar" was removed by ADR-91 and deferred to Phase 3; the minimal phase and "Tengo poco tiempo" were removed by the user on 2026-11-03). The coach proposes a phase change **only at the end-of-block review**; the user accepts or keeps the current phase.

**Output:** a plan in 4-week blocks (design decision, §9) with:
- the routines of each week, using the existing routine model;
- calories and macros;
- progression per exercise;
- expected outcomes (weight, body fat, circumferences or e1RM) **only when the plan can justify them**. The user never enters target numbers.

**Review:** at the end of each block; earlier only if the preferences change or the user asks.

**One behaviour, "Entrenador" (user decisions 2026-11-01; no mode selector; amends ADR-76's "adjustments are proposals accepted one by one", "suggestions never rewrite planned values" and "nothing is applied without acceptance"):** the user accepts or edits the whole plan (new block) and any phase change; **everything inside an accepted block applies on its own**, each change visible with its reason and undoable:
- load progression: the §3 increase and the 5 % drop, written to the next session of that exercise, with "Deshacer";
- weekly calorie changes inside the safe band of §4, with "Deshacer";
- deloads, scheduled or triggered (§3), which the user can cancel, or start one themselves.
Autonomy support, which includes explaining the rationale and offering choice, is associated with better health behaviour [Ntoumanis et al. 2021; *strong* for the mechanism, small-to-medium effects]; which changes a trainer makes without asking has no evidence (*common practice*), so the split is a *design decision*: automatic changes are small, bounded, explained and reversible; the long-term direction (phase, block) stays the user's.

**Grounding:** the model only describes app features, screens and data that exist; the server validates its output against the list of features and the summary, and drops any text that mentions anything else (anti-pattern seen in AI coaches: inventing features). *Common practice in leading apps* (product benchmark, not science).

**Division of work (amended by T-202, user 2026-11-03):** every calculation (BMR, activity, adaptive expenditure, weight trend, calories and macros, cardio minutes and steps, progression, e1RM, adherence, deload trigger, phase triggers) is deterministic, in SQL or TypeScript, and testable. **The training block is built by the model**: split, exercises, sets, rep ranges, target RPE, rests, and supersets or drop sets under their time conditions (§3 "Complete routine"). The server validates it with the routine checker (§3 "Complete routine"): a hard failure gets one retry, then the call fails and nothing is stored. Outside the block the model still selects within validated options and explains. Its output is always structured (JSON schema) and validated before it is shown; the model never writes to the database. (Supersedes the earlier "the model only picks one exercise per slot among server candidates".) §12 marks, per stage, what is a rule, what is model judgement and what the user decides.

## 2. Derived values (confirmed by the user)

| Value | How it is computed | Confidence without history |
|---|---|---|
| Basal expenditure | Mifflin-St Jeor with sex, age, height and weight (profile, `04` §1) | High (validated equation) |
| Activity level | Starts from `profiles.activity_level` (ADR-78); the coach proposes a change from Health Connect steps (bands of Tudor-Locke et al. 2011), active calories when there are no steps, and the completed sessions per week (3 or more raise a measured level by one). Exact mapping in `04` §7.1. Sessions alone never change the profile level (it already includes training) | Low: shown as provisional |
| Total expenditure | BMR × activity factor (`04` §1.3) without a reliable diary; with one, the capped 28-day intake, plus a weight-change term only when the trend has 4 weekly averages and 8 weigh-in days, clamped to one top-of-range rate (`04` §7.2-§7.3; *design decision*, T-180) | Improves with months of data |
| Weight trend | Slope of weekly averages, with its confidence interval (§5) | Depends on the number of weigh-ins |
| Experience | The **higher** of the self-reported training age (intake) and the app history class (`04` §7.5). Self-reported consistent lifting: under 6 months beginner, 6 months to under 2 years intermediate, 2 years or more advanced. ACSM: intermediate "approximately 6 months of consistent RT experience", advanced "years of RT experience" [ACSM 2009; *strong*, expert-based]; the 2-year cut for "years" is a *design decision* | Self-reported until the history class is equal or higher; shown as "según lo que nos contaste" |

**Returning lifters keep their experience class (amends the earlier "without history: beginner").** ACSM 2009 counts people "who have not trained for several years" as novices, but retraining is faster than first-time training: after 10 weeks of detraining, losses "were regained rapidly", with larger leg-press strength and muscle-area gains in the first 5 weeks of retraining than in the same weeks of first-time training [Halonen et al. 2024; *moderate*, RCT, 55 untrained adults]; women detrained 30-32 weeks lost strength "but not to pretraining levels" and fibre area rose significantly within 6 weeks of retraining [Staron et al. 1991; *moderate*, small n, women]. The evidence is on short breaks and on people who were trained for months, not years-long layoffs; so this is a *design decision built on that evidence*. **What experience drives (one rule):** the gain rate and protein (`04` §8) and the default number of days when the user sets none (beginner 3, intermediate and advanced 4, `04` §9.1; inside ACSM's 2-3 / 3-4 / 4-5 days by status [ACSM 2009]). It does **not** change the volume: every class starts at the 10 weekly sets of §3 (no verified source for a lower beginner dose: *none*; the former "beginner 8 sets" is dropped). It never sets starting loads (§12.2).

**Intake priors and their handover (*design decision*, §12.1):** self-reported values are labelled provisional and replaced by measured ones as soon as the measured rule's own threshold is met. Self-report is biased: athletes under-reported energy intake by 19 % against doubly labelled water (11 studies) [Capling et al. 2017; *strong*, athletes]. No study gives a correction factor or a weighting between a remembered maintenance and an equation (*none*), so the app applies no correction: the known maintenance replaces BMR × factor as the expenditure prior until the adaptive expenditure qualifies (28-day diary at 70 % logged days, 4 weekly averages and 8 weigh-in days), then the adaptive value replaces it and the card says so once ("Ahora usamos tus datos reales: tu gasto medido es de 2.450 kcal.").

**Intake extraction: removed (ADR-91, T-198).** No model extracts fields from the intake text; the free text is sent verbatim as context (§8).

**Confirmation rule:** each block shows a card with the derived values, their source and the missing data. The user accepts or edits them. A value is not used until confirmed; until then it is shown as provisional. A confirmed value is asked again only when its new estimate falls outside the uncertainty of the confirmed one.

**Intake completeness:** adaptive expenditure uses only days with a logged diary; days without entries are excluded, not counted as zero. Below 70 % logged days in the window (design decision) the estimate is shown as unreliable and the coach does not propose calorie changes from it.

**Data cleaning before any calorie change (*common practice in leading apps*, product benchmark; thresholds are *design decisions*):** a day counts as logged only if it looks complete: a day under 40 % of the median of the logged days of the 28-day window is partial and is excluded from the expenditure anchor **and** from every count of logged days (the 70 % reliability, the weekly gate below). One rule for the whole app, the one already built for the anchor (`04` §7.3, T-180); it replaces the earlier "50 % of the target" draft, which had no target before the first plan. No "incomplete day" control is added (scope). Missing weigh-ins are never filled in; the trend uses the weigh-ins that exist (§5). A week with fewer than 5 complete diary days (70 % of 7, the rule above applied per week) or fewer than 3 weigh-ins changes no calories; the report says why ("Esta semana faltan registros: no cambiamos tus calorías.").

## 3. Training

### Complete routine (T-202, user 2026-11-03; supersedes the fixed skeleton)

**One checker** (server, deterministic) judges any set of routines against the intention, days per week and session length. It validates the **block generator** (a hard failure is rejected: one retry, then the call fails and nothing is stored) and runs the **folder review** of any routine folder of the user (a hard failure is shown as a "Falta" item with a proposed change; nothing is blocked, the user decides). The model writes the soft comments and proposed changes; the server re-checks every proposed change before it is shown. Sets are counted fractionally: primary muscle 1, each distinct secondary 0.5 (`04` §4, the method that fit best in Pelland 2026 [*strong*]); warm-up sets do not count.

**Population and transfer:** the guideline (ACSM 2026) covers healthy adults of all training levels; the regional trials below are small, mostly young untrained or recreationally active adults (stated per rule); they transfer to recreational lifters, with smaller certainty for advanced lifters.

**Hard checks:**
- **H1 Weekly sets:** each of chest, back, shoulders, quads, hamstrings and glutes has 10-20 fractional sets a week; a group marked "Mantener" at least 4 (6 from 65) (§12.4). Minimum: ACSM 2026, hypertrophy "enhanced by higher volumes (≥10 sets/wk)" [*strong*]; the 20 cap is a *design decision* on diminishing returns [Pelland 2026; *strong*]; the "Mantener" floor rests on Spiering 2021 [*moderate*]. Only strength exercises add sets (§3 "What H1 counts"). When the minimum cannot fit (1 day a week, or a session too short), H1 is not enforced and the plan or review shows "Por debajo de lo recomendado" (never blocks).
- **H2 Sessions:** at least 2 lifting sessions a week when the user has 2 or more days. ACSM 2026: strength enhanced by "≥2 sessions/week" [*strong*].
- **H3 Side deltoid:** at least 1 `shoulder_abduction` exercise a week. Side-deltoid activation 5 % in the bench press, 27.9 % in the shoulder press, 30.3 % in the lateral raise [Campos 2020; *weak*, EMG, 13 trained men]; lateral raises, 10 sets a week, grew it 3.3-4.6 % [Larsen 2025; *moderate*, 24 trained adults]; no trial of pressing alone vs pressing plus raises was found. *Design decision* on that evidence and the user's priority.
- **H3b Knee extension (rectus femoris):** at least 1 quads isolation (knee-extension) exercise a week. Squats: rectus femoris and hamstrings "did not change" while the knee extensors grew 4.6-4.9 % [Kubo 2019; *moderate*, 17 young men]; leg press +1.1 % (n.s.) vs knee extension +13.2 % in rectus femoris [Kinoshita 2026; *moderate*, 17 untrained adults, within-subject].
  - *Conditions for H3 and H3b:* 2 or more days a week, intention other than "Ganar fuerza", and at least one candidate inside the user's equipment; otherwise the review shows a plain note and nothing is required.
- **H4 Rep ranges:** 6-20 on any exercise for "Ganar musculatura", "Perder grasa", "Recomposición" and "Mantenimiento"; for "Ganar fuerza", 3-8 on main lifts and 6-20 on the rest. Low (≤ 60 % 1RM) and high loads gave similar hypertrophy; 1RM gains favoured high loads [Schoenfeld, Grgic et al. 2017; *strong*]; ACSM 2026: strength enhanced by loads ≥ 80 % 1RM. The exact bounds are *design decisions* (the %-to-reps mapping was not verified). No singles or doubles (recreational lifters logging their own RPE).
- **H5 Effort:** every working set carries a target RPE of 7, 8 or 9 (1-3 reps in reserve); no planned failure sets; no warm-up sets (§3 "Warm-up"). ACSM 2026: sets to failure do "not enhance gains", target 2-3 RIR, "insufficient evidence to quantify exact RIR" [*strong*]; RIR targets are feasible and more accurate close to failure [Bastos 2024; *weak-moderate*, scoping review, 31 studies]; failure gives no hypertrophy advantage [Refalo 2023].
- **H6 Safety and fit:** catalogue exercises (or the user's own) inside the equipment; no exercise with an unresolved level 4-5 discomfort (§7; injuries come only from logged discomforts, ADR-91); sessions = days per week; each routine's time (sets, reps, rests, supersets and drop sets counted) fits "Duración de la sesión"; 1-10 sets per exercise; rests within §3 "Rest between sets"; cardio as computed by the server (§3 "Cardio prescription"), unchanged by the model.
- **H7 Order ("Ganar fuerza"):** the main lifts go first in the session. ACSM 2026: strength enhanced by "performing the exercise at the start of sessions" [*strong*]; [Nunes 2021].

**Soft (the model comments and may propose; never blocks):**
- Each major group in 2 sessions a week: volume-equated frequency shows "no significant difference" for hypertrophy [Schoenfeld, Grgic, Krieger 2019; *strong*]; strength rises with frequency [Pelland 2026; *strong*], so the model stresses it for "Ganar fuerza". A split that trains a group once a week (e.g. legs in push-pull-legs-upper) is valid.
- Movement-pattern coverage (squat or lunge, hinge, horizontal and vertical push, horizontal and vertical pull): no trial defines completeness by patterns (*none*); some systematic exercise variation helps regional growth and strength, excessive rotation may hurt [Kassiano 2022; *moderate*, 8 studies, 241 young trained men].
- A knee-flexion exercise (leg curl), seated preferred: hamstrings did not grow with squats [Kubo 2019]; a hip-extension (hinge) exercise grew the biceps femoris long head more than Nordics [Bourne 2017; *moderate*, 30 recreationally active men]; seated curl +14 % vs prone +9 % [Maeo 2021; *moderate*, 20 adults]. H1 already forces hamstring sets (hinge or knee flexion).
- Rear deltoid (reverse fly, face pull): posterior-deltoid activation 24 % in the lateral raise, 11.4 % in the shoulder press, 3.5 % in the bench press [Campos 2020; *weak*]; no growth trial found.
- An overhead triceps extension when triceps get isolation work: long head +28.5 % overhead vs +19.6 % neutral [Maeo 2023; *moderate*, 21 adults, within-subject]; whether pressing alone grows the long head: *not found*.
- Calves: a calf raise when time allows (*none*: no study found on compound lifts and calf growth).
- Undulating weekly loads for experienced "Ganar fuerza" users (§3 "Periodization").
- What to keep between blocks: lifts still improving stay; a few accessories change on purpose [Kassiano 2022].

**Free (the model or the user):** split type; exercise choice within a group or pattern (favourites first, below); order outside H7; number of exercises; biceps isolation (adding single-joint arm work to compounds added nothing in trained men [de França 2015; *moderate*, 20 trained men]); chest angle (*not found*); forearms and core (*not found*; no required sets); glute medius (little growth with squats or hip thrusts [Plotkin 2023; *moderate*, 34 untrained adults]; abduction growth trial *not found*); rests within bounds.

**Starting points (user UX decision 2026-11-03):** a new block starts either **from scratch** (the model proposes 2-3 split candidates for the days and minutes, recommends one with its reason, and the user picks; the model then builds that split) or **from one of the user's routine folders** (the model reviews it against the checker and proposes changes the user accepts or rejects; then it becomes the block). Both pass the hard checks before the block is stored. **Block length stays 4 weeks** (§9; *design decision, none*: no trial compares block lengths; it keeps variation systematic [Kassiano 2022], gives the review 3 weeks of e1RM and matches the week-4 deload and diet break).

**Model input:** intention, phase, days, minutes, equipment; the user's routine folders and the last 8 weeks of logged performance per exercise (sets, e1RM trend, RPE); the previous blocks with adherence (and "¿Cómo te ha ido?" once T-190 stores it); favourites (ADR-94); unresolved level 4-5 and open discomforts; the free-text block (§8); the eligible catalogue by muscle group and pattern, unranked and uncapped. Cardio is appended by the server unchanged (ADR-93). The block carries a reason per split and per exercise and a "what changed versus the last block and why" field.

**Favourites (user decision 2026-11-03):** a starred exercise (exercise detail) is the preferred pick within its muscle group or pattern **after** the hard checks pass; it never adds volume and is never forced in. Ties between favourites, or with no favourite, go to logged history (most sessions in the last 8 weeks, then the best e1RM trend). When a favourite cannot fit, the reason says why in one line. Evidence: self-selected exercises gave a small lean-mass edge [Rauch 2020; *weak-moderate*, 17 highly trained men]; equipment type showed no consistent effect [ACSM 2026], so honouring preference costs nothing; ACSM 2026 asks for programs "individualized to maximize adherence, enjoyment, safety, and effectiveness" (expert judgement within a guideline).

**Taxonomy (T-202):** one new `movement_pattern` value, `shoulder_abduction`, for the 7 lateral-raise keys now tagged `isolation`: `lateral-raise`, `cable-lateral-raise`, `seated-dumbbell-lateral-raise`, `side-lying-lateral-raise`, `bodyweight-lateral-raise`, `plate-loaded-lateral-raise`, `single-arm-plate-loaded-lateral-raise`. It counts as an isolation role and is not a main lift. Knee extension is expressed as quads + `isolation` (`leg-extension`, `single-leg-extension`, `banded-terminal-knee-extension`, `reverse-nordic-curl`) and knee flexion as hamstrings + `isolation`; rear deltoid and overhead triceps are soft rules judged by the model, so they get no tag. Front raises, upright rows and face pulls keep their tags. *For the planner:* hinges are filed under glutes as primary (`04` §9.4); check that the hinge rows list hamstrings as a secondary muscle, or H1 undercounts hamstrings.

**Lower-body filing (Checkpoint E13-H feedback, 2026-11-03; supersedes "the catalogue files squats and lunges under glutes" in `04` §9):** one primary and one secondary group per lower-body movement, so H1 counts the muscles that grow and H3b counts only knee extension.
- *Knee-dominant compounds* (squat and its variants, leg press, hack squat, lunge, split squat, step-up, wall sit, jump squat, box jump): **quads primary, glutes secondary**. Squats grew the knee extensors 4.6-4.9 %, gluteus maximus 2.2-6.7 % and adductors 2.7-6.2 %, not the rectus femoris or hamstrings [Kubo 2019; *moderate*, 17 young men]; against the hip thrust, the squat grew the quadriceps (+3.6 cm²) and adductors (+2.5 cm²) more and the gluteus maximus similarly [Plotkin 2023; *moderate*, 34 untrained adults]; the leg press grew quadriceps +4.9 %, gluteus maximus +15.4 %, adductor magnus +6.2 % [Kinoshita 2026; *moderate*, 17 untrained adults]; squats and leg press grow the gluteus maximus [Krause Neto 2025; *strong*]; lunges: high quadriceps and gluteus maximus activity [Escamilla 2025; *weak*, EMG, 20 adults]. No hamstrings secondary (Kubo 2019). Quads as primary is a *design decision*: with one primary, the 0.5 secondary undercounts glutes (the leg press grew them more than the quads in %); plyometric variants follow for consistency (*none* for their growth).
- *Hip extension* (hip thrust, glute bridge, kickback, pull-through, and the bent-knee deadlifts): glutes primary, hamstrings secondary (as above). The bent-knee deadlifts (`deadlift`, `sumo-deadlift`, `hex-bar-deadlift`, etc.) keep their current primary.
- *Straight-knee hinge* (Checkpoint E13-H feedback, 2026-11-03): **hamstrings primary, glutes secondary** for `romanian-deadlift`, `ez-bar-romanian-deadlift`, `dumbbell-romanian-deadlift`, `banded-romanian-deadlift`, `smith-machine-rdl`, `stiff-leg-deadlift`, `single-leg-romanian-deadlift`, `one-arm-single-leg-dumbbell-romanian-deadlift`, `one-arm-single-leg-kettlebell-romanian-deadlift`, `kettlebell-single-leg-deadlift`, `single-leg-rdl-hold`, `db-kickstand-deadlift`, `double-db-kickstand-deadlift`, `kettlebell-kickstand-deadlift`, `good-morning`, `banded-good-morning`, `bodyweight-good-morning`, `smith-machine-good-morning`. Evidence: 9 weeks of stiff-leg deadlifts grew the whole hamstrings 7.0 ± 8.1 % and the semimembranosus 11.2 ± 12.7 % [Morin 2025, ref. 90; *moderate*, 36 untrained adults, 3D ultrasound]; in the Romanian deadlift biceps femoris and semitendinosus activity exceeds erector spinae activity [Martín-Fuentes 2020, ref. 91; *weak*, EMG review]. Gluteus maximus growth from a straight-knee hinge alone: *not found*, so glutes stay as the secondary. Good mornings and the kickstand (staggered-stance) and single-leg variants follow by the same joint action (*design decision, none* for their growth). Population: untrained adults; transfers to recreational lifters. Journey stage: plan and block review (H1).
- *Hip abduction* (machine, band, clamshell, fire hydrant, side-lying abduction): **glutes** (gluteus medius and minimus abduct the hip [StatPearls, ref. 86]).
- *Hip adduction* (machine, band, side-lying adduction, adductor stretches): new group **"Aductores"** (adductor magnus, longus and brevis adduct the hip [ref. 86]); it is **outside H1** (no required sets; adductors grow with squats and leg press, Kubo 2019, Kinoshita 2026). Enum value, label and body-map entry are implementation.
- *Hip flexion* (leg raises, knee raises, L-sits, sit-ups, V-ups, toes-to-bar, flutter and scissor kicks, hollow and boat holds, knee tucks, mountain climbers): **core**, never quads (the iliopsoas is the main hip flexor [ref. 86]); `pilates-side-bend` is core too.
- Knee extension: quads + `isolation`, and **H3b counts only** `leg-extension`, `single-leg-extension`, `banded-terminal-knee-extension`, `reverse-nordic-curl`. Knee flexion: hamstrings. Calf raises: calves. Stretches carry the stretched group (forward folds: hamstrings; hip-flexor, couch and quad stretches: quads).
- *Keys, not names:* the categories above are filed by catalogue key, by the joint action, whatever the exercise's category (strength, yoga, mobility, cardio). So frontal-plane and inner-thigh mobility (`seated-straddle-stretch`, `lateral-leg-swing`, `happy-baby`, `garland-pose`) is adductors; hip-flexion flows (`downward-dog-to-knee-drive`, `downward-dog-knee-tuck`) are core; `kettlebell-sumo-high-pull` is a hinge (glutes, hamstrings secondary); `wide-legged-forward-fold` is hamstrings. A key that fits no category keeps its tag. Filing these is a *design decision* from anatomy [ref. 86]; *none* for their growth.
- *Population and transfer:* young men and untrained adults; transfers to recreational lifters. Journey stage: plan and block review (H1, H3b).

**What H1 counts (T-211, user decision 2026-11-03: H1 counts only strength exercises):** filing (above) says which group an exercise belongs to; this says whether its sets add to H1 at all. Applies to the coach's checks only (block generator, folder review, H1 note "Por debajo de lo recomendado").
- *Criterion:* an exercise counts when it is **dynamic resistance work logged as reps that can be prescribed inside H4 (6-20 reps) at H5's target RPE 7-9**, against an external load or the body weight (barbell, dumbbell, machine, cable, band, bodyweight squats, push-ups, pull-ups, glute bridges, banded clamshells). H1's set-volume figures come from such sets: ACSM 2026 "≥10 sets/wk" and Pelland 2026's fractional counting [refs 71, 4; *strong*]. A set that cannot carry a rep range and an RPE target is not the set those figures describe.
- *Does not count:* stretches, yoga poses and mobility flows (`deep-squat-hold`, `squat-hold`, `cat-cow`, `lateral-leg-swing`, forward folds); cardio rows (`stationary-bike` and every `cardio_machine` key, `running`, `walking`, `jump-rope`, `jumping-jacks`, `battle-ropes`); impact and plyometric moves (`jump-squat`, `box-jump`, `burpees`, `plyo-lunge`; *none*: no source opened on their growth); **every timed hold**, including isometric strength holds (`wall-sit`, `plank` and its variants, `dead-hang`, `l-sit`, levers, `handstand-hold`) and loaded carries (`-farmers-walk`, `-carry`, `plate-pinch`).
- *Why holds are out although they build muscle:* isometric training does grow muscle, more at long muscle lengths (0.86-1.69 % a week) and "regardless of training intensity" [Oranchuk 2019, ref. 87; *moderate*, systematic review of small, mostly lab trials with maximal-intent dynamometer protocols, not bodyweight holds]; stretching grows it slightly (d = 0.20; only long, frequent stretching reached significance) [Warneke 2024, ref. 88; *strong* for a small effect]; aerobic training can too [Konopka 2014, ref. 89; *moderate*, review, untrained and older adults]. No study equating a timed hold, a stretch or a cardio bout to one working set was found (*not found*), so excluding them is a **design decision** (the user's): H1 measures sets the checker can compare, and the model must place real strength sets instead of padding with holds. Consequence accepted by the user: `wall-sit` stays filed as quads (knee-dominant, above) and keeps showing in stats, but adds 0 to H1; a home user whose only quads work was holds now gets squats, lunges or step-ups proposed. Core is outside H1, so planks change nothing there.
- *Custom exercises* (`is_custom`): **count**, unless their metric type is time- or distance-based (`duration`, `weight_duration`, `distance_duration`, `floors_duration`, `steps_duration`), which follows the hold and cardio rule above. *Design decision, none*: the user created the exercise as work; the metric type is the only fact the app has about it.
- *Source of truth:* a **stored per-key flag** on the catalogue, set by the catalogue generator from the lists above, not derived at runtime. - *Unchanged:* warm-up sets never count, a failure set is not planned, a drop set counts as 1 (`04` §4); a non-counting exercise still takes session time (H6) and may stay in a routine.
- *Statistics "Series por grupo" (E8):* not affected by this rule; it reports what the user did, not what H1 checks. Whether it should also exclude non-strength work is a product question for the PM (*none*: no evidence settles it).
- *Population and transfer:* ACSM 2026 covers healthy adults of all levels and Pelland 2026 pooled trained and untrained adults; the isometric and stretching reviews are mostly young untrained adults. Transfers to recreational lifters. Journey stage: plan and block review (H1).

### Training rules

- **Frequency (amended by T-202):** at least 2 lifting sessions a week when the user has 2 or more days (H2); per-muscle frequency is soft ("Complete routine"); with one day, one full-body session. *Superseded:* "each muscle group at least twice a week" as a hard rule.
- **Volume:** starting point of 10 weekly sets per muscle group, inside H1's 10-20. Dose-response is positive [Schoenfeld, Ogborn, Krieger 2017], with diminishing returns at higher volumes, much more pronounced for strength than for hypertrophy [Pelland et al. 2026].
- **Intensity (amended by T-202):** rep ranges per H4, chosen by the model. *Superseded:* the fixed bands "main 6-10, isolation 10-15" and the mandatory strength undulation "3-5 / 5-6 / 6-8" (now an option, below).
- **Proximity to failure:** 1-3 reps in reserve on working sets, prescribed as a target RPE of 7-9 (H5). Training to momentary failure shows no hypertrophy advantage over stopping short of it, and set failure only a trivial one [Refalo et al. 2023]. Reps in reserve are derived from the logged RPE (RIR = 10 − RPE); there is no separate RIR field (ADR-76).
- **Progression:** double progression. Work inside the rep range; when every working set reaches the top of the range at RPE 8 or less, raise the load to the next available increment. ACSM: a 2-10 % load increase when the individual can perform the current workload "for one to two repetitions over the desired number" [ACSM 2009; *strong*, position stand, expert-based]; double progression is that rule applied to a rep range. With light dumbbells the next available increment can exceed 10 % (equipment limit, *design decision*: still the next increment). **Applied automatically** to the next session, with its reason and "Deshacer" (§1). **Where it lives and who computes it:** inside an accepted block, when a session completes, the **server** computes the decision and the step (the increment from the user's plates and handle, `04` §4.9, so the plate settings must be readable on the server) and writes the new weight to the planned sets of the block's routines that hold that exercise with the same rep range (a routine serves every week, so the new planned weight is the baseline from the next session on; ADR-50 planned values); on a raise the planned reps go to the bottom of the range. If the user's "Actualizar automáticamente" (ADR-70) is on, it runs first and the coach's change is applied on top. "Deshacer" restores the planned weight and reps from before the coach's write. Outside a block it stays a live-session suggestion. Example reason: "Subimos a 62,5 kg: la última vez hiciste 12 repeticiones en todas las series."
- **Failed sessions:** when most working sets miss the bottom of the range in two consecutive sessions of the exercise, lower the load 5 %, rounded to the available increment. *Design decision.* Applied automatically, like the increase.
- **Rest between sets:** 2-3 min on main multi-joint lifts, 1-2 min on isolation exercises. Trained lifters need more than 2 min to maximise strength [Grgic et al. 2018]; 3 min beat 1 min for strength and thigh hypertrophy [Schoenfeld et al. 2016]; for hypertrophy alone the difference is small [Singer et al. 2024]. The model writes rests inside these bounds; the checker enforces them (H6).
- **Exercise order:** for "Ganar fuerza" the priority multi-joint lifts go first in the session (H7); strength improves most on exercises done early, hypertrophy is similar in any order [Nunes et al. 2021]. For other intentions the order is free.
- **Periodization (amended by T-202):** undulating loads within the week (heavy, medium, light) are an **option** the model may use for experienced "Ganar fuerza" users, never mandatory. Undulating beat linear for 1RM (ES 0.31; trained 0.61, CI touching 0; untrained 0.06, n.s.) with no hypertrophy difference (0.05) [Moesgaard et al. 2022; *strong*, mixed by training status]; ACSM 2026: periodization "not significantly superior" to non-periodized programs. *Superseded:* mandatory undulation for "Ganar fuerza" and "other intentions keep one rep range per exercise".
- **Range of motion:** full range by default; differences against partial range are small [Pallarés et al. 2021; Wolf et al. 2023]. A technique note, not a computed rule.
- **Cardio:** concurrent aerobic training does not compromise whole-muscle hypertrophy (SMD -0.01) or maximal strength (SMD -0.06); only explosive strength is attenuated (SMD -0.28), more when both are in the same session than 3 h or more apart; training status, cycling vs running, more or fewer than 5 sessions a week and age did not moderate it [Schumann et al. 2022, 43 studies; *strong*]. At fibre level there may be a small negative effect (SMD -0.23), possibly only with running [Lundberg et al. 2022; *moderate, preliminary*]. So the coach does not reduce cardio or steps for strength or muscle goals.
- **Cardio prescription (proposed, ADR-85; every source re-checked online on 2026-11-01, §10 29-50; E13 Q23-Q29 resolved 2026-11-01: Q27 and the placement inside the routine by the user, the rest by the fitness-scientist on this evidence).** The coach prescribes cardio as a trainer would. Every figure is computed by the server's rules, never by the model (§1). Grades: *strong* = guideline or meta-analysis of trials; *moderate* = single trial or review; *weak* = observational or expert opinion.
  - *Dose (weekly minutes of moderate aerobic work):* the adult guideline is 150-300 min moderate or 75-150 min vigorous per week (so one vigorous minute counts as two moderate), and bouts of any duration count [WHO 2020, Bull et al.: strong recommendation, moderate-certainty evidence; ACSM 2011, Garber et al.: ≥ 30 min on ≥ 5 days, ≥ 150 min]. More than 300 min may add benefit (WHO, conditional). **"Perder grasa": band 150-300**: aerobic exercise lowers weight 0.52 kg, waist 0.56 cm and body fat 0.37 % per 30 min a week, linearly up to 300 min, with clinically important waist and fat changes from about 150 min [Jayedi et al. 2024, 116 RCTs; *strong*, but in adults with overweight or obesity (mean age 46) and supervised aerobic training of 8 weeks or more]; 150-250 min gives only a modest loss and adds to the diet only with moderate (not severe) restriction, more than 250 min a clinically significant one [Donnelly et al. 2009, ACSM; *strong*]. **Every other intention: 150**, the guideline minimum: it is there for health, not for the goal; it does not compromise hypertrophy or maximal strength (above). An older meta-analysis links more frequent and longer endurance work to smaller strength and hypertrophy gains (r -0.26 to -0.75) [Wilson et al. 2012; *moderate*, correlational], a frequency effect the newer one did not find [Schumann 2022]: evidence is mixed, so the non-fat-loss intentions stay at the minimum. **Resolved (E13 Q23):** the coach proposes 150 for every intention, inside the band 150-300 for "Perder grasa" (the diet carries the deficit, Donnelly 2009; the lowest dose with clinically important fat and waist change, Jayedi 2024); the user edits it freely. The default is a *design decision*.
  - *Intensity:* moderate = the user can still talk comfortably; the last talk-test stage with comfortable speech tracks the ventilatory threshold [Foster et al. 2008, healthy young adults; *moderate*] and is proposed for aerobic prescription [Vieira et al. 2022, systematic review in cardiopulmonary patients; *moderate*, other population]. Shown as the pace word "suave" with that explanation; no heart-rate zones (no verified source for a zone formula here).
  - *Type:* continuous moderate work only in this pass. Intervals give similar fat loss (SMD -0.82 vs -0.85 in running programmes) with about 40 % less time [Wewege et al. 2017; *strong*, adults 18-45 with overweight or obesity], but intervals added to lifting reduce lower-body strength gains (ES -0.248) [Sabag et al. 2018; *strong*, small effect]; so intervals are not prescribed (E13 Q28, resolved: continuous "suave" only, no heart-rate zones). Cycling vs running: *mixed* (running interfered more in Wilson 2012 and, for type I fibres, in Lundberg 2022; no difference in Schumann 2022; in Wewege 2017 cycling programmes showed no fat loss). So "low-impact machines first" is a *design decision* (joint comfort, availability), not an evidence rule. The exercise comes from the catalogue's `cardio` pattern, filtered by place and equipment like any other slot; walking needs no equipment.
  - *Modality and swap (E13 Q28b, resolved by fitness-scientist, 2026-11-01; user requirement: the user switches between the cardio they have):*

Fat-loss trials did not report a credible difference by intensity, and the modality subgroups were not reported in the main text [Jayedi 2024]; Wewege 2017's cycling subgroup showed no fat loss (*mixed*, one subgroup), not enough to adjust the minutes per modality.   - *Copy (ux-reviewer finalises):* reason on such an alternative "Mismo ejercicio con otro material: para ganar músculo da el mismo resultado."
- **Shoulder coverage (side deltoid; fitness-scientist, 2026-11-02, after the user found no lateral raise in a block; sources §10 67-68 and 4):**
  - *Evidence:* side-deltoid activation is 5 % MVIC in the bench press, 27.9 % in the shoulder press and 30.3 % in the lateral raise [Campos et al. 2020; *weak*: EMG, not growth, 13 trained men]. Indirect sets best predict hypertrophy when counted as half a set [Pelland et al. 2026, "fractional" method; *strong*]. No trial has compared pressing with raising for side-deltoid growth; Larsen et al. 2025 state that no earlier training study measured lateral-deltoid thickness; in their trial, lateral raises 2 × 5 sets a week (10 sets), 12-16 RM to failure, 8 weeks, raised it 3.3-4.6 %, dumbbell and cable alike [*moderate*, RCT within subject, 24 trained adults, 16 men and 8 women, 3+ years of training; transfers to recreational lifters, the effect may be larger in beginners, not verified].
  - *Rule (amended by T-202):* side-deltoid work is hard check H3 ("Complete routine"): at least 1 `shoulder_abduction` exercise a week, any equipment the user has (dumbbell and cable are equivalent, so no equipment preference). Front raises are not chosen by default (every press already works the front deltoid, Campos 2020). Rep range per H4. *Superseded:* "the shoulders main slot is a vertical press" (EMG only, *weak*; now model judgement) and the open question on a lateral-raise slot (resolved by H3).
  - *Copy (ux-reviewer finalises):* reason on the lateral raise "Trabaja la parte lateral del hombro, que el press de banca apenas activa." Never "imprescindible". The user can swap it or remove it, and "Priorizar" hombros at the block review adds sets as for any group (§12.4).
- **Main lifts:** the "main" or "priority multi-joint" lifts are the exercises whose `movement_pattern` is squat, hinge, lunge, horizontal or vertical push or pull. *Design decision* (user, 2026-10-29, E13 Q3).
- **Rep range:** each routine exercise carries an optional rep range, per session (so undulating weeks keep their ranges); without one, no progression is suggested (user, 2026-10-29, E13 Q2).
- **Deload (applies on its own, user decision 2026-11-01; the user can cancel a planned deload or start one for the next week):** triggered when no main lift (done in each of the three weeks) improved its e1RM over the last three weeks of sessions, and only inside an accepted block; **scheduled** in week 4 of a block when no deload ran in the previous 7 training weeks (weeks count as plan weeks: a paused calendar week does not count, §12.5; so at most every 8 training weeks; *design decision*, inside the 5.6 ± 2.3-week practice below). A block has at most one deload, always week 4 (trigger and schedule land on the same week). It may coincide with a diet-break week: one cuts sets, the other sets calories to maintenance, they do not conflict. The end-of-block review runs after week 4; its e1RM trend uses weeks 1-3 when week 4 was a deload (lower volume, same weights), while adherence counts week 4 normally. The deload week keeps the weights and cuts working sets by 40 %, rounded to the nearest whole set and at least 1 per exercise. *Design decision* (thresholds from common practice; scope and rounding by the user, 2026-10-29, E13 Q3). Soreness is not a signal (§7). Implementation (T-165, `04` §9.10): a lift improved iff `max(w2, w3) > w1` over the weekly best e1RM of plan weeks `c-2..c` (strict, ties are not improvement); it is evaluated in week `c >= 3` and targets week `c + 1`, so a 4-week block can only get a deload in week 4 (evaluated in week 3). Evidence (checked 2026-11-01): competitive strength and physique athletes deload about every 5.6 ± 2.3 weeks for 6.4 ± 1.7 days, mostly cutting sets (78.9 %) and keeping frequency (63.0 %); 54.1 % deload when performance stalls [Rogerson et al. 2024; *weak*, survey, 246 athletes]; a full week off at mid-programme gave no hypertrophy benefit and smaller lower-body strength gains in trained adults [Coleman et al. 2024; *moderate*, RCT, n = 39, full cessation]. So the deload is reduced volume (triggered or scheduled), never a week of full rest. Copy: "Semana de descarga: mismos pesos, menos series. Llevas 3 semanas sin mejorar en los básicos." (scheduled: "Llevas 7 semanas entrenando sin descarga.", counted in training weeks) with "Cancelar descarga"; outside a deload, "Hacer descarga la próxima semana".

## 4. Energy and macros

- **Calorie floor:** a plan never goes below 1200 kcal (women) / 1500 kcal (men) (ADR-25).
- **Protein:** at least 1.6 g/kg, plateau around 2.2 g/kg [Morton et al. 2018]. In a deficit with high lean mass, the upper end: 2.3-3.1 g/kg of fat-free mass [Helms, Zinn, Rowlands, Brown 2014]. Shown as guidance, not a meal plan: about 0.4 g/kg per meal over at least 4 meals [Schoenfeld, Aragon 2018].
- **Fat:** at least 20 % of calories; usual range 20-35 %; below 20 % gives no performance benefit [Rodriguez, DiMarco, Langley 2009, ADA/DC/ACSM position]. (The 2016 update [Thomas, Erdman, Burke 2016] could not be checked for these figures, so it is not cited for them.)
- **Rate of loss:** 0.5-1 % of body weight per week [Helms, Aragon, Fitschen 2014]; default 0.5 %. (ACSM 2009 states 0.5-1 kg per week for the general population; the percentage suits lean trainees better.)
- **Rate of gain:** 0.25-0.5 % of body weight per week [Iraki et al. 2019; slower for advanced lifters].
- **Energy constant:** 7 700 kcal per kg is an approximation, used only without history; with history the adaptive estimate is used [Hall 2008; Hall et al. 2011].
- **Target check (T-180, *design decision*):** the target must stay within the rate range of the intention measured from the user's capped intake (`04` §8.7), so a surplus or deficit is never stacked on top of an expenditure that already absorbed it.
- **Adjustment inside a block (applies on its own inside the safe band, user decision 2026-11-01):** made only when the plan's target rate is outside the confidence interval of the weight trend for two consecutive weeks, and only on clean data (§2 data cleaning); one change moves calories by at most 10 %, at least 14 days apart. **Safe band (*design decision*):** automatic changes inside one block add up to at most ±10 % of the block's accepted calories (net: an undone change does not count), never cross the floor (ADR-25), the 500 kcal deficit cap or the intention's rate range (target check above); a change that would leave the band waits for the end-of-block review, where it needs the user's OK. **Reference expenditure:** the total expenditure in use at the moment of the change (`04` §7.2: adaptive when reliable, else the intake prior or BMR × factor). Maintenance and recomposition: the target stays within ± the energy of 0.25 %/week of body weight around it (the no-change range of `04` §8.7), so a maintenance user gaining faster than the trend allows **does** get a decrease, down to the bottom of that range; if the gain persists there, the adaptive expenditure will move and the review takes over. **Undo:** each change shows its reason and "Deshacer"; undoing restores the previous calories, does not count towards the band and restarts the 14-day clock (the user's decision is respected for two weeks); after two undos in one block, no more automatic calorie changes until the review (*design decision*). This matches "the smallest possible deficit that yields appreciable weight loss", adjusting intake when loss plateaus [Trexler, Smith-Ryan, Norton 2014; *moderate*, review, athletes].
- **Deficit cap (cut phase):** the daily deficit below the expenditure in use is at most 500 kcal, even when the rate (0.5 %) would ask for more; then the slower rate is kept. Energy deficit impaired lean-mass gains during resistance training (ES -0.57) but not strength (ES -0.31, n.s.); "an energy deficit of ~500 kcal · day-1 prevented gains" in lean mass, and the authors advise avoiding deficits above 500 kcal a day to preserve it [Murphy, Koehler 2022; *strong*, meta-analysis; the 500 figure is a meta-regression reading]. Slower loss preserves lean mass better in leaner people [Aragon et al. 2017, ISSN; *strong*].
- **Phase calories (§12.3):** cut by the rate and the cap above; gain by the existing rate by experience; maintenance and recomposition at rate 0 (the regain phase was removed by ADR-91 and the minimal phase by the user on 2026-11-03).
- **After a cut:** the next phase starts at the measured maintenance in one step. Reverse dieting (raising calories gradually) is unproven, "research is needed to evaluate its efficacy" [Trexler 2014], so it is not prescribed; the in-block adjustment above corrects drift.
- **Diet breaks (optional, *mixed* evidence):** inside a cut the user may choose "Con semana de descanso": weeks 1-3 of the block in deficit, week 4 at maintenance. In resistance-trained adults, 3-week deficit blocks separated by 1 week at energy balance gave the same fat and fat-free mass loss as continuous dieting, with lower hunger (P = 0.002) [Peos et al. 2021; *moderate*, RCT, n = 61]; in men with obesity, 2 weeks on / 2 off lost more weight and fat (14.1 vs 9.1 kg) with a smaller adjusted drop in resting expenditure [Byrne et al. 2018; *moderate*, other population]; the ISSN finds "no significant advantage over daily caloric restriction" for body composition [Aragon 2017; *strong*]. So it is an adherence and hunger tool, not a faster cut: default off, the cut simply takes longer; only deficit weeks count towards the cut's length (§12.3). Refeeds are not prescribed ("more research is needed", Trexler 2014).

## 5. Weight and measurements

- **Daily weigh-in** recommended: day-to-day changes of 1-2 kg from water, glycogen and gut content make a single weigh-in uninformative.
- **Trend:** slope over weekly averages, shown with its confidence interval computed from the real spread of the user's weigh-ins. There is no minimum of data to use the app; data only changes the confidence shown.
- **Reminders (E10):** weight after 2 days in a row without a weigh-in; circumferences after 14 days without measuring (*design decision*: circumferences change slowly).
- **Body composition:** impedance body fat is unreliable; circumferences are a secondary reference and their uncertainty is shown.

## 6. Outcomes set by the coach

- Weight, body fat, circumferences or e1RM per lift, depending on the intention and the plan. (T-161 ships weight and e1RM per lift: the figures are derived by the server from the summary and the model only picks, explains and sets the deadline; body fat and circumferences wait for data the summary does not carry.)
- Each outcome carries its reason and its deadline (normally the end of the block).
- The user cannot set an outcome's value; they can turn an outcome off. `profiles.target_weight_kg` stops being a user input (ADR-78).

## 7. Discomfort and safety

- Logging discomfort on an exercise (E12) blocks load increases for that exercise for 7 days, or until the user confirms "Ya no me molesta" (**open** discomfort, `04` §4.12).
- **Unresolved severe discomfort (*design decision*, separate from "open"):** a level 4-5 discomfort stays **unresolved**, whatever its age, until the user taps "Ya no me molesta" or completes step 3 of the graded return below. While unresolved it stays visible on the exercise with "Ya no me molesta", keeps the exercise out of the next block (§12.4) and drives the health note (14 days unresolved). The 7-day "open" window still governs only the load block of levels 1-3.
- The user picks a **level** (1 to 5, ADR-81) when logging a discomfort; the two highest levels (swelling, tingling or numbness; sharp pain or injury) are severe. The level, not the text, drives the coach. Levels 1-3 block load increases only (the reps rule and the 5 % drop still apply) and the suggestion's reason states neutrally that the load is kept because of the open discomfort; levels 4-5 give no suggestion for that exercise (E13 Q1, user 2026-10-29). No diagnosis and no medical advice.
- **Scope of "no generic disclaimers" (user rule 2026-11-01):** it covers the whole app, not only the coach. A health line is allowed only when it comes from the user's own data **and** goes with a decision the app takes. So the pre-E13 `metric_disclaimer` (T-081) and the underweight "consulta con un profesional" line in the goal sheet go, unless the app attaches a decision to that underweight state (it does not today). Owner: PM, as a fix task.
- **Train around the affected area (an unresolved level 4-5 discomfort; the intake injury area was removed by ADR-91):** the next block keeps every exercise that does not load that area and leaves out the exercises the user flagged at level 4-5 (the model, which builds the block, never picks a flagged exercise; checker H6). Stopping training reduces every component of strength (submaximal SMD -0.62, maximal force -0.46, power -0.20), with a dose-response on the length of the stop, larger in people over 65 and in inactive people [Bosquet et al. 2013; *strong*, meta-analysis]; so keeping the healthy areas trained has a cost-of-not-doing argument; which exercises "load the area" is model judgement over the catalogue, shown to the user, who can put any exercise back. *Common practice built on that evidence.*
- **Graded return after an injury (*common practice in leading apps*, product benchmark, about 6 weeks; no sourced ramp figure, steps are *design decisions*; no treatment):** for the flagged exercise, three steps, each lasting at least one week: (1) a substitute of the same movement pattern the user has not flagged; (2) the original exercise at the last load before the discomfort, with a routine note to use only the range that does not bother ("Rango sin molestia"; partial and full range differ little, see §3 "Range of motion"); (3) full range with normal progression. The app offers the next step after a week with no new discomfort on it; **the user decides when to move on**. A new discomfort at the same level or higher sends it back one step; at level 4-5, back to step 1. The level is the only signal.
- **Health note from the user's own data (user decision 2026-11-01; amends ADR-81's "nothing else is shown"):** no generic disclaimers anywhere in the app. A specific note is shown **once per discomfort** when a level 4-5 discomfort persists: still unresolved 14 days after it was logged, or logged at level 4-5 on the same exercise in 3 sessions. It states the fact and the decision the coach already took: "Esta molestia sigue ahí desde hace 14 días. Seguimos entrenando el resto sin cargar esta zona. Puede merecer la pena que te lo revise un profesional." Shown in the coach's report and on the discomfort row, dismissible, never blocking. Trigger and wording: *design decision, grade none*: no verified threshold for when persistent exercise pain warrants a check (clinical pain-monitoring trials use clinician-set thresholds that could not be verified, §10 note); 14 days matches two 7-day blocks of §7's first bullet.
- Free text (intake, check-in and discomfort notes, "¿Cómo te ha ido?") reaches the model as context (§8), shown to the user exactly as sent. It is **never matched against terms**, never triggers a health message (the note above is triggered by levels and dates only), never used to diagnose, and never changes a figure by itself: every number and trigger uses structured fields (no fields are extracted from the text, ADR-91).
- Muscle soreness is not collected: it is a poor indicator of recovery or of adaptation [Schoenfeld, Contreras 2013; Nosaka et al. 2002].

## 8. Data, privacy and cost

- Personal use: no prior consent screen, by user decision. Before distributing the app to other people, each must accept the use of their data and the coach provider's terms; this condition is written, not implemented.
- The `coach` Edge Function sends a compact summary (last 8 weeks at most), never raw tables or photos. `coach_summary` (`04` §7.8) caps it at 16 384 bytes (about 4 000 tokens) and excludes raw rows and photos; exercises go by catalogue key or custom id. **Free text (user decision 2026-11-01, reverses the earlier exclusion of all free text):** the summary carries one block "Lo que el entrenador sabe de ti": the intake free text (up to 500 characters), and the check-in notes, discomfort notes and "¿Cómo te ha ido?" answers of the last 8 weeks, newest first, verbatim, cut at 2 000 bytes in total (*design decision*). The user sees that block exactly as sent, in the Trainer tab, and can leave any line out of what is sent (the original note is kept). Set and routine notes, food names and custom exercise names stay excluded. Use limits in §7.
- Cost control by money, not by calls (ADR-77, ADR-90): 3 € per user and 5 € in total per calendar month, plus a spending limit on the Anthropic account.
- Deleting the account deletes the coach's plans, recommendations, outcomes, usage and conversations (ADR-29); "Eliminar historial del entrenador" deletes the plans, recommendations, outcomes, reports and conversations without deleting the account; the confirmed derived values and the AI usage stay (E13 Q5, Q13).

## 9. Design decisions without evidence backing

Defaults chosen for this app; adjusted with real data, not scientific figures:
- Block length: 4 weeks (planning convention; confirmed by T-202: no trial compares block lengths).
- Complete routine (T-202, user 2026-11-03; §3): H1's 20-set cap; H3 side deltoid as a hard check (evidence *weak-moderate*); the conditions of H3 and H3b (2+ days, not "Ganar fuerza", a candidate inside the equipment); H4's exact bounds 6-20 and 3-8; target RPE 7-9 as whole numbers; drop sets and supersets only when the time does not fit, with their limits; planned weight from own history only; at most one technique note; favourites preferred after the hard checks, ties by logged history; 2-3 split candidates from scratch; one new pattern `shoulder_abduction`.
- Load increments: those available in the user's equipment (plates or dumbbells, E6).
- Place defines the default equipment; the user can change it.
- 5 % load drop after two failed sessions; 40 % fewer sets in a deload; three weeks without e1RM improvement as the deload trigger; at most 10 % calorie change per adjustment; 70 % logged days for a reliable intake; 14 days between circumference reminders; sleep below 6 h mentioned in the report (below the 7 h adult recommendation).
- Activity level (T-157, `04` §7.1): the active-kcal bands (150 / 300 / 500 / 750 per day), the 28-day window with 7 days minimum per source, the +1 level for 3 or more sessions per week, and the uncertainties 0.1 (data) and 0.2 (profile only). The step bands are published (§10, ref. 28).
- Experience (T-157, `04` §7.5): 24 sessions and 12 weeks for intermediate, 150 sessions and 52 weeks for advanced.
- Nutrition plan (T-161, `04` §8): rate 0 and adjustment 0 for strength, recomposition and maintenance; gain rate by experience 0.5 / 0.35 / 0.25 % per week (the range 0.25-0.5 is sourced, the split by experience follows "slower for advanced"); protein 2.2 / 2.0 / 1.8 g/kg by case (the lean-mass formula of §4 is not used: there is no body-fat input); fat default 25 %; 7 700 kcal per kg for every rate-to-deficit conversion (§4 "only without history" is read as: the adaptive expenditure of `04` §7.2 replaces BMR x factor when available); minimum change 50 kcal; at least 14 days between calorie changes (so the two weeks restart after a decision); a floor-limited plan keeps its slower rate instead of failing.
- Outcome candidates (T-161, `04` §8.4): weight only for loss and gain; e1RM per main lift by a 4-week extrapolation of the user's own least-squares slope over at least 3 weeks with data; body fat and circumferences are deferred (nothing to derive them from in the summary).
- Cardio (ADR-85, E13 Q23-Q29 resolved 2026-11-01): default 150 min for every intention (inside the sourced 150-300 band for fat loss); one steps floor of 7 000 (the ranges are sourced, the single number is chosen); "never below the current 28-day average", rounded down to 500; low-impact machines first (modality evidence is mixed) and the default ranking bike, elliptical, incline walk, rower, walking, with the most-logged cardio of the last 8 weeks first; no per-modality minute adjustment; no automatic ramp; cardio as the last exercise of each routine, split evenly in 5-minute units, at most 60 min per routine, the excess "por tu cuenta", outside "Duración de la sesión". **Removed after the 2026-11-01 check:** every warm-up element (the ACSM "5-10 min" figure was not found; then the user decided the coach ignores warm-ups), the age split 8 000 / 6 000 as a sourced figure, "cycling interferes less" as a rule (mixed evidence), "cardio before upper-body lifting is fine" (cardio is always last), separate cardio days (user decision), and the "start small" tip line (no tip lines).
- Equipment and alternatives (T-201, ADR-92, user 2026-11-02): one new item "Barra Z" and every other implement under "Otro"; one "Máquina de cardio" item; same barbell / EZ bar / dumbbell exercise = similarity 1.00 both ways (no barbell-vs-dumbbell growth trial found; Haugen 2023 backs equal hypertrophy across tools only); the 0.90 floor below which no alternative is offered or stored.
- Coach summary: 16 384-byte cap and the 12 main lifts / 10 discomforts / 8 muscle groups per week lists (`04` §7.8); fallback trend uncertainty of 0.5 kg per week without an interval.
- Trainer journey (§12, user-approved direction 2026-11-01): one "Entrenador" behaviour, with load progression, the 5 % drop, weekly calories inside the safe band (±10 % per block in total, one change ≤ 10 %, 14 days apart, floor, 500 kcal cap, rate range) and deloads applying on their own, and only phase changes and new blocks needing acceptance; scheduled deload in week 4 when none ran in the previous 7 weeks; data cleaning (partial day under 40 % of the 28-day median, excluded from every count; no calorie change in a week with fewer than 5 complete diary days or 3 weigh-ins); "Mantener" muscle groups at 4 weekly sets (6 from 65), "Priorizar" groups +2 sets per block up to 20, at most 3 prioritised groups; graded return in 3 steps of at least a week each; breaks pause the block (a calendar week with no session does not count) and resume at the next planned session; after a gap of 14 days or more, one failed session (instead of two) triggers the 5 % drop; experience = the higher of self-reported and history class, 2 years of consistent lifting for "advanced"; returning lifters keep their class; no correction of self-reported maintenance, replaced by the adaptive expenditure at its existing thresholds; deficit weeks only count towards a cut; maximum cut of 3 deficit blocks before a maintenance block is proposed, and at least 1 maintenance block after it; (regain phase, "returning" situation, cutting calories and pre-injury bests removed by ADR-91); "¿Seguimos?" after 6 blocks of gain, maintenance or recomposition; (minimal phase removed by the user, 2026-11-03); session adherence 80 % as "high"; +2 weekly sets for a stalled muscle group, at most once per block, never above 20 sets; one session without discomfort before a returned exercise progresses; the health note at 14 days or 3 sessions at level 4-5, once; free text capped at 500 characters (intake) and 2 000 bytes (total). ## 12. Long-term follow-up: the trainer journey

User-approved direction (2026-11-01). How the coach follows one person for months or years. **Evidence caveat:** the coaching *process* (intake, weekly review, when to change phase) has almost no outcome trials; the evidence covers the levers (energy, volume, deloads, detraining, retraining) and two behavioural mechanisms (self-monitoring [Burke et al. 2011], autonomy support [Ntoumanis et al. 2021]). Sequencing phases over a year has no trial in recreational lifters (*none*): §12.3's durations are *design decisions* anchored where stated. Every figure is computed server-side (§1).

**Who decides:** *Rule* = deterministic server code (all numbers and all triggers). *Model* = the LLM chooses among server-validated options and explains, reading the structured summary and the free-text block (§8). *User* = accepts or edits phase changes and new blocks; undoes or cancels any automatic change (load, calories inside the safe band, deload), or starts a deload (§1).

### 12.2 First block (cold start)

The first block starts from the priors and passes the routine checker (§3 "Complete routine"): 10 weekly sets per major group as the starting point (H1), rep ranges per H4, target RPE 7-9. Starting loads come only from the user's own logged sessions or the load the user enters. After 14 or more days without a completed session, the first session of each exercise keeps the last load, with no increase, and one failed session (instead of two) triggers the 5 % drop, so loads re-adjust from the first sessions back (*design decision*; §12.5). Retraining at ordinary doses regains quickly [Halonen 2024; Staron 1991], and no study prescribes a different dose for retraining (*none*), so someone coming back after a break gets the normal ranges.

### 12.5 Busy periods and breaks

- **Busy or travelling:** the user changes days or place ("Revisar el bloque", §12.8) or uses "Solo unos días". (Minimal phase removed, user 2026-11-03; re-plan in E14.)
- **Breaks follow the plan, not the calendar (*common practice in leading apps*, product benchmark):** a calendar week with no completed session does not count as a block week, so the block pauses and the user resumes at the next planned session, where they left off (the end-of-block review and the week-3 deload evaluation move with it). Loads re-adjust from the first sessions back (§12.2: no increase on the first session, one failed session triggers the drop after 14 or more days off).
- **Long break:** the paused block resumes where it stopped (no regain phase since ADR-91). Losses scale with the length of the stop and are larger over 65 [Bosquet 2013; *strong*]; retraining recovers them quickly and "trainees should not be too concerned about occasional short-term training breaks" [Halonen 2024; *moderate*]. The 14-day threshold and the absence of a sourced load cut on return are *design decisions*.
- **Illness:** no rule (none verified).

### 12.6 Weekly follow-up

The weekly report shows the weekly average weight and trend against the target rate, logged diary days, sessions done against planned, open discomforts and the loads changed automatically that week, each with its reason. Self-monitoring of diet and self-weighing are consistently associated with weight loss (Class IIa, Level A; self-weighing at least weekly may help) [Burke 2011; *moderate*]; explaining the rationale is part of the autonomy support associated with better health behaviour [Ntoumanis 2021]. Weekly changes are limited to calorie changes inside the §4 safe band (only on clean data) and the §3 deload, both applied on their own with "Deshacer" or "Cancelar descarga"; phase and volume change only at the end-of-block review, with the user's OK.

### 12.8 Life changes

User-approved design (2026-11-01). How the coach reacts when the user's life changes in the middle of a block. **Evidence caveat:** apart from the rows that cite a source, these are *design decisions*: how a trainer handles each event is *common practice* with no outcome trials. Every row follows the "Entrenador" split (§1): small, reversible changes apply on their own; a new block or a phase change needs the user's OK. Free text never triggers anything (§7).

**"Revisar el bloque" (mechanism for rows 1-3 and 5).** When the user saves a new place, equipment, days per week or session length in "Mi entrenamiento" during an accepted block, the Trainer tab offers "Revisar el bloque" with three choices:
- **"Adaptar el bloque"** (default for a place or equipment change only; *rule*, no model call, free; amended by T-202/ADR-93: there is no server split any more, so a days-per-week or session-length change offers only "Bloque nuevo" and "Solo unos días", rows 2-3). It keeps the block week, the phase, the sets per muscle group and the rep ranges. Exercises the new equipment cannot do are swapped by the server to a candidate with the same muscle group and movement pattern, in the order of §3 "Exercise selection" (T-179). With no such candidate it takes any candidate of the same muscle group; with none at all, the slot is dropped and the preview says so. The cardio exercise is re-picked by the §3 default ranking, with the same minutes. The user sees the preview and applies it with one tap.
- **"Bloque nuevo"**: an early end-of-block review (§12.4; *model*, a paid call). It needs acceptance like any new block.
- **"Solo unos días"**: the user picks an end date. The swaps apply only to sessions until then, and then the original routines and their loads return untouched. Fewer training days in that period: minimal phase removed (user, 2026-11-03); re-plan in E14. The block's phase and calories do not change.

**Loads for an exercise new to the block (every row):** the planned weight is the user's last working weight on that exercise (their own history). Without history there is no planned weight, and the first session finds it by RPE: the user picks a weight they can lift for the bottom of the range at RPE 7-8 (RIR 2-3, §3). A load is never converted from another exercise: no conversion between exercises was verified (*none*). Double progression starts from that session.
