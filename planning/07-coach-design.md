# Coach design: evidence base and default rules

Design base of the performance assistant (E13) and of the data it needs (E10-E12). Decisions: ADR-76 (coach), ADR-77 (AI provider and cost), ADR-78 (profile and catalogue).

**Principle:** every rule has a source, a common practice or a "design decision" label. No figure exists for convenience. Every source was checked before the E13 breakdown (2026-10-29, §10); the cardio and trainer-journey sources on 2026-11-01 (§10 29-66); the complete-routine sources on 2026-11-02/03 (§10 71-83, T-202).

## 1. What the coach does

**User inputs:**
- **Intention:** "Ganar fuerza", "Ganar musculatura", "Perder grasa", "Recomposición" or "Mantenimiento".
- **Static preferences** (Preferencias): training place (home, gym, other), available equipment and, optionally, days per week and session length.
- **Discomfort:** logged per exercise when it happens (E12). It blocks load increases (§7). It is **not an input of block creation** (user 2026-11-04, as for the folder review): the block builder and "Desde una carpeta" neither hide nor mark an exercise for a discomfort (§3 "Block builder"). *Superseded:* "at levels 4-5, keeps the exercise out of the next block's proposal".
- **Intake ("Para conocerte", amended by ADR-91, user 2026-11-02, §12.1):** training years ("Tiempo entrenando"), known maintenance calories and free text, nothing else. (The situation, injured area, pre-break bests and cutting calories were removed by T-198/T-200; injuries come only from logged discomforts, §7.) Every answer is a **provisional prior**, labelled "según lo que nos contaste", that measured data replaces (§2, §12.1). Editable at any time.
- **Feedback at the end of a block:** "¿Cómo te ha ido?" and, optionally, "Priorizar" / "Mantener" per muscle group (§12.4).
- **Self-reports kept minimal:** RPE per set and the discomfort log, plus the block feedback; no pump, soreness or readiness questionnaires. *Common practice in leading apps* (product benchmark); soreness is a poor signal anyway (§7).

**Phase:** each block runs in one phase (cut, gain, maintenance, recomposition; §12.3; the regain phase "Recuperar" was removed by ADR-91 and deferred to Phase 3; the minimal phase and "Tengo poco tiempo" were removed by the user on 2026-11-03). The coach proposes a phase change **only at the end-of-block review**; the user accepts or keeps the current phase.

**Output:** a plan in 4-week blocks (design decision, §9) with:
- the routines of each week, using the existing routine model;
- calories and macros;
- progression per exercise;
- expected outcomes (weight, body fat, circumferences or e1RM) **only when the plan can justify them**. The user never enters target numbers.

**Review:** at the end of each block; earlier only if the preferences change or the user asks.

**One behaviour, "Entrenador" (user decisions 2026-11-01; no mode selector; amends ADR-76's "adjustments are proposals accepted one by one", "suggestions never rewrite planned values" and "nothing is applied without acceptance"):** the user accepts or edits the whole plan (new block) and any phase change; **everything inside an accepted block applies on its own**, each change visible with its reason and undoable:
- load progression: the §3 increase and the 5 % drop, written to the next session of that exercise, with "Deshacer";
- weekly calorie changes inside the safe band of §4: **proposed, applied only on the user's "Aplicar"** (user decision 2026-11-05, E14; *superseded:* "with Deshacer");
- deloads, scheduled or triggered (§3), which the user can cancel, or start one themselves.
Autonomy support, which includes explaining the rationale and offering choice, is associated with better health behaviour [Ntoumanis et al. 2021; *strong* for the mechanism, small-to-medium effects]; which changes a trainer makes without asking has no evidence (*common practice*), so the split is a *design decision*: automatic changes are small, bounded, explained and reversible; the long-term direction (phase, block) stays the user's.

**Grounding:** the model only describes app features, screens and data that exist; the server validates its output against the list of features and the summary, and drops any text that mentions anything else (anti-pattern seen in AI coaches: inventing features). *Common practice in leading apps* (product benchmark, not science).

**Division of work (amended by T-219, user 2026-11-04; supersedes the T-202 version):** every calculation (BMR, activity, adaptive expenditure, weight trend, calories and macros, cardio minutes and steps, progression, e1RM, adherence, deload trigger, phase triggers) is deterministic, in SQL or TypeScript, and testable. **The training block is built by deterministic rules and the user's picks, with no model call** (§3 "Block builder"): the app computes the split options, sets, reps, RPE, rests and the time fit; the user picks the split, the routine type per day and every exercise; "Desde una carpeta" checks the user's folder against the same 100 % (§3 "Block builder" (h)). The folder review (§3 "Folder review") and the nutrition plan (§4) are model-free too. Where a model is still used (weekly report, chat), its output is structured, validated before it is shown, and it never writes to the database. §12 marks, per stage, what is a rule, what is model judgement and what the user decides. *Superseded* (history): "the training block is built by the model" with the H1-H7 checker and one retry (T-202), and before it "the model only picks one exercise per slot among server candidates".

## 2. Derived values (confirmed by the user)

| Value | How it is computed | Confidence without history |
|---|---|---|
| Basal expenditure | Mifflin-St Jeor with sex, age, height and weight (profile, `04` §1) | High (validated equation) |
| Activity level | Starts from `profiles.activity_level` (ADR-78); the coach proposes a change from Health Connect steps (bands of Tudor-Locke et al. 2011), active calories when there are no steps, and the completed sessions per week (3 or more raise a measured level by one). Exact mapping in `04` §7.1. Sessions alone never change the profile level (it already includes training) | Low: shown as provisional |
| Total expenditure | BMR × activity factor (`04` §1.3) without a reliable diary; with one, the capped 28-day intake, plus a weight-change term only when the trend has 4 weekly averages and 8 weigh-in days, clamped to one top-of-range rate (`04` §7.2-§7.3; *design decision*, T-180) | Improves with months of data |
| Weight trend | Slope of weekly averages, with its confidence interval (§5) | Depends on the number of weigh-ins |
| Experience | The **higher** of the self-reported training age (intake) and the app history class (`04` §7.5). Self-reported consistent lifting: under 6 months beginner, 6 months to under 2 years intermediate, 2 years or more advanced. ACSM: intermediate "approximately 6 months of consistent RT experience", advanced "years of RT experience" [ACSM 2009; *strong*, expert-based]; the 2-year cut for "years" is a *design decision* | Self-reported until the history class is equal or higher; shown as "según lo que nos contaste" |

**Returning lifters keep their experience class (amends the earlier "without history: beginner").** ACSM 2009 counts people "who have not trained for several years" as novices, but retraining is faster than first-time training: after 10 weeks of detraining, losses "were regained rapidly", with larger leg-press strength and muscle-area gains in the first 5 weeks of retraining than in the same weeks of first-time training [Halonen et al. 2024; *moderate*, RCT, 55 untrained adults]; women detrained 30-32 weeks lost strength "but not to pretraining levels" and fibre area rose significantly within 6 weeks of retraining [Staron et al. 1991; *moderate*, small n, women]. The evidence is on short breaks and on people who were trained for months, not years-long layoffs; so this is a *design decision built on that evidence*. **What experience drives (one rule):** the gain rate and protein (`04` §8) and the default number of days when the user sets none (beginner 3, intermediate and advanced 4, `04` §9.1; inside ACSM's 2-3 / 3-4 / 4-5 days by status [ACSM 2009]). It does **not** change the volume: every class starts at the 10 weekly sets of §3 (no verified source for a lower beginner dose: *none*; the former "beginner 8 sets" is dropped). It never sets starting loads (§12.2).

**Intake priors and their handover (*design decision*, §12.1):** self-reported values are labelled provisional and replaced by measured ones as soon as the measured rule's own threshold is met. Self-report is biased: athletes under-reported energy intake by 19 % against doubly labelled water (11 studies) [Capling et al. 2017; *strong*, athletes]. No study gives a correction factor or a weighting between a remembered maintenance and an equation (*none*), so the app applies no correction: the known maintenance replaces BMR × factor as the expenditure prior until the adaptive expenditure qualifies (28-day diary at 70 % logged days, 4 weekly averages and 8 weigh-in days), then the adaptive value replaces it and the card says so once ("Ahora usamos tus datos reales: tu gasto medido es de 2.450 kcal.").

**Intake extraction: removed (ADR-91, T-198).** No model extracts fields from the intake text; the free text is sent verbatim as context (§8).

**Confirmation rule:** each block shows a card with the derived values, their source and the missing data. The user accepts or edits them. A value is not used until confirmed; until then it is shown as provisional. A confirmed value is asked again only when its new estimate falls outside the uncertainty of the confirmed one.

**Intake completeness:** adaptive expenditure uses only days with a logged diary; days without entries are excluded, not counted as zero. Below 70 % logged days in the window (design decision) the estimate is shown as unreliable and the coach does not propose calorie changes from it.

**Data cleaning before any calorie change (*common practice in leading apps*, product benchmark; thresholds are *design decisions*):** a day counts as logged only if it looks complete: a day under 40 % of the median of the logged days of the 28-day window is partial and is excluded from the expenditure anchor **and** from every count of logged days (the 70 % reliability, the weekly gate below). One rule for the whole app, the one already built for the anchor (`04` §7.3, T-180); it replaces the earlier "50 % of the target" draft, which had no target before the first plan. No "incomplete day" control is added (scope). Missing weigh-ins are never filled in; the trend uses the weigh-ins that exist (§5). A week with fewer than 5 complete diary days (70 % of 7, the rule above applied per week) or fewer than 3 weigh-ins changes no calories; the report says why ("Esta semana faltan registros: no cambiamos tus calorías.").

## 3. Training

### Complete routine (T-202, user 2026-11-03; supersedes the fixed skeleton)

> **Superseded for block creation by §3 "Block builder" (T-219, user 2026-11-04).** No model builds or reviews a block any more, so the block-generator gate H1-H7, the soft and free lists, "Starting points", "Model input" and every "the model ..." sentence in this section are **history**: they describe the model-built block (T-202 to T-215) and stay only until the builder task replaces that code. **Still in force** (read by the builder, the folder review or statistics): fractional set counting, "Taxonomy", "Lower-body filing", "What H1 counts", the "Favourites" order (now the picker order) and the bounds of "Routine tools" for the values the builder writes. H3 and H3b are not rules of the builder (user 2026-11-04) nor of the folder review ("Removed").

**One checker** (server, deterministic) judges any set of routines against the intention, days per week and session length. It validates the **block generator** (a hard failure is rejected: one retry, then the call fails and nothing is stored). The model writes the soft comments and proposed changes; the server re-checks every proposed change before it is shown. The folder review has its own deterministic rules (§3 "Folder review"). Sets are counted fractionally: primary muscle 1, each distinct secondary 0.5 (`04` §4, the method that fit best in Pelland 2026 [*strong*]); warm-up sets do not count.

**Population and transfer:** the guideline (ACSM 2026) covers healthy adults of all training levels; the regional trials below are small, mostly young untrained or recreationally active adults (stated per rule); they transfer to recreational lifters, with smaller certainty for advanced lifters.

**Hard checks:**
- **H1 Weekly sets:** each of chest, back, shoulders, quads, hamstrings and glutes has 10-20 fractional sets a week; a group marked "Mantener" at least 4 (6 from 65) (§12.4). Minimum: ACSM 2026, hypertrophy "enhanced by higher volumes (≥10 sets/wk)" [*strong*]; the 20 cap is a *design decision* on diminishing returns [Pelland 2026; *strong*]; the "Mantener" floor rests on Spiering 2021 [*moderate*]. Only strength exercises add sets (§3 "What H1 counts"). When the minimum cannot fit (1 day a week, or a session too short), H1 is not enforced and the plan or review shows "Por debajo de lo recomendado" (never blocks).
- **H2 Sessions:** at least 2 lifting sessions a week when the user has 2 or more days. ACSM 2026: strength enhanced by "≥2 sessions/week" [*strong*].
- **H3 Side deltoid:** at least 1 `shoulder_abduction` exercise a week. Side-deltoid activation 5 % in the bench press, 27.9 % in the shoulder press, 30.3 % in the lateral raise [Campos 2020; *weak*, EMG, 13 trained men]; lateral raises, 10 sets a week, grew it 3.3-4.6 % [Larsen 2025; *moderate*, 24 trained adults]; no trial of pressing alone vs pressing plus raises was found. *Design decision* on that evidence and the user's priority.
- **H3b Knee extension (rectus femoris):** at least 1 quads isolation (knee-extension) exercise a week. Squats: rectus femoris and hamstrings "did not change" while the knee extensors grew 4.6-4.9 % [Kubo 2019; *moderate*, 17 young men]; leg press +1.1 % (n.s.) vs knee extension +13.2 % in rectus femoris [Kinoshita 2026; *moderate*, 17 untrained adults, within-subject].
  - *Conditions for H3 and H3b:* 2 or more days a week, intention other than "Ganar fuerza", and at least one candidate inside the user's equipment; otherwise the review shows a plain note and nothing is required.
- **H4 Rep ranges:** 6-20 on any exercise for "Ganar musculatura", "Perder grasa", "Recomposición" and "Mantenimiento"; for "Ganar fuerza", 3-8 on main lifts and 6-20 on the rest. Low (≤ 60 % 1RM) and high loads gave similar hypertrophy; 1RM gains favoured high loads [Schoenfeld, Grgic et al. 2017; *strong*]; ACSM 2026: strength enhanced by loads ≥ 80 % 1RM. The exact bounds are *design decisions* (the %-to-reps mapping was not verified). No singles or doubles (recreational lifters logging their own RPE).
- **H5 Effort:** every working set carries a target RPE of 7, 8 or 9 (1-3 reps in reserve); no planned failure sets; no warm-up sets (§3 "Warm-up"). ACSM 2026: sets to failure do "not enhance gains", target 2-3 RIR, "insufficient evidence to quantify exact RIR" [*strong*]; RIR targets are feasible and more accurate close to failure [Bastos 2024; *weak-moderate*, scoping review, 31 studies]; failure gives no hypertrophy advantage [Refalo 2023].
- **H6 Safety and fit:** catalogue exercises (or the user's own) inside the equipment; no exercise with an unresolved level 4-5 discomfort (§7; injuries come only from logged discomforts, ADR-91); sessions = days per week; each routine's time (sets, reps, rests, supersets and drop sets counted) fits "Duración de la sesión"; 1-10 sets per exercise; rests within §3 "Rest between sets"; cardio as computed by the server (§3 "Cardio prescription"), unchanged by the model.
- **H7 Order ("Ganar fuerza"):** the main lifts go first in the session. ACSM 2026: strength enhanced by "performing the exercise at the start of sessions" [*strong*]; [Nunes 2021].

**Soft (the model comments and may propose; never blocks):**
- Each major group in 2 sessions a week: volume-equated frequency shows "no significant difference" for hypertrophy [Schoenfeld, Grgic, Krieger 2019; *strong*]; strength rises with frequency [Pelland 2026; *strong*], so the model stresses it for "Ganar fuerza". A split that trains a group once a week (e.g. legs in push-pull-legs-upper) is valid.
- Movement-pattern coverage (squat or lunge, hinge, horizontal and vertical push, horizontal and vertical pull): no trial defines completeness by patterns (*none*); some systematic exercise variation helps regional growth and strength, excessive rotation may hurt [Kassiano 2022; *moderate*, 8 studies, 241 young trained men].
- A knee-flexion exercise (leg curl), seated preferred: hamstrings did not grow with squats [Kubo 2019]; a hip-extension (hinge) exercise grew the biceps femoris long head more than Nordics [Bourne 2017; *moderate*, 30 recreationally active men]; seated curl +14 % vs prone +9 % [Maeo 2021; *moderate*, 20 adults]. H1 already forces hamstring sets (hinge or knee flexion).
- Rear deltoid (reverse fly, face pull): posterior-deltoid activation 24 % in the lateral raise, 11.4 % in the shoulder press, 3.5 % in the bench press [Campos 2020; *weak*]; no growth trial found.
- An overhead triceps extension when triceps get isolation work: long head +28.5 % overhead vs +19.6 % neutral [Maeo 2023; *moderate*, 21 adults, within-subject]; whether pressing alone grows the long head: *not found*.
- Calves: a calf raise when time allows (*none*: no study found on compound lifts and calf growth).
- Undulating weekly loads for experienced "Ganar fuerza" users (§3 "Periodization").
- What to keep between blocks: lifts still improving stay; a few accessories change on purpose [Kassiano 2022].

**Free (the model or the user):** split type; exercise choice within a group or pattern (favourites first, below); order outside H7; number of exercises; biceps isolation (adding single-joint arm work to compounds added nothing in trained men [de França 2015; *moderate*, 20 trained men]); chest angle (*not found*); forearms and core (*not found*; no required sets); glute medius (little growth with squats or hip thrusts [Plotkin 2023; *moderate*, 34 untrained adults]; abduction growth trial *not found*); rests within bounds.

**Starting points (user UX decision 2026-11-03):** a new block starts either **from scratch** (the model proposes 2-3 split candidates for the days and minutes, recommends one with its reason, and the user picks; the model then builds that split) or **from one of the user's routine folders** (the model reviews it against the checker and proposes changes the user accepts or rejects; then it becomes the block). Both pass the hard checks before the block is stored. **Block length stays 4 weeks** (§9; *design decision, none*: no trial compares block lengths; it keeps variation systematic [Kassiano 2022], gives the review 3 weeks of e1RM and matches the week-4 deload and diet break).

**Model input:** intention, phase, days, minutes, equipment; the user's routine folders and the last 8 weeks of logged performance per exercise (sets, e1RM trend, RPE); the previous blocks with adherence (and "¿Cómo te ha ido?" once T-190 stores it); favourites (ADR-94); unresolved level 4-5 and open discomforts; the free-text block (§8); the eligible catalogue by muscle group and pattern, unranked and uncapped. Cardio is appended by the server unchanged (ADR-93). The block carries a reason per split and per exercise and a "what changed versus the last block and why" field.

**Favourites (user decision 2026-11-03):** a starred exercise (exercise detail) is the preferred pick within its muscle group or pattern **after** the hard checks pass; it never adds volume and is never forced in. Ties between favourites, or with no favourite, go to logged history (most sessions in the last 8 weeks, then the best e1RM trend). When a favourite cannot fit, the reason says why in one line. Evidence: self-selected exercises gave a small lean-mass edge [Rauch 2020; *weak-moderate*, 17 highly trained men]; equipment type showed no consistent effect [ACSM 2026], so honouring preference costs nothing; ACSM 2026 asks for programs "individualized to maximize adherence, enjoyment, safety, and effectiveness" (expert judgement within a guideline).

**Taxonomy (T-202):** one new `movement_pattern` value, `shoulder_abduction`, for the 7 lateral-raise keys now tagged `isolation`: `lateral-raise`, `cable-lateral-raise`, `seated-dumbbell-lateral-raise`, `side-lying-lateral-raise`, `bodyweight-lateral-raise`, `plate-loaded-lateral-raise`, `single-arm-plate-loaded-lateral-raise`. It counts as an isolation role and is not a main lift. Knee extension is expressed as quads + `isolation` (`leg-extension`, `single-leg-extension`, `banded-terminal-knee-extension`, `reverse-nordic-curl`) and knee flexion as hamstrings + `isolation`; rear deltoid and overhead triceps are soft rules judged by the model, so they get no tag. Front raises, upright rows and face pulls keep their tags. *For the planner:* hinges are filed under glutes as primary (`04` §9.4); check that the hinge rows list hamstrings as a secondary muscle, or H1 undercounts hamstrings.

**Lower-body filing (Checkpoint E13-H feedback, 2026-11-03; supersedes "the catalogue files squats and lunges under glutes" in `04` §9):** one primary and one secondary group per lower-body movement, so H1 counts the muscles that grow and H3b counts only knee extension.
- *Knee-dominant compounds* (squat and its variants, leg press, hack squat, lunge, split squat, step-up, wall sit, jump squat, box jump): **quads primary, glutes secondary**. Squats grew the knee extensors 4.6-4.9 %, gluteus maximus 2.2-6.7 % and adductors 2.7-6.2 %, not the rectus femoris or hamstrings [Kubo 2019; *moderate*, 17 young men]; against the hip thrust, the squat grew the quadriceps (+3.6 cm²) and adductors (+2.5 cm²) more and the gluteus maximus similarly [Plotkin 2023; *moderate*, 34 untrained adults]; the leg press grew quadriceps +4.9 %, gluteus maximus +15.4 %, adductor magnus +6.2 % [Kinoshita 2026; *moderate*, 17 untrained adults]; squats and leg press grow the gluteus maximus [Krause Neto 2025; *strong*]; lunges: high quadriceps and gluteus maximus activity [Escamilla 2025; *weak*, EMG, 20 adults]. No hamstrings secondary (Kubo 2019). Quads as primary is a *design decision*: with one primary, the 0.5 secondary undercounts glutes (the leg press grew them more than the quads in %); plyometric variants follow for consistency (*none* for their growth).
- *Hip extension* (hip thrust, glute bridge, kickback, pull-through, and the bent-knee deadlifts): glutes primary, hamstrings secondary (as above). The bent-knee deadlifts (`deadlift`, `sumo-deadlift`, `hex-bar-deadlift`, etc.) keep their current primary.
- *Straight-knee hinge* (Checkpoint E13-H feedback, 2026-11-03): **hamstrings primary, glutes secondary** for `romanian-deadlift`, `ez-bar-romanian-deadlift`, `dumbbell-romanian-deadlift`, `banded-romanian-deadlift`, `smith-machine-rdl`, `stiff-leg-deadlift`, `single-leg-romanian-deadlift`, `one-arm-single-leg-dumbbell-romanian-deadlift`, `one-arm-single-leg-kettlebell-romanian-deadlift`, `kettlebell-single-leg-deadlift`, `single-leg-rdl-hold`, `db-kickstand-deadlift`, `double-db-kickstand-deadlift`, `kettlebell-kickstand-deadlift`, `good-morning`, `banded-good-morning`, `bodyweight-good-morning`, `smith-machine-good-morning`. Evidence: 9 weeks of stiff-leg deadlifts grew the whole hamstrings 7.0 ± 8.1 % and the semimembranosus 11.2 ± 12.7 % [Morin 2025, ref. 90; *moderate*, 36 untrained adults, 3D ultrasound]; in the Romanian deadlift biceps femoris and semitendinosus activity exceeds erector spinae activity [Martín-Fuentes 2020, ref. 91; *weak*, EMG review]. Gluteus maximus growth from a straight-knee hinge alone: *not found*, so glutes stay as the secondary. Good mornings and the kickstand (staggered-stance) and single-leg variants follow by the same joint action (*design decision, none* for their growth). Population: untrained adults; transfers to recreational lifters. Journey stage: plan and block review (H1).
- *Hip abduction* (machine, band, clamshell, fire hydrant, side-lying abduction): **glutes** (gluteus medius and minimus abduct the hip [StatPearls, ref. 86]).
- *Hip adduction* (machine, band, side-lying adduction, adductor stretches): new group **"Aductores"** (adductor magnus, longus and brevis adduct the hip [ref. 86]); it is **outside H1** (no required sets; adductors grow with squats and leg press, Kubo 2019, Kinoshita 2026). Enum value, label and body-map entry are implementation.
- *Hip flexion* (leg raises, knee raises, L-sits, sit-ups, V-ups, toes-to-bar, flutter and scissor kicks, hollow and boat holds, knee tucks, mountain climbers): **core**, never quads (the iliopsoas is the main hip flexor [ref. 86]); `pilates-side-bend` is core too.
- Knee extension: quads + `isolation`, and **H3b counts only** `leg-extension`, `single-leg-extension`, `banded-terminal-knee-extension`, `reverse-nordic-curl`. Knee flexion: hamstrings. Calf raises: calves. Stretches carry the stretched group (forward folds: hamstrings; hip-flexor, couch and quad stretches: quads).
- *Keys, not names:* the categories above are filed by catalogue key, by the joint action, whatever the exercise's category (strength, yoga, mobility, cardio). So frontal-plane and inner-thigh mobility (`seated-straddle-stretch`, `lateral-leg-swing`, `happy-baby`, `garland-pose`) is adductors; hip-flexion flows (`downward-dog-to-knee-drive`, `downward-dog-knee-tuck`) are core; `kettlebell-sumo-high-pull` is a hinge (glutes, hamstrings secondary); `wide-legged-forward-fold` is hamstrings. A key that fits no category keeps its tag. Filing these is a *design decision* from anatomy [ref. 86]; *none* for their growth.
- *Population and transfer:* young men and untrained adults; transfers to recreational lifters. Journey stage: plan and block review (H1, H3b).

**What H1 counts (T-211, user decision 2026-11-03: H1 counts only strength exercises):** filing (above) says which group an exercise belongs to; this says whether its sets add to H1 at all. Applies to the coach's checks only (block builder slots and score, folder review, H1 note "Por debajo de lo recomendado"; T-219 replaced the block generator).
- *Criterion:* an exercise counts when it is **dynamic resistance work logged as reps that can be prescribed inside H4 (6-20 reps) at H5's target RPE 7-9**, against an external load or the body weight (barbell, dumbbell, machine, cable, band, bodyweight squats, push-ups, pull-ups, glute bridges, banded clamshells). H1's set-volume figures come from such sets: ACSM 2026 "≥10 sets/wk" and Pelland 2026's fractional counting [refs 71, 4; *strong*]. A set that cannot carry a rep range and an RPE target is not the set those figures describe.
- *Does not count:* stretches, yoga poses and mobility flows (`deep-squat-hold`, `squat-hold`, `cat-cow`, `lateral-leg-swing`, forward folds); cardio rows (`stationary-bike` and every `cardio_machine` key, `running`, `walking`, `jump-rope`, `jumping-jacks`, `battle-ropes`); impact and plyometric moves (`jump-squat`, `box-jump`, `burpees`, `plyo-lunge`; *none*: no source opened on their growth); **every timed hold**, including isometric strength holds (`wall-sit`, `plank` and its variants, `dead-hang`, `l-sit`, levers, `handstand-hold`) and loaded carries (`-farmers-walk`, `-carry`, `plate-pinch`).
- *Why holds are out although they build muscle:* isometric training does grow muscle, more at long muscle lengths (0.86-1.69 % a week) and "regardless of training intensity" [Oranchuk 2019, ref. 87; *moderate*, systematic review of small, mostly lab trials with maximal-intent dynamometer protocols, not bodyweight holds]; stretching grows it slightly (d = 0.20; only long, frequent stretching reached significance) [Warneke 2024, ref. 88; *strong* for a small effect]; aerobic training can too [Konopka 2014, ref. 89; *moderate*, review, untrained and older adults]. No study equating a timed hold, a stretch or a cardio bout to one working set was found (*not found*), so excluding them is a **design decision** (the user's): H1 measures sets the checker can compare, and the model must place real strength sets instead of padding with holds. Consequence accepted by the user: `wall-sit` stays filed as quads (knee-dominant, above) and keeps showing in stats, but adds 0 to H1; a home user whose only quads work was holds now gets squats, lunges or step-ups proposed. Core is outside H1, so planks change nothing there.
- *Custom exercises* (`is_custom`): **count**, unless their metric type is time- or distance-based (`duration`, `weight_duration`, `distance_duration`, `floors_duration`, `steps_duration`), which follows the hold and cardio rule above. *Design decision, none*: the user created the exercise as work; the metric type is the only fact the app has about it.
- *Source of truth:* a **stored per-key flag** on the catalogue, set by the catalogue generator from the lists above, not derived at runtime. Science view: the criterion is a property of the movement and its load (same principle as "Keys, not names" above); `metric_type` alone cannot carry it (`reps_only` mixes glute bridges with cat-cow and leg swings; `duration` mixes wall sits with stretches). A key not named above follows the criterion; doubtful keys default to counting when they are loadable dynamic work, else not. Column name and migration are implementation.
- *Unchanged:* warm-up sets never count, a failure set is not planned, a drop set counts as 1 (`04` §4); a non-counting exercise still takes session time (H6) and may stay in a routine.
- *Statistics "Series por grupo" (E8):* not affected by this rule; it reports what the user did, not what H1 checks. Whether it should also exclude non-strength work is a product question for the PM (*none*: no evidence settles it).
- *Population and transfer:* ACSM 2026 covers healthy adults of all levels and Pelland 2026 pooled trained and untrained adults; the isometric and stretching reviews are mostly young untrained adults. Transfers to recreational lifters. Journey stage: plan and block review (H1).

- *Main-lift pattern:* only multi-joint lifts carry `squat`, `hinge`, `lunge` or a push/pull pattern. - *Counts for H1:* mat Pilates sequences, bird dogs and supermans do not count (§3 "What H1 counts": they cannot carry a 6-20 rep range at RPE 7-9; *design decision*).
- *Custom exercises:* the app stores one primary group, no secondaries and an optional pattern. The review counts the primary at 1 when it is an H1 group, never infers secondaries or a pattern from the name, and treats no pattern as not a main lift; a `full_body` custom adds 0. Counting follows §3 "What H1 counts" (metric type). *Design decision*; the user can fix a wrong group or pattern in the exercise's own edit form.
- *Population and transfer:* Lanza 2024 healthy men (training status not stated), Gentil 2013 untrained young men; transfers to recreational lifters with less certainty for advanced lifters. **Journey stage (§12):** plan (folder review, block builder) and statistics.

**Counting.** For each H1 group G (chest, back, shoulders, quads, hamstrings, glutes): `sets(G) = Σ working sets × w` over every counting exercise of every routine, `w = 1` if G is the primary group, `0.5` if G is among its secondary groups, else 0 (one 0.5 per exercise however many of its secondary muscles fall in G). Fractional counting predicted growth best [Pelland 2026, ref. 4; *strong*]. A **lifting routine** is a routine with at least one counting exercise.

**Checks (each confirmed with sources opened 2026-11-04, §10):**
- **C1 Weekly volume:** every H1 group `sets(G) ≥ 10`. ACSM 2026: hypertrophy "enhanced by higher volumes (≥10 sets/wk)" [ref. 71; *strong*]. **No upper bound** in the review: ACSM 2026 reports diminishing returns beyond "~18–20 weekly sets for hypertrophy" and Pelland 2026 "diminishing returns", not harm, so more than 20 is neither a finding nor a penalty (T-220: above 20 a neutral note is shown, "Folder review: coverage" below). The six groups are a *design decision* reading of ACSM's "all major muscle groups being engaged". Same figure for every intention and experience level ("training experience had a minimal impact", ref. 71).
  - *Quads and hamstrings (T-220 note, sources opened 2026-11-04):* the 10 is **extrapolated from pooled data** for these two groups: ACSM 2026 states "The available evidence did not compare distinct body regions or muscle groups" and gives no quadriceps or hamstring figure [ref. 71; *strong* for the pooled figure, *weak* for its per-group transfer]. *Quads:* in trained lifters anterior-thigh thickness grew similarly with 12, 18 and 24 weekly lower-body sets (sum +7.7 %, +6.7 %, +6.1 %; time effect only, no group difference) [Aube 2022, ref. 104; *moderate*, 35 resistance-trained individuals]; moderate (12-20) and high (> 20) weekly sets did not differ for the quadriceps (p = 0.19) [Baz-Valle 2022, ref. 105; *moderate*, review of 6-7 RCTs, young trained men]; against these, higher volumes grew the thigh more (9 vs 45 weekly sets: mid-thigh +3.4 % vs +12.5 %) [Schoenfeld 2019, ref. 106; *moderate*, 34 trained men] and 32 weekly sets beat 16 for lower-body muscle thickness [Brigatto 2022, ref. 107; *moderate*, 27 trained men]. Evidence is **mixed** above 12 sets, and no trial tested fewer than 9 vs 10-12 for the quads, so 10 stays a minimum, not an optimum. *Hamstrings:* the whole hamstrings grew +14 % (seated) and +9 % (prone) with 5 sets twice a week, 10 sets a week [Maeo 2021, ref. 76; *moderate*, 20 healthy adults, training status not stated in the abstract]; this shows 10 sets can grow them, not that 10 is the right dose: no hamstring dose-response trial was found (§10 "Not found"). Population: trained men (quads) and healthy adults (hamstrings); transfers to recreational lifters as a floor. The rule does not change.
- **C2 Group not trained:** `sets(G) = 0`. ACSM 2026 primary recommendation: "at least twice weekly, with all major muscle groups being engaged" [ref. 71; *strong*]. Shown before C1 and caps the score (below); a group with 0 is reported by C2 only, not again by C1.
- **C3 Training days:** at least 2 lifting routines. ACSM 2026: "at least twice weekly"; strength "≥2 sessions/wk" [ref. 71; *strong*].
- **C4 Strength only ("Ganar fuerza"):**
  - *Main lift (deterministic):* a counting exercise whose catalogue `movement_pattern` is `squat`, `hinge`, `lunge`, `horizontal_push`, `vertical_push`, `horizontal_pull` or `vertical_pull` (§3 "Main lifts", user design decision E13 Q3). Custom exercises use their own stored pattern; none means not main.
  - *C4a Heavy reps:* every main lift with a rep range has `rep max ≤ 8`. ACSM 2026: strength "enhanced by lifting heavier loads (≥80% one-repetition maximum)" [ref. 71; *strong*]; low (≤ 60 %) vs high loads, 1RM gains "significantly greater in favor of high" [Schoenfeld 2017, ref. 5; *strong*]. The 8 is a *design decision* from the reps-to-failure curve: about 15 reps at 70 % and 5 at 90 % 1RM, with a between-person SD of 2.51 reps at 80 % [Nuzzo 2024, ref. 92; *strong*, 269 studies, 7 289 people, "little influences of sex, age, or training status"], minus the 1-3 reps in reserve of H5; the curve is imprecise per person. No lower bound (singles are heavy loads too). Main lifts without a rep range are not judged.
  - *C4b Main lifts first:* in each routine holding at least one main lift and one other counting exercise, no other counting exercise comes before a main lift (non-counting rows such as stretches or cardio are ignored). Strength gains are "the largest in the exercises performed at the beginning of an exercise session" [Nunes 2021, ref. 21; *strong*, 11 studies]; ACSM 2026 "Beginning of training session" [*strong*].
- **Removed** (no solid evidence or noise for a big-picture review): *rep range vs goal for the other four intentions*: ACSM 2026 lists "low (30% 1RM) to high (100% 1RM) loads" with no change in hypertrophy and Schoenfeld 2017 found similar hypertrophy for low and high loads, so no range is wrong for "Ganar musculatura", "Perder grasa", "Recomposición" or "Mantenimiento"; *lateral raise and knee extension*: ACSM 2026 found "insufficient data" on single-joint vs multijoint training for hypertrophy, whole-quadriceps growth was "comparable" between knee extension and leg press (only the rectus femoris differed, +13.2 % vs +1.1 %) [Kinoshita 2026, ref. 74; *moderate*, 17 untrained adults], and lateral raises grow the side deltoid (+3.3-4.6 % [Larsen 2025, ref. 68; *moderate*]) but no trial compared them with pressing alone (*not found*). H3/H3b are not checked anywhere since the block builder (user 2026-11-04; they stayed in the model-built block generator only). Also out: upper bound of 20, frequency per muscle, per-session volume, movement patterns, variety and every soft item.

**Score 0-10 (*design decision, none*: no study weights the parts of a program, §10):**
- Parts: `pV = mean over the 6 groups of min(sets(G) / 10, 1)`; `pD = 1` if lifting routines ≥ 2, else 0; `pH` = share of main lifts with a rep range that pass C4a; `pO` = share of routines eligible for C4b that pass it.
- Weights: other intentions `V 75, D 25`; "Ganar fuerza" `V 50, D 20, H 15, O 15`. A part with nothing to judge (no main lift with a range; no routine eligible for C4b) is left out and the rest rescale.

#### Folder review: coverage, per-intention checks and the `?` (T-220, fitness-scientist 2026-11-04, Checkpoint E13-H feedback 4; amends "Folder review" above, sources re-opened 2026-11-04, §10)

**(a) What "covered" means. Coverage is per muscle group, never per movement pattern, for every intention.**
- *Covered:* an H1 group G is covered when `sets(G) ≥ 10` (C1); it is *missing* when `sets(G) = 0` (C2); in between it is *low*. Nothing else is "covered" or "missing".
- *A movement pattern is never reported as missing.* ACSM 2026 states, as expert judgement in its limitations, that applying its recommendations to "upper" and "lower" body regions for "push" and "pull" exercises ("four body regions") "is sufficient to target major muscle groups", with horizontal and vertical as an optional split; it also states "The available evidence did not compare distinct body regions or muscle groups" [ref. 71; *weak*: expert judgement inside a guideline; "sufficient", not "necessary"]. No trial defines completeness by patterns (*none*, §3 "Complete routine"), and a single-joint exercise grew the whole quadriceps comparably to a multi-joint one (knee extension +7.1 % vs leg press +4.9 %, "comparable" [Kinoshita 2026, ref. 74; *moderate*, 17 untrained adults]), so a folder can reach every group without one of the patterns. The six-group volume check already covers the four regions (chest and shoulders: upper push; back: upper pull; quads: lower push; hamstrings and glutes: lower pull).
- *Do more sets of exercises already in the folder suffice?* **Yes, for the groups those exercises train, and only for them.** Each working set adds 1 to its primary group and 0.5 to each secondary group (Counting, above; fractional counting predicted growth best [Pelland 2026, ref. 4; *strong*, 67 studies, 2 058 participants, mean age 25]). So 4 more sets of a row add 4 to back and 2 to biceps; more squat sets add nothing to hamstrings (squats left the hamstrings and rectus femoris unchanged [Kubo 2019, ref. 73; *moderate*, 17 young men]). Whether reaching 10 only through secondary (half) sets is as good as direct work was not tested (*not found*); the review accepts it (it is Pelland's counting).
- *What the app says (ux-reviewer writes the Spanish):* for a low or missing group, the row names the group, its sets and the minimum, and what adds to it: "{group}: {sets} of at least 10 sets a week. Exercises where {group} is the main muscle count 1 per set; exercises where it helps count half." plus one static example line per group, taken from the filing rules of §3 (no equipment is read, so the examples are generic, never a proposal to pick a named exercise): chest "presses on a bench, dips, flyes"; back "rows, pull-downs, pull-ups"; shoulders "overhead presses, lateral raises (bench presses count half)"; quads "squats, lunges, leg press, leg extension"; hamstrings "Romanian deadlift, leg curl (hip thrusts count half)"; glutes "hip thrust, glute bridge (squats and lunges count half)". The proposal of `group_low` becomes "Add {ceil(10 − sets)} sets of exercises where {group} is the main muscle (or twice as many where it helps)." Never the words "patrón" or "patrón de movimiento" in the review.

**(b) Per-muscle figures (confirmed; the review shows them for every group).**

Every group row shows its sets and the minimum, met or not, e.g. "12 series a la semana (se recomiendan al menos 10)". Ten is a **minimum, not a target**: 12 does not "exceed the recommendation" and gets no warning.

### Block builder (T-219, fitness-scientist 2026-11-04; **user decision 2026-11-04**: the block reuses the perfect-routine concept and the folder-review score, with no model call; replaces options A/B/C of the earlier evaluation; nothing changes the built flow until a task implements it)

**What it superseded (removed in T-224):** for block creation, the model-built block of §1 (old "Division of work"), §3 "Complete routine" (gate H1-H7, soft and free lists, "Starting points", "Model input"), the `block_splits` / `plan_block` / `folder_review purpose: block` model calls (§11), and the discomfort exclusion of §7 and §12.4 (user 2026-11-04: discomfort is not an input of the builder). H3 (lateral raise) and H3b (knee extension) are no special case (user 2026-11-04). Sources: §10 "Re-opened for the block builder" and "Same-muscle exercises in one routine".

**Flow (user):** (1) pick a split for the days per week, then, per day, a routine type (each day shows its alternatives, one marked "Recomendado"); (2) the builder shows each routine's muscle sections with sets, reps, RPE and rest already computed; (3) the user picks an exercise per slot; each pick raises the score; (4) at 100 % (every required slot filled) "Guardar bloque" is enabled. **(a) Routine types and splits.**
- *Routine types (each holds H1 groups only; arms, calves, core and adductors go in "Extra", (d)):* **Cuerpo completo** (quads, chest, back, hamstrings, shoulders, glutes) · **Torso** (chest, back, shoulders) · **Pierna** (quads, hamstrings, glutes) · **Empuje** (chest, shoulders, quads) · **Tirón** (back, hamstrings, glutes). Empuje/Tirón follows ACSM 2026's "upper"/"lower" × "push"/"pull" regions [ref. 71; *weak*: expert judgement in the limitations], so both types hold 3 groups and sessions stay balanced; the classic push-pull-legs is not offered (its pull day holds one H1 group; *design decision*). Section order inside a routine is the order listed (*design decision, none*: order does not change hypertrophy, ES = 0.03, p = 0.862 [Nunes 2021, ref. 21; *strong*, 11 studies]).
- *Splits (first = "Recomendado"; the reason is the one shown):*

| Days | Recommended | Alternatives | Why the recommended one (shown) |
|---|---|---|---|
| 1 | Cuerpo completo ×1 | none (any other type leaves groups with no day) | The only routine that trains every muscle in one day (Q-B1, below) |
| 2 | Cuerpo completo ×2 | Torso / Pierna · Empuje / Tirón | The only one that trains every muscle twice a week |
| 3 | Cuerpo completo ×3 | Torso / Pierna / Cuerpo completo · Empuje / Tirón / Cuerpo completo | Every muscle 3 times, sessions of similar length |
| 4 | Torso / Pierna / Torso / Pierna | Empuje / Tirón ×2 · Cuerpo completo ×4 | Every muscle twice, 3 exercises per session instead of 6 |
| 5 | Torso / Pierna / Torso / Pierna / Cuerpo completo | Empuje / Tirón ×2 + Cuerpo completo · Cuerpo completo ×5 | Every muscle 3 times |
| 6 | Torso / Pierna ×3 | Empuje / Tirón ×3 | Every muscle 3 times, short sessions |

  Evidence: split and full-body routines gave similar strength and growth "when volume is equated", so people "are free to confidently select a resistance training routine based on their personal preferences" [Ramos-Campo 2024, ref. 108; *moderate-strong*, 14 studies, 392 healthy adults]; frequency shows "compatibility with negligible effects" for hypertrophy while "strength gains increase with increasing frequency" with diminishing returns [Pelland 2026, ref. 4; *strong*, 67 studies, 2 058 participants, 79.1 % men, mean age 25]; strength needs "≥2 sessions/wk" and every major group "at least twice weekly" [ACSM 2026, ref. 71; *strong*]. Hence the recommended split trains each group at least twice; which of the valid splits is first is a *design decision* (no trial ranks them). Cuerpo completo ×6 is not offered: 10 sets over 6 sessions leaves sessions with 1 set per exercise, below ACSM's "at least two sets per exercise" [ref. 71].

- *Split names and day types (Checkpoint E13-K feedback, fitness-scientist 2026-11-05; science settled; Q-B6 decided by the user 2026-11-05: named splits, day types limited to the split's family; Q-B7 decided: no suggestions):*
  - *What the evidence says:* split and full-body routines give similar strength and growth "when volume is equated" [Ramos-Campo 2024, ref. 108; *moderate-strong*, 14 studies, 392 healthy adults; re-opened 2026-11-05]; single trials disagree in direction (total body favoured isokinetic bench strength, p = 0.015, a split favoured vastus lateralis thickness, p = 0.037 [Bartolomei 2021, ref. 113; *moderate*, 21 trained men]; total body 3×/week grew the forearm flexors more than a once-a-week body-part split [Schoenfeld 2015, ref. 114; *moderate*, 20 trained men]). ACSM 2026: hypertrophy not influenced by "low (1 d/wk) versus high (>5 d/wk) frequency when total volume was equated", yet the primary recommendation stays "at least twice weekly, with all major muscle groups being engaged", and "upper"/"lower" × "push"/"pull" regions suffice to target the major groups [ref. 71; *strong*; the regions sentence is expert judgement; re-opened 2026-11-05]. No trial ranks named splits (push-pull-legs, Arnold, "bro split", upper-strength/upper-hypertrophy variants) for the same days (*not found*). So **which day types belong to a split is a naming and coherence decision, not a science one**; the only evidence-backed constraints stay those already in (a): every H1 group on at least 1 day (C2), at least 2 days per group recommended (ACSM), and none at 6 days (fewer than 2 sets a session).
  - *Split names (Spanish UI; ux-reviewer finalises):* the split card shows a name and, below it, the days: **"Cuerpo completo"** (days "Cuerpo completo"); **"Torso-Pierna"** (days "Torso", "Pierna"); **"Torso-Pierna + Cuerpo completo"** (3 and 5 days); **"Empuje-Tirón"** (and "+ Cuerpo completo" at 3 and 5 days). Because this app's "Empuje"/"Tirón" hold legs too (Empuje: pecho, hombros, cuádriceps; Tirón: espalda, isquiotibiales, glúteos; ACSM's regions), while in common practice in leading apps "Empuje" means chest, shoulders and triceps, every day type always shows its groups under its name (e.g. "Empuje · Pecho, hombros y cuádriceps").
  - *Allowed day types per split (proposed rule):* a day may take only the types of its split's family, plus "Cuerpo completo" on the day that already is one; other types are **hidden**, not disabled. Torso-Pierna: Torso, Pierna (and Cuerpo completo on its full-body day at 3 and 5 days). Empuje-Tirón: Empuje, Tirón (same). Cuerpo completo: Cuerpo completo only, so no per-day choice is shown. The existing disabled-with-reason rule ("Dejaría el pecho sin entrenar") still applies inside the family (e.g. 4-day Torso-Pierna with three Torso days). Mixing families (an Empuje day in a Torso-Pierna week) is not offered: it gives no evidence-backed benefit and makes the split's name false.
  - *Not offered (unchanged or new, all design decisions):* classic push-pull-legs (pull day holds only back among H1 groups, (a)); Arnold split (its shoulders-and-arms day holds one H1 group); body-part "bro split" (each group 1 day a week, below ACSM's "at least twice weekly"; Schoenfeld 2015 found a "potentially superior hypertrophic benefit" with higher frequency); "Torso fuerza / Torso hipertrofia" variants (ACSM 2026: periodization without consistent effect [ref. 71]; low to high loads give similar hypertrophy [ref. 5]; "Ganar fuerza" already gets heavy main slots).
- *Arms, core, calves and forearms (Checkpoint E13-K feedback, 2026-11-05):* **no required slot is correct.** Adding elbow-flexion and extension work to presses and pulldowns gave "no additional benefits" in untrained men [Gentil 2013, ref. 94; *moderate*], "no significant difference in any variable" in trained men [de França 2015, ref. 79; *moderate*], and no additional 10RM or arm-circumference benefit in untrained men and trained women [Barbalho 2018, refs 115-116; *moderate*; the trained-women paper carries a 2026 expression of concern]. Evidence is **mixed** once the comparison is exercise against exercise: a curl grew the elbow flexors 11.06 % vs 5.16 % with a row on the other arm [Mannarino 2021, ref. 117; *moderate*, 10 untrained men, within-subject]; the triceps long head grew more with single-joint work [Brandão 2020, ref. 112; Maeo 2023, ref. 77]; ACSM 2026 calls single- vs multi-joint for hypertrophy "insufficient data" [ref. 71]. Core and forearm growth from compound lifts alone, or a minimum dose for them: *not found* (searched 2026-11-05; no training trial measuring rectus abdominis size after compound-only training was found). Hence arms, calves, core and forearms stay outside H1 and the score; the builder **offers** them as optional slots in "Extra (opcional)" ((d); 2 sets, accessory values, never in the score). *Proposed (Q-B7), **declined by the user 2026-11-05: no suggestions, "Extra (opcional)" stays as is**:* would have shown them as one-tap suggestions by day type: Torso and Empuje → "Tríceps"; Torso and Tirón → "Bíceps"; Pierna, Tirón and Empuje → "Gemelos"; every type → "Core"; "Antebrazos" only through "Añadir ejercicio" (no evidence for a suggestion). The `?` says why (ux-reviewer writes it): "Bíceps y tríceps ya trabajan en los ejercicios de empuje y tirón; añadir ejercicios para ellos es opcional." Population: untrained and trained young adults, mostly men; transfers to recreational lifters. **Journey stage (§12):** plan (first block, "Bloque nuevo"); no other stage gains a rule.
- *Aesthetics and proportion for "Ganar musculatura" (Checkpoint E13-K feedback 2, fitness-scientist 2026-11-05; sources opened 2026-11-05, §10):* **no change to the required groups, the minimum of 10 or the score.** ACSM 2026 names only "major muscle groups", states "The available evidence did not compare distinct body regions or muscle groups" and does not discuss appearance or physique; it asks programs to be "individualized" to goals [ref. 71; *strong* for the minimum, *none* for proportion]. No trial of training for symmetry or proportion, or of a per-muscle dose for visible size (arms, calves, upper chest, side delts), was found (*not found*). Regional findings exist but change no check, because coverage is per group and each finding is already reachable by the user's pick: the bench press grew the medial deltoid less than the other pressing muscles ("higher increases in CSA of all muscles compared to medial deltoid", P ≤ 0.016 [Lanza 2024, ref. 93; *moderate*, 24 men]) and lateral raises are a valid "Hombros" pick; the incline press grew the upper pectoral more than the flat press (+0.62 cm vs flat, p = 0.003; middle and lower sites similar [Chaves 2020, ref. 119; *moderate*, 30 untrained young men with thickness data, once a week]) and any incline press is a valid "Pecho" pick; standing calf raises grew the gastrocnemius more than seated ones (lateral +12.4 % vs +1.7 %, medial +9.2 % vs +0.6 %, soleus similar [Kinoshita 2023, ref. 118; *moderate*, 14 untrained adults, within-subject]), relevant only if the user adds calves in "Extra". More size for a chosen group comes from "Priorizar" at the block review (§12.4: +2 weekly sets), not from a new check. Population: untrained and trained young adults; transfers to recreational lifters. **Journey stage:** plan and block review; no new rule.
- *Grip strength and forearms (Checkpoint E13-K feedback 2, 2026-11-05):* **never required, never in H1 or the score, no app-initiated suggestion** (no evidence-backed trigger or dose). Evidence: lower grip strength is **associated** with higher mortality (per 5 kg lower, HR 1.16, 1.12-1.20 [Wu 2017, ref. 120; *strong* for the association, 42 cohorts, 3 002 203 people]; HR 1.16, 1.13-1.20, 139 691 adults in 17 countries [Leong 2015, ref. 121; observational]), but whether raising grip strength lowers mortality is untested (*none* for a training rule); general exercise training raised handgrip strength only slightly in older adults (SMD 0.28, 0.13-0.44 [Labott 2019, ref. 122; *strong*, 24 trials, 3 018 adults, mean age 73]). Lifting straps, acutely: more reps at 80 % 1RM and less grip-strength loss [Trahey 2023, ref. 124; *moderate-weak*, 10 trained women], less grip fatigue and lower RPE [Jukic 2021, ref. 123; 16 men], 20-28 % more force at 90 % 1RM [Coswig 2015, ref. 125; 11 trained adults]; no long-term trial of straps or of grip work for deadlift or pull-up progress was found (*not found*). So the app neither recommends nor forbids straps (equipment, outside the catalogue logic) and adds no grip note. A user who wants grip work adds it through "Extra (opcional)" › "Añadir ejercicio" at the Extra default of 2 sets (ACSM "at least two sets per exercise" [ref. 71]; no grip-specific dose was found). Catalogue (checked 2026-11-05, migrations): group "Antebrazos", weight × reps: `wrist-curl`, `dumbbell-wrist-curl`, `barbell-wrist-curl`, `ez-bar-wrist-curl`, `cable-wrist-curl`, `kettlebell-wrist-curl`, `db-reverse-wrist-curl`, `kettlebell-reverse-wrist-curl`, `wrist-roller`; timed: `dead-hang`, `ring-dead-hang` (duration), `plate-pinch`, `suitcase-carry` (weight × duration); stretch `kneeling-wrist-stretch`; `dumbbell-farmers-walk` and `kettlebell-farmers-walk` are filed under "Cuerpo completo" (weight × duration). Population: cohorts of community-dwelling adults; older adults for the training effect; small trained samples for straps. Transfers to recreational lifters only as background, not as a prescription. **Journey stage:** none gains a rule.
- *"Rutina Weider" (Checkpoint E13-K feedback 2, 2026-11-05):* no program called "Welder" was found (searched 2026-11-05: only welding-trade fitness pages); in Spanish gyms "rutina Weider" names the body-part split (one or two muscle groups per day, each trained once a week; common practice, Spanish fitness media, not a source). **(b) Per-section prescription (computed before any pick; every figure a *design decision* inside the cited rule unless sourced).**
- *Weekly sets per group:* **10** for each H1 group, every intention and experience level (ACSM 2026 "≥10 sets/wk", "training experience had a minimal impact" [ref. 71; *strong*]; 10 is the minimum, not an optimum: dose-response is positive with diminishing returns [ref. 4]; more sets come from "Priorizar" at the block review, §12.4). Counted at 1 per set of the slot's own group (secondaries are ignored by the builder and added by the review, (c)).
- *Sets per session:* with `f(G)` = days whose type holds G, `s = floor(10 / f)` per session, the remainder +1 to the earliest days of the week. Example 4 days Torso/Pierna: 5 + 5; 6 days: 4 + 3 + 3.
- *Slots per section:* non-strength intentions `ceil(s / 5)` slots, sets split as evenly as possible, larger first (s = 10, two-day Torso/Pierna: 5 + 5). "Ganar fuerza": a **main slot** with `s` sets when s ≤ 4, else 3 sets and the rest `r = s − 3` in `ceil(r / 5)` **accessory slots** (s = 5: 3 + 2; s = 10: 3 + 4 + 3). ACSM 2026: strength "2–3 sets/session", "diminishing returns beyond ~2–3 sets/exercise", "at least two sets per exercise" [ref. 71; *strong*]; the 5-set cap per slot is a *design decision* (fewer exercises, less setup time).
- *Values per slot:*

| Intention | Slot | Reps | Target RPE | Rest | Order |
|---|---|---|---|---|---|
| Ganar musculatura · Perder grasa · Recomposición · Mantenimiento | every slot | 8-12 | 8 | 120 s | section order |
| Ganar fuerza | main | 4-6 | 8 | 180 s | all main slots first, then accessories |
| Ganar fuerza | accessory | 6-8 | 8 | 120 s | after the main slots |

  Sources: hypertrophy was "similar" with low (≤ 60 %) and high (> 60 %) loads while 1RM favoured high loads [Schoenfeld 2017, ref. 5; *strong*]; ACSM 2026: "low (30% 1RM) to high (100% 1RM) loads", strength "≥80% 1RM", exercise "at the beginning of training sessions", "a target of 2–3 repetitions in reserve" with "insufficient evidence to quantify exact RIR" [ref. 71; *strong*]. RPE 8 = 2 reps in reserve, inside both. The ranges come from the reps-to-failure curve, "~5 and ~15 repetitions" at 90 % and 70 % 1RM, SD 2.51 reps at 80 % [Nuzzo 2024, ref. 92; *strong*, "little influences of sex, age, or training status"]: 4-6 at 2 in reserve is about 6-8 to failure (above 80 %); 8-12 sits inside H4's 6-20 with room for double progression; every strength slot tops out at 8 or fewer, so C4a passes whatever the user picks. Rest: 120 s is the only value inside both §3 bounds (main lifts 2-3 min, isolation 1-2 min), so any pick is valid; hypertrophy shows "a small hypertrophic benefit" beyond 60 s and no "appreciable differences" beyond 90 s [Singer 2024, ref. 20; *moderate*, 9 studies, mostly young untrained adults]; 3 min beat 1 min for thigh growth and 1RM [Schoenfeld 2016, ref. 19; *moderate*, 21 young trained men]; strength needs "> 2 min" in trained people, "60-120 s" is enough in untrained [Grgic 2018, ref. 18; *moderate*, systematic review]; ACSM 2026 found strength unaffected by "short (<1 min) versus long (>1 min)" rests and "insufficient data" for hypertrophy [ref. 71]. Evidence on rest is **mixed**; 180 s on strength main slots follows Grgic and Schoenfeld for trained lifters.
- *Session length (time fit, the existing `routineSeconds` estimate, `04` §9.6, *design decision, none*):* each routine's time is computed from the slot values before any pick (setup 30 s per slot). If it exceeds "Duración de la sesión", apply in order until it fits: (1) strength main rest 180 → 120 s (Grgic 2018: 60-120 s enough for untrained); (2) non-strength only: supersets of slots with equal sets, pairs fixed by type (Cuerpo completo: chest + back, quads + hamstrings, shoulders + glutes; Torso: chest + back; Pierna: quads + hamstrings; Empuje: chest + quads; Tirón: back + hamstrings): "shorter session duration" (SMD 1.74) with similar strength (0.10) and hypertrophy (−0.05), and similar-movement pairs "led to less volume load" (−1.08) [Zhang 2025, ref. 81; *strong*, 19 studies, 313 participants], so no push + push pair; (3) remove 1 set from the slot with the most sets (accessory before main, later in the session first), never below 2 per slot, and show "Por debajo de lo recomendado" (existing note). If it still does not fit with every slot at 2 sets (Q-B2, decided: user accepted the recommendation 2026-11-04), "Continuar" is disabled with "No cabe en {min} min: sube la duración, los días o cambia la división." (*design decision*: below ACSM's "at least two sets per exercise" [ref. 71] the builder does not cut further; the user changes a preference or the split). No supersets for "Ganar fuerza" (a main-pattern exercise can land in any slot, and §3 never supersets a main lift for strength); no drop sets (they need an isolation exercise, unknown before the pick). Phase, age, sex and experience do not change any value (§2; ACSM 2026 "evidence-based across all ages").

**(c) The score (reuses the folder-review score, §3 "Folder review"; *design decision, none*).**
- `pV = mean over the 6 H1 groups of min(filled(G) / target(G), 1)`, with `target(G)` = the sets of G's required slots in the week (10, or fewer after time-fit step 3) and `filled(G)` = the sets of its filled slots. `pD` = share of training days with at least one filled slot. `pH` and `pO` have nothing to judge (every strength slot is ≤ 8 reps and main slots come first, by construction), so they are left out and the weights rescale, as the review already does: other intentions `V 75, D 25`; "Ganar fuerza" `V 50, D 20` → 71.4 / 28.6. Shown as `round(100 × Σ w p / Σ w)` %.
- **Changes against the review:** (1) only the slot's own group counts, at 1 (secondaries would let a group reach its target before its slots are filled); (2) the target is the prescribed sets, not a fixed 10; (3) `pD` is a share of days, not "≥ 2 lifting routines"; (4) no 6.0 cap (it would hold the number at 60 % and then jump). Result: every pick of a required slot strictly raises the score, and **100 % ⇔ every required slot is filled**. Extra slots and cardio do not count.
- **At save** the saved folder gets the normal review (§3 "Folder review", T-220): with 2+ days and no time-fit cut it scores **10,0** (each group's primary sets alone reach 10; C3, C4a and C4b hold by construction), an invariant test. After a time-fit cut, the review shows the low groups as usual.
- For "Ganar fuerza", at save the app moves main-pattern exercises of accessory slots before the non-main ones in the same routine, keeping slot order otherwise, so C4b holds (Nunes 2021: strength gains "the largest in the exercises performed at the beginning of an exercise session").

**(d) Freedom per slot.**
- *Allowed:* any catalogue or custom exercise whose **primary group is the section's group**, that counts for H1 (§3 "What H1 counts") and is inside the user's saved equipment. Nothing else filters the list: **discomfort is not an input** (user 2026-11-04; §7 keeps acting on progression only), and no exercise of the group is required, preferred or excluded by its movement, including lateral raises and knee extensions (user 2026-11-04; H3/H3b are not rules here). Any equipment the user has: ACSM 2026 found equipment type without consistent effect [ref. 71]. Coverage is per group, never per pattern (§3 "Folder review: coverage"), so no pattern is required, except the strength **main slot**, which accepts only main-lift patterns (squat, hinge, lunge, horizontal or vertical push or pull, §3 "Main lifts"); if the user's equipment offers none for that group, the slot becomes an accessory slot (6-8, 120 s) with a one-line reason.
- *Picker order:* favourites, then most sessions in the last 8 weeks, then the equipment order (T-179), then name; every eligible exercise, no cap, no discomfort marker, no hidden count.
- *Repeats:* never the same exercise twice in one routine (existing invariant: the exercise already picked in that routine is shown disabled in the other slots); the same exercise on different days is allowed and changes nothing in the score. Both are *design decisions*: no trial tested repeating an exercise inside a session (§10 "Same-muscle exercises in one routine"), and two slots of one exercise in a routine are simply more sets of it. Varying exercises across sessions grew every measured site while fixed exercises missed two [Costa 2021, ref. 111; *moderate*, 22 detrained men], so different exercises across days are reasonable, but not required (one small trial, other population).
- *Two different exercises for the same muscle, or for overlapping muscles, in one routine* (e.g. two presses, or lateral raises and chest flyes): allowed, no rule, no note. Combining a multi-joint and a single-joint exercise grew different heads of the same muscle (triceps long head more with the single-joint, lateral head more with the multi-joint) [Brandão 2020, ref. 112; *moderate*, 43 young men]; systematic variation helps regional growth while "different exercises that provide a redundant stimulus" or excessive rotation may not [Kassiano 2022, ref. 72; *moderate*, 8 studies, 241 young men; the "redundant" warning is the authors' interpretation, not a tested comparison]; no trial compared two similar exercises with one exercise at equal sets (*not found*). Lateral raises and flyes have different primary groups (shoulders, chest), so each counts for its own section; nothing was found against combining them.
- *Swap and clear:* any filled slot can be changed or cleared before saving; after saving the routines are normal routines (editor, T-179 swaps, "Revisar carpeta" re-scores).
- *Extra:* each routine has an "Extra (opcional)" section; "Añadir ejercicio" takes any eligible exercise of any group (arms, calves, core, adductors, or more of an H1 group) at 2 sets with the routine's accessory values (non-strength: 8-12, RPE 8, 120 s); extras never change the score; when they push the routine over the session length the time line says by how much (never blocks). 2 sets = ACSM's "at least two sets per exercise".
- *Not editable in the builder:* sets, reps, RPE, rest and order (they are what makes 100 % mean a complete week); editable after saving.

Planned reps = bottom of the range. Never converted from another exercise or rep range (no conversion verified, §3 "Routine tools"). Progression afterwards: §3 "Progression".
- *Cardio:* unchanged server rules (§3 "Cardio prescription"): weekly minutes by intention, split evenly over the routines in 5-minute units, last in each routine, default exercise by the cardio ranking. The builder shows it as a fixed last section "Cardio" pre-filled, swappable to any cardio inside the equipment; it is outside the score and the session length.
- *Q1, Q2:* settled by the user (no model; the free text no longer reaches the block: preference is expressed by the picks).
- *Q4 ("not a template"):* settled: the app computes only the values; the user picks every exercise, so two users with the same split get different blocks.
- *Q3 ("Desde una carpeta"):* decided by the user (Q-B3, 2026-11-04): the same 100 % as the builder, with a fix step on a copy; see (h). *Superseded:* the model change proposals and the earlier recommendation "safety gate only, review as notes".

Discomfort is not an input (user 2026-11-04): inside the saved block it keeps acting as today (§7: load increases blocked while open, the level 4-5 mid-block swap offer, the graded return and the 14-day health note). **(h) "Desde una carpeta" (Q-B3, decided by the user 2026-11-04).**
- *What is checked:* the folder's own content (routines in folder order; per exercise: key or custom id, working sets, rep range, as the folder review reads them) against the **same 100 %** as the builder, read as the folder review at **10,0** with the counting of §3 "Folder review" (fractional: primary 1, secondary 0.5; only exercises that count for H1): C2 and C1 (every H1 group ≥ 10 sets), C3 (≥ 2 lifting routines; with "Días por semana" = 1, a one-routine folder is judged as the 1-day split of Q-B1: C3 is shown as unmet and the save needs every other check met, so the % tops at 75, 80 for "Ganar fuerza"), and for "Ganar fuerza" C4a and C4b. Same gate as (g): every exercise inside the equipment, no repeat in a routine. A builder-made block scores 10,0 by construction ((c)), so both starting points end at the same bar. Why the review's counting and not the builder's primary-only count: the folder has no slots, and fractional counting is the method that predicted growth best [Pelland 2026, ref. 4; *strong*]; the builder counts primaries only for one UX reason (each pick must raise the score), which a finished folder does not need. Not checked (as the review): rep ranges for the four non-strength intentions, the 20-set cap, session length, RPE, rest, discomfort.
- *Days (Q-B5, decided by the user 2026-11-04):* the block has one training day per lifting routine of the folder (a routine with no lifting exercise is left out of the block, named in a note, and does not count as a day). If that number differs from "Días por semana", the block is **refused** until the two match: the user changes the preference or the folder (one line says which numbers differ). One source of truth for the days.
- *When the folder reaches it:* "Guardar bloque" saves it as is.
- *When it does not (fix):* the folder opens in the builder screen, on a copy: each routine shows its own exercises under the builder's group sections plus the review's rows (missing or low groups with the sets still needed, `one_day`, `strength_reps`, `strength_order`), and the live % (= 10 × review score). The user may: **add** an exercise to any routine in the section of a missing or low group (picker as (d), with the builder's values for the intention: non-strength 8-12, RPE 8, 120 s; "Ganar fuerza" 6-8, RPE 8, 120 s, or 4-6, RPE 8, 180 s when it is the routine's only main lift for that group; sets = what the group still needs, capped at 5 per exercise, at least 2 (ACSM 2026 "at least two sets per exercise" [ref. 71])), and remove what they added; **swap** any exercise for another of the same primary group inside the equipment (keeps its sets, reps, RPE and rest, as the T-179 swap; this also fixes an exercise outside the equipment or a repeat); and, only for `strength_reps`, apply the review's proposal "Cambiar a {min(min, 6)}-8 repeticiones" on that main lift. `strength_order` is fixed at save as in the builder (main lifts moved first, other order kept). Nothing else is editable here (no deleting the user's exercises, no set, rest or RPE edits, no new routine): those stay in the routine editor of the original or the new folder after saving. A one-routine folder with 2 or more days a week cannot pass C3 here: the line says "Añade una segunda rutina a la carpeta o empieza desde cero."

### Training rules

- **Frequency (amended by T-202):** at least 2 lifting sessions a week when the user has 2 or more days (H2); per-muscle frequency is soft ("Complete routine"); with one day, one full-body session. *Superseded:* "each muscle group at least twice a week" as a hard rule.
- **Volume:** starting point of 10 weekly sets per muscle group, inside H1's 10-20. Dose-response is positive [Schoenfeld, Ogborn, Krieger 2017], with diminishing returns at higher volumes, much more pronounced for strength than for hypertrophy [Pelland et al. 2026].
- **Intensity (amended by T-219):** in a block, rep ranges are the builder's per-slot values (§3 "Block builder" (b): 8-12, or 4-6 / 6-8 for "Ganar fuerza"); routines the user edits keep any range. *Superseded (T-202):* "rep ranges per H4, chosen by the model". *Superseded:* the fixed bands "main 6-10, isolation 10-15" and the mandatory strength undulation "3-5 / 5-6 / 6-8" (now an option, below).
- **Proximity to failure:** 1-3 reps in reserve on working sets, prescribed as a target RPE of 7-9 (H5). Training to momentary failure shows no hypertrophy advantage over stopping short of it, and set failure only a trivial one [Refalo et al. 2023]. Reps in reserve are derived from the logged RPE (RIR = 10 − RPE); there is no separate RIR field (ADR-76).
- **Progression:** double progression. Work inside the rep range; when every working set reaches the top of the range at RPE 8 or less, raise the load to the next available increment. ACSM: a 2-10 % load increase when the individual can perform the current workload "for one to two repetitions over the desired number" [ACSM 2009; *strong*, position stand, expert-based]; double progression is that rule applied to a rep range. With light dumbbells the next available increment can exceed 10 % (equipment limit, *design decision*: still the next increment). **Applied automatically** to the next session, with its reason and "Deshacer" (§1). **Where it lives and who computes it:** inside an accepted block, when a session completes, the **server** computes the decision and the step (the increment from the user's plates and handle, `04` §4.9, so the plate settings must be readable on the server) and writes the new weight to the planned sets of the block's routines that hold that exercise with the same rep range (a routine serves every week, so the new planned weight is the baseline from the next session on; ADR-50 planned values); on a raise the planned reps go to the bottom of the range. If the user's "Actualizar automáticamente" (ADR-70) is on, it runs first and the coach's change is applied on top. "Deshacer" restores the planned weight and reps from before the coach's write. Outside a block it stays a live-session suggestion. Example reason: "Subimos a 62,5 kg: la última vez hiciste 12 repeticiones en todas las series."
- **Failed sessions:** when most working sets miss the bottom of the range in two consecutive sessions of the exercise, lower the load 5 %, rounded to the available increment. *Design decision.* Applied automatically, like the increase.
- **Deload-week sessions (T-227, fitness-scientist 2026-11-05):** a session in a deload week (§3 "Deload") counts for neither rule: it never raises the load (the deload keeps the weights by definition) and never counts as a failed session; it is skipped, not a reset, so "two consecutive sessions" means two consecutive non-deload sessions of the exercise. *Design decision, grade none:* no trial tests progression decisions made inside a deload; it follows from the deload's own definition (same weights, fewer sets) and from the e1RM review already excluding the deload week (§3 "Deload").
- **Rest between sets:** 2-3 min on main multi-joint lifts, 1-2 min on isolation exercises. Trained lifters need more than 2 min to maximise strength [Grgic et al. 2018]; 3 min beat 1 min for strength and thigh hypertrophy [Schoenfeld et al. 2016]; for hypertrophy alone the difference is small [Singer et al. 2024]. The builder writes 120 s, or 180 s on strength main slots, inside these bounds (§3 "Block builder" (b)). *Superseded:* "the model writes rests inside these bounds; the checker enforces them (H6)".
- **Exercise order:** for "Ganar fuerza" the priority multi-joint lifts go first in the session (H7); strength improves most on exercises done early, hypertrophy is similar in any order [Nunes et al. 2021]. For other intentions the order is free.
- **Periodization (amended by T-202; T-219):** undulating loads within the week (heavy, medium, light) are not prescribed by the builder (one range per slot); the user may set them in the routine editor. *Superseded:* "an option the model may use for experienced 'Ganar fuerza' users". Undulating beat linear for 1RM (ES 0.31; trained 0.61, CI touching 0; untrained 0.06, n.s.) with no hypertrophy difference (0.05) [Moesgaard et al. 2022; *strong*, mixed by training status]; ACSM 2026: periodization "not significantly superior" to non-periodized programs. *Superseded:* mandatory undulation for "Ganar fuerza" and "other intentions keep one rep range per exercise".
- **Range of motion:** full range by default; differences against partial range are small [Pallarés et al. 2021; Wolf et al. 2023]. A technique note, not a computed rule.
- **Cardio:** concurrent aerobic training does not compromise whole-muscle hypertrophy (SMD -0.01) or maximal strength (SMD -0.06); only explosive strength is attenuated (SMD -0.28), more when both are in the same session than 3 h or more apart; training status, cycling vs running, more or fewer than 5 sessions a week and age did not moderate it [Schumann et al. 2022, 43 studies; *strong*]. At fibre level there may be a small negative effect (SMD -0.23), possibly only with running [Lundberg et al. 2022; *moderate, preliminary*]. So the coach does not reduce cardio or steps for strength or muscle goals.
- **Cardio prescription (proposed, ADR-85; every source re-checked online on 2026-11-01, §10 29-50; E13 Q23-Q29 resolved 2026-11-01: Q27 and the placement inside the routine by the user, the rest by the fitness-scientist on this evidence).** The coach prescribes cardio as a trainer would. Every figure is computed by the server's rules, never by the model (§1). Grades: *strong* = guideline or meta-analysis of trials; *moderate* = single trial or review; *weak* = observational or expert opinion.
  - *Dose (weekly minutes of moderate aerobic work):* the adult guideline is 150-300 min moderate or 75-150 min vigorous per week (so one vigorous minute counts as two moderate), and bouts of any duration count [WHO 2020, Bull et al.: strong recommendation, moderate-certainty evidence; ACSM 2011, Garber et al.: ≥ 30 min on ≥ 5 days, ≥ 150 min]. More than 300 min may add benefit (WHO, conditional). **"Perder grasa": band 150-300**: aerobic exercise lowers weight 0.52 kg, waist 0.56 cm and body fat 0.37 % per 30 min a week, linearly up to 300 min, with clinically important waist and fat changes from about 150 min [Jayedi et al. 2024, 116 RCTs; *strong*, but in adults with overweight or obesity (mean age 46) and supervised aerobic training of 8 weeks or more]; 150-250 min gives only a modest loss and adds to the diet only with moderate (not severe) restriction, more than 250 min a clinically significant one [Donnelly et al. 2009, ACSM; *strong*]. **Every other intention: 150**, the guideline minimum: it is there for health, not for the goal; it does not compromise hypertrophy or maximal strength (above). An older meta-analysis links more frequent and longer endurance work to smaller strength and hypertrophy gains (r -0.26 to -0.75) [Wilson et al. 2012; *moderate*, correlational], a frequency effect the newer one did not find [Schumann 2022]: evidence is mixed, so the non-fat-loss intentions stay at the minimum. **Resolved (E13 Q23):** the coach proposes 150 for every intention, inside the band 150-300 for "Perder grasa" (the diet carries the deficit, Donnelly 2009; the lowest dose with clinically important fat and waist change, Jayedi 2024); the user edits it freely. The default is a *design decision*.
  - *Intensity:* moderate = the user can still talk comfortably; the last talk-test stage with comfortable speech tracks the ventilatory threshold [Foster et al. 2008, healthy young adults; *moderate*] and is proposed for aerobic prescription [Vieira et al. 2022, systematic review in cardiopulmonary patients; *moderate*, other population]. Shown as the pace word "suave" with that explanation; no heart-rate zones (no verified source for a zone formula here).
  - *Type:* continuous moderate work only in this pass. Intervals give similar fat loss (SMD -0.82 vs -0.85 in running programmes) with about 40 % less time [Wewege et al. 2017; *strong*, adults 18-45 with overweight or obesity], but intervals added to lifting reduce lower-body strength gains (ES -0.248) [Sabag et al. 2018; *strong*, small effect]; so intervals are not prescribed (E13 Q28, resolved: continuous "suave" only, no heart-rate zones). Cycling vs running: *mixed* (running interfered more in Wilson 2012 and, for type I fibres, in Lundberg 2022; no difference in Schumann 2022; in Wewege 2017 cycling programmes showed no fat loss). So "low-impact machines first" is a *design decision* (joint comfort, availability), not an evidence rule. The exercise comes from the catalogue's `cardio` pattern, filtered by place and equipment like any other slot; walking needs no equipment.

- **(1) Progression inside the block (feature 1; applies on its own with "Deshacer"):** the double-progression and 5 % drop rules of §3 "Progression" and "Failed sessions" are unchanged; E14 only moves them from the live-session suggestion to the server write already specified there. ## 4. Energy and macros

- **Calorie floor:** a plan never goes below 1200 kcal (women) / 1500 kcal (men) (ADR-25).
- **Protein:** at least 1.6 g/kg, plateau around 2.2 g/kg [Morton et al. 2018]. In a deficit with high lean mass, the upper end: 2.3-3.1 g/kg of fat-free mass [Helms, Zinn, Rowlands, Brown 2014]. Shown as guidance, not a meal plan: about 0.4 g/kg per meal over at least 4 meals [Schoenfeld, Aragon 2018].
- **Fat:** at least 20 % of calories; usual range 20-35 %; below 20 % gives no performance benefit [Rodriguez, DiMarco, Langley 2009, ADA/DC/ACSM position]. (The 2016 update [Thomas, Erdman, Burke 2016] could not be checked for these figures, so it is not cited for them. Re-check 2026-11-04: neither position's abstract carries the figure and both full texts are paywalled; the 20-35 % range is verified through Iraki 2019, ref. 10, which cites ACSM for it; §4 "Nutrition plan evaluation".)
- **Rate of loss:** 0.5-1 % of body weight per week [Helms, Aragon, Fitschen 2014]; default 0.5 %. (ACSM 2009 states 0.5-1 kg per week for the general population; the percentage suits lean trainees better.)
- **Rate of gain:** 0.25-0.5 % of body weight per week [Iraki et al. 2019; slower for advanced lifters].
- **Energy constant:** 7 700 kcal per kg is an approximation, used only without history; with history the adaptive estimate is used [Hall 2008; Hall et al. 2011].
- **Target check (T-180, *design decision*):** the target must stay within the rate range of the intention measured from the user's capped intake (`04` §8.7), so a surplus or deficit is never stacked on top of an expenditure that already absorbed it.
- **Calorie change is proposed and needs the user's approval (user decision 2026-11-05, E14 feature 3; supersedes "applies on its own inside the safe band" and its "Deshacer" below, and the matching lines of §1, §12.1, §12.6, §12.7 and §12.8):** when the trigger below fires, the app **proposes** the change in the weekly summary and the Trainer tab with "Aplicar" / "Ahora no"; nothing changes until the user taps "Aplicar". The trigger, the 10 % per-change limit, the 14-day spacing, the clean-data gate and the safe band are unchanged; an applied change counts towards the band. "Ahora no" keeps the calories, does not count towards the band and restarts the 14-day clock; after two "Ahora no" in one block, no more proposals until the end-of-block review (the two-undo rule below, re-read for proposals; *design decision*). A pending proposal is replaced by the next week's computation, never stacked. Why approval: a calorie change touches every logged meal and the targets the user plans around; proposing and confirming is *common practice in leading apps* (MacroFactor and Carbon, E14 competitor review; product evidence, not re-verified in this session); explaining the rationale and offering choice is the autonomy support associated with better health behaviour (73 studies) [Ntoumanis 2021, ref. 55, re-opened 2026-11-05; *strong* for the mechanism, modest effects]. No trial compares automatic with approved calorie changes (*none*). Copy: "Te proponemos bajar 150 kcal: llevas 2 semanas perdiendo menos de lo previsto." with "Aplicar" / "Ahora no".
- **Adjustment inside a block (history: "applies on its own inside the safe band", user decision 2026-11-01, superseded by the approval rule above; the trigger, band and limits still apply):** made only when the plan's target rate is outside the confidence interval of the weight trend for two consecutive weeks, and only on clean data (§2 data cleaning); one change moves calories by at most 10 %, at least 14 days apart. **Safe band (*design decision*):** automatic changes inside one block add up to at most ±10 % of the block's accepted calories (net: an undone change does not count), never cross the floor (ADR-25), the 500 kcal deficit cap or the intention's rate range (target check above); a change that would leave the band waits for the end-of-block review, where it needs the user's OK. **Reference expenditure:** the total expenditure in use at the moment of the change (`04` §7.2: adaptive when reliable, else the intake prior or BMR × factor). Maintenance and recomposition: the target stays within ± the energy of 0.25 %/week of body weight around it (the no-change range of `04` §8.7), so a maintenance user gaining faster than the trend allows **does** get a decrease, down to the bottom of that range; if the gain persists there, the adaptive expenditure will move and the review takes over. **Undo:** each change shows its reason and "Deshacer"; undoing restores the previous calories, does not count towards the band and restarts the 14-day clock (the user's decision is respected for two weeks); after two undos in one block, no more automatic calorie changes until the review (*design decision*). This matches "the smallest possible deficit that yields appreciable weight loss", adjusting intake when loss plateaus [Trexler, Smith-Ryan, Norton 2014; *moderate*, review, athletes].
- **Deficit cap (cut phase):** the daily deficit below the expenditure in use is at most 500 kcal, even when the rate (0.5 %) would ask for more; then the slower rate is kept. Energy deficit impaired lean-mass gains during resistance training (ES -0.57) but not strength (ES -0.31, n.s.); "an energy deficit of ~500 kcal · day-1 prevented gains" in lean mass, and the authors advise avoiding deficits above 500 kcal a day to preserve it [Murphy, Koehler 2022; *strong*, meta-analysis; the 500 figure is a meta-regression reading]. Slower loss preserves lean mass better in leaner people [Aragon et al. 2017, ISSN; *strong*].
- **Phase calories (§12.3):** cut by the rate and the cap above; gain by the existing rate by experience; maintenance and recomposition at rate 0 (the regain phase was removed by ADR-91 and the minimal phase by the user on 2026-11-03).
- **After a cut:** the next phase starts at the measured maintenance in one step. Reverse dieting (raising calories gradually) is unproven, "research is needed to evaluate its efficacy" [Trexler 2014], so it is not prescribed; the in-block adjustment above corrects drift.
- **Diet breaks (optional, *mixed* evidence):** inside a cut the user may choose "Con semana de descanso": weeks 1-3 of the block in deficit, week 4 at maintenance. In resistance-trained adults, 3-week deficit blocks separated by 1 week at energy balance gave the same fat and fat-free mass loss as continuous dieting, with lower hunger (P = 0.002) [Peos et al. 2021; *moderate*, RCT, n = 61]; in men with obesity, 2 weeks on / 2 off lost more weight and fat (14.1 vs 9.1 kg) with a smaller adjusted drop in resting expenditure [Byrne et al. 2018; *moderate*, other population]; the ISSN finds "no significant advantage over daily caloric restriction" for body composition [Aragon 2017; *strong*]. So it is an adherence and hunger tool, not a faster cut: default off, the cut simply takes longer; only deficit weeks count towards the cut's length (§12.3). Refeeds are not prescribed ("more research is needed", Trexler 2014).

### Nutrition plan evaluation (T-217, fitness-scientist 2026-11-04; decided, as T-216; covers only what is built today; code changes wait for their task)

**Scope:** the nutrition plan as built (`plan_nutrition`, `plan_recompute`, the "Plan nutricional" proposal screen, the Diario goals it writes). Out of scope for now: anything not built (weekly report T-166, chat T-169, E14 review, phase changes and in-block automatic changes).

**What a good plan is for a lifter (sources opened 2026-11-04: §10 refs 95-103 new; 7, 9, 10, 26, 59, 60 re-checked).** Only four things carry evidence; everything else is noise for the figures.
1. *Calories by phase:* cut 0.5-1 % of body weight per week [Helms 2014, ref. 9; *moderate*, natural bodybuilders, narrative review], deficit at most ~500 kcal/day [Murphy 2022, ref. 59; *strong*, meta-regression; slower loss protects lean mass in leaner people, Aragon 2017, ref. 60, *strong*]; gain 0.25-0.5 %/week, advanced ~0.25 % [Iraki 2019, ref. 10, Table 1; *moderate*, bodybuilders]; a larger surplus added fat (+15 vs +3 %) with no extra lean mass [Garthe 2013, ref. 96; *moderate*, RCT, 39 elite athletes]; maintenance and recomposition at rate 0 (*design decision*, §9). The existing §4 rules already implement this.
2. *Protein:* the daily total is the lever: gains in fat-free mass stop rising beyond 1.62 g/kg/day [Morton 2018, ref. 7; *strong*, healthy adults; smaller effect with age, larger in trained]; ISSN 1.4-2.0 g/kg, 2.3-3.1 g/kg in a deficit [Jäger 2017, ref. 95; *strong*, position stand]; 2.3-3.1 g/kg of fat-free mass in lean trained dieters [Aragon 2017, ref. 60]. The app's 1.8-2.2 g/kg of body weight sits inside these (no body-fat input, §9).
3. *Fat floor:* 20-35 % of calories, "conforming to The American College of Sports Medicine recommendations for athletes" [Iraki 2019, ref. 10; *moderate*]; 15-30 % in contest prep [Helms 2014]; low-fat diets lowered total testosterone in men, SMD −0.38 [Whittaker 2021, ref. 98; *moderate*, 6 studies, 206 men; an erratum exists]. So 20 % stays the floor.
4. *Carbohydrates:* the remainder. In 49 studies higher carbohydrate did not improve strength in 13 acute studies and did in 6, "no evidence of a dose-response effect" [Henselmans 2022, ref. 99; *moderate*, systematic review, mixed]; no g/kg minimum is set.
- *Meal structure and timing: guidance only, never a rule.* Protein timing showed no effect once total protein was controlled ("total protein intake was the strongest predictor") [Schoenfeld 2013, ref. 97; *strong*]; meal frequency's apparent benefit came from "a single study" [Schoenfeld 2015, ref. 100; *strong*, null]; ISSN: 0.25 g/kg or 20-40 g per dose, every 3-4 h [ref. 95]; 0.4 g/kg over at least 4 meals is an estimate the authors call speculative for mixed meals [Schoenfeld, Aragon 2018, ref. 26; *weak-moderate*]. The existing one line "Reparte la proteína…" stays as an optional tip; no meal times, no meal count rule.
- *Diet type:* "a wide range of dietary approaches" are "similarly effective"; success "depends upon compliance" [Aragon 2017, ref. 60; *strong*]. So preferences matter for adherence, not for the figures.

## 5. Weight and measurements

- **Daily weigh-in** recommended: day-to-day changes of 1-2 kg from water, glycogen and gut content make a single weigh-in uninformative.
- **Trend:** slope over weekly averages, shown with its confidence interval computed from the real spread of the user's weigh-ins. There is no minimum of data to use the app; data only changes the confidence shown.
- **Reminders (E10):** weight after 2 days in a row without a weigh-in; circumferences after 14 days without measuring (*design decision*: circumferences change slowly).
- **Body composition:** impedance body fat is unreliable; circumferences are a secondary reference and their uncertainty is shown.

## 6. Outcomes set by the coach

- Weight, body fat, circumferences or e1RM per lift, depending on the intention and the plan. (T-161 ships weight and e1RM per lift: the figures are derived by the server from the summary and the model only picks, explains and sets the deadline; body fat and circumferences wait for data the summary does not carry.)
- Each outcome carries its reason and its deadline (normally the end of the block).
- The user cannot set an outcome's value; they can turn an outcome off. `profiles.target_weight_kg` stops being a user input (ADR-78).

## 7. Discomfort and safety

- Logging discomfort on an exercise (E12) blocks load increases for that exercise for 7 days, or until the user confirms "Ya no me molesta" (**open** discomfort, `04` §4.12).
- **Unresolved severe discomfort (*design decision*, separate from "open"):** a level 4-5 discomfort stays **unresolved**, whatever its age, until the user taps "Ya no me molesta" or completes step 3 of the graded return below. While unresolved it stays visible on the exercise with "Ya no me molesta" and drives the health note (14 days unresolved). *Superseded (T-219, user 2026-11-04: discomfort is not an input of block creation):* "keeps the exercise out of the next block (§12.4)". The 7-day "open" window still governs only the load block of levels 1-3.
- The user picks a **level** (1 to 5, ADR-81) when logging a discomfort; the two highest levels (swelling, tingling or numbness; sharp pain or injury) are severe. The level, not the text, drives the coach. Levels 1-3 block load increases only (the reps rule and the 5 % drop still apply) and the suggestion's reason states neutrally that the load is kept because of the open discomfort; levels 4-5 give no suggestion for that exercise (E13 Q1, user 2026-10-29). No diagnosis and no medical advice.
- **Scope of "no generic disclaimers" (user rule 2026-11-01):** it covers the whole app, not only the coach. A health line is allowed only when it comes from the user's own data **and** goes with a decision the app takes. So the pre-E13 `metric_disclaimer` (T-081) and the underweight "consulta con un profesional" line in the goal sheet go, unless the app attaches a decision to that underweight state (it does not today). Owner: PM, as a fix task.
- **Train around the affected area (an unresolved level 4-5 discomfort; the intake injury area was removed by ADR-91; amended by T-219):** inside a block, the level 4-5 swap offer of §12.8 row 7 and the graded return below apply. Block creation does not read discomforts (user 2026-11-04): the user picks every exercise (§3 "Block builder"). *Superseded:* "the next block leaves out the exercises the user flagged at level 4-5 (the model never picks a flagged exercise; checker H6)" and "which exercises load the area is model judgement". Stopping training reduces every component of strength (submaximal SMD -0.62, maximal force -0.46, power -0.20), with a dose-response on the length of the stop, larger in people over 65 and in inactive people [Bosquet et al. 2013; *strong*, meta-analysis]; so keeping the healthy areas trained has a cost-of-not-doing argument. *Common practice built on that evidence.*
- **Graded return after an injury (*common practice in leading apps*, product benchmark, about 6 weeks; no sourced ramp figure, steps are *design decisions*; no treatment):** for the flagged exercise, three steps, each lasting at least one week: (1) a substitute of the same movement pattern the user has not flagged; (2) the original exercise at the last load before the discomfort, with a routine note to use only the range that does not bother ("Rango sin molestia"; partial and full range differ little, see §3 "Range of motion"); (3) full range with normal progression. The app offers the next step after a week with no new discomfort on it; **the user decides when to move on**. A new discomfort at the same level or higher sends it back one step; at level 4-5, back to step 1. The level is the only signal.
- **Health note from the user's own data (user decision 2026-11-01; amends ADR-81's "nothing else is shown"):** no generic disclaimers anywhere in the app. A specific note is shown **once per discomfort** when a level 4-5 discomfort persists: still unresolved 14 days after it was logged, or logged at level 4-5 on the same exercise in 3 sessions. It states the fact and the decision the coach already took: "Esta molestia sigue ahí desde hace 14 días. Seguimos entrenando el resto sin cargar esta zona. Puede merecer la pena que te lo revise un profesional." Shown in the coach's report and on the discomfort row, dismissible, never blocking. Trigger and wording: *design decision, grade none*: no verified threshold for when persistent exercise pain warrants a check (clinical pain-monitoring trials use clinician-set thresholds that could not be verified, §10 note); 14 days matches two 7-day blocks of §7's first bullet.
- Free text (intake, check-in and discomfort notes, "¿Cómo te ha ido?") reaches the model as context (§8), shown to the user exactly as sent. It is **never matched against terms**, never triggers a health message (the note above is triggered by levels and dates only), never used to diagnose, and never changes a figure by itself: every number and trigger uses structured fields (no fields are extracted from the text, ADR-91).
- Muscle soreness is not collected: it is a poor indicator of recovery or of adaptation [Schoenfeld, Contreras 2013; Nosaka et al. 2002].

## 12. Long-term follow-up: the trainer journey

User-approved direction (2026-11-01). How the coach follows one person for months or years. **Evidence caveat:** the coaching *process* (intake, weekly review, when to change phase) has almost no outcome trials; the evidence covers the levers (energy, volume, deloads, detraining, retraining) and two behavioural mechanisms (self-monitoring [Burke et al. 2011], autonomy support [Ntoumanis et al. 2021]). Sequencing phases over a year has no trial in recreational lifters (*none*): §12.3's durations are *design decisions* anchored where stated. Every figure is computed server-side (§1).

**Who decides:** *Rule* = deterministic server code (all numbers and all triggers). *Model* = the LLM chooses among server-validated options and explains, reading the structured summary and the free-text block (§8). *User* = accepts or edits phase changes and new blocks; undoes or cancels any automatic change (load, deload), applies or declines a calorie proposal (E14, §4), or starts a deload (§1).

### 12.2 First block (cold start)

The first block is made in the block builder (§3 "Block builder"; *superseded:* "passes the routine checker"): 10 weekly sets per major group, the builder's per-slot reps, target RPE 8. Starting loads come only from the user's own logged sessions or the load the user enters. After 14 or more days without a completed session, the first session of each exercise keeps the last load, with no increase, and one failed session (instead of two) triggers the 5 % drop, so loads re-adjust from the first sessions back (*design decision*; §12.5). Retraining at ordinary doses regains quickly [Halonen 2024; Staron 1991], and no study prescribes a different dose for retraining (*none*), so someone coming back after a break gets the normal ranges.

### 12.5 Busy periods and breaks

- **Busy or travelling:** the user changes days or place ("Revisar el bloque", §12.8) or uses "Solo unos días". (Minimal phase removed, user 2026-11-03; re-plan in E14.)
- **Breaks follow the plan, not the calendar (*common practice in leading apps*, product benchmark):** a calendar week with no completed session does not count as a block week, so the block pauses and the user resumes at the next planned session, where they left off (the end-of-block review and the week-3 deload evaluation move with it). Loads re-adjust from the first sessions back (§12.2: no increase on the first session, one failed session triggers the drop after 14 or more days off).
- **Long break:** the paused block resumes where it stopped (no regain phase since ADR-91). Losses scale with the length of the stop and are larger over 65 [Bosquet 2013; *strong*]; retraining recovers them quickly and "trainees should not be too concerned about occasional short-term training breaks" [Halonen 2024; *moderate*]. The 14-day threshold and the absence of a sourced load cut on return are *design decisions*.
- **Illness:** no rule (none verified).

### 12.6 Weekly follow-up

The weekly report shows the weekly average weight and trend against the target rate, logged diary days, sessions done against planned, open discomforts and the loads changed automatically that week, each with its reason. Self-monitoring of diet and self-weighing are consistently associated with weight loss (Class IIa, Level A; self-weighing at least weekly may help) [Burke 2011; *moderate*]; explaining the rationale is part of the autonomy support associated with better health behaviour [Ntoumanis 2021]. Weekly changes are limited to calorie changes inside the §4 safe band (only on clean data), **proposed and applied on the user's "Aplicar"** (E14, user 2026-11-05), and the §3 deload, applied on its own with "Cancelar descarga"; phase and volume change only at the end-of-block review, with the user's OK. **E14 (user 2026-11-05):** the weekly summary uses fixed templates with no model (D4), appears in the Trainer tab with one notification (D5) and adds sets per muscle group and "¿Por qué no progreso?" (§3 "Block follow-up" (3), (7)); the model-written report is kept only for the later epics.

- **"Adaptar el bloque"** (default for a place or equipment change only; *rule*, no model call, free; amended by T-202/ADR-93: there is no server split any more, so a days-per-week or session-length change offers only "Bloque nuevo" and "Solo unos días", rows 2-3). It keeps the block week, the phase, the sets per muscle group and the rep ranges. Exercises the new equipment cannot do are swapped by the server to a candidate with the same muscle group and movement pattern, in the order of §3 "Exercise selection" (T-179). With no such candidate it takes any candidate of the same muscle group; with none at all, the slot is dropped and the preview says so. The cardio exercise is re-picked by the §3 default ranking, with the same minutes. The user sees the preview and applies it with one tap.
- **"Bloque nuevo"**: an early end-of-block review (§12.4) that opens the block builder with the new preferences (§3 "Block builder"; a rule, no model call, free; *superseded:* "*model*, a paid call"). It needs the user's save like any new block.
- **"Solo unos días"**: the user picks an end date. The swaps apply only to sessions until then, and then the original routines and their loads return untouched. Fewer training days in that period: minimal phase removed (user, 2026-11-03); re-plan in E14. The block's phase and calories do not change.

**Loads for an exercise new to the block (every row):** the planned weight is the user's last working weight on that exercise (their own history). Without history there is no planned weight, and the first session finds it by RPE: the user picks a weight they can lift for the bottom of the range at RPE 7-8 (RIR 2-3, §3). A load is never converted from another exercise: no conversion between exercises was verified (*none*). Double progression starts from that session.
