# Data model (Supabase Postgres) - current state

Compact summary; full column tables, constraints and RPC contracts are in [`phase1/03-data-model.md`](phase1/03-data-model.md) (frozen). The authoritative schema is `supabase/migrations/`. New schema decisions: a new ADR in `00-decisions.md`, then update this summary.

## Conventions
- All tables in `public`; `id uuid` PK default `gen_random_uuid()` unless stated; `created_at` and trigger-maintained `updated_at`.
- `user_id uuid not null default auth.uid() references auth.users(id) on delete cascade` (every user-owned table cascades; ADR-29). Nullable author columns pick `cascade` or `set null`.
- RLS enabled and forced on every table; owner policy `user_id = (select auth.uid())` for select/insert/update/delete. Closed value sets are Postgres enums.
- Calendar dates (`log_date`) are `date` in the device's local time zone; instants are `timestamptz`.
- No default privileges for `anon`; every new object needs an explicit grant to `authenticated`/`service_role`.

## 1. Enums
`sex`, `activity_level` (sedentary..very_high), `goal_strategy` (deficit/maintenance/surplus), `meal_type` (default meal codes), `food_source` (off/user), `food_base_unit` (g/ml), `food_cooking_method` (raw/griddle/air_fryer/fried), `measurement_source` (manual/health_connect), `circumference_site`, `muscle_group`, `equipment`, `session_status` (in_progress/completed/discarded), `exercise_metric_type` (weight_reps, reps_only, duration, weight_duration, distance_duration, bodyweight, assisted, weighted, steps_duration, floors_duration), `set_type` (working/warm_up/failure/drop), `notification_kind` (weight/circumference/weekly_check_in), `coach_value_key` (activity_level/total_expenditure/weight_trend/experience, T-157).

## 2. Profile and goals
- `profiles` (id = auth user): display_name, avatar_url (Google, `https://` only), birth_date, sex, height_cm, activity_level, onboarding_completed (the former `target_weight_kg` was dropped in T-162, ADR-78: the weight outcome now lives in the accepted `coach_plans.outcomes`). Created by the `on_auth_user_created` trigger (sanitized metadata); `on_auth_user_metadata_updated` refreshes the avatar only. Client has SELECT and column-level UPDATE; no delete. Current weight is the latest `body_measurements` row.
- `nutrition_goals` (one per user): strategy, calorie_adjustment, target_kcal, protein/carbs/fat percentages. Written together with `profiles` through `save_preferences`.

## 3. Nutrition
- `foods`: source (`off`/`user`), barcode, off_id, base_unit, nutrition per 100 base units (kcal, macros), `micronutrients jsonb` (35 label keys), `off_data jsonb` (full OFF product, Edge-Function-written only), serving fields, image_url, created_by, `search_vector`, `fetched_at`. Shared cache for OFF rows; manual foods are owner-only (editable, ADR-53).
- `food_portions` (food_id, label, amount in base units, position).
- `food_log_entries`: log_date, meal_slot_id, food_id, resolved `amount`, `portion_label`, snapshots of kcal/macros/`food_name`, `cooking_method`, `cooking_oil_retained_g` (added fat g), nullable `group_id`/`group_name` (saved-comida group snapshot, ADR-68).
- `meal_slots` (label, position, `enabled` always true; deleted when unused, at least one stays; ADR-41). Seeded Desayuno/Comida/Merienda/Cena at onboarding.
- `meal_templates` ("comidas", unique name per user, suggested slot nullable) + `meal_template_items` (food, amount, portion, cooking_method).
- `food_preferences` (one per user): fat % for griddle / air fryer / fried (0-20).
- `meal_defaults` (user, meal_slot, template, ISO weekday; one per slot+weekday) and `diary_default_applications` (user, log_date marker; idempotent daily apply).
- `favorite_foods` (user, food).

## 4. Weight
- `body_measurements`: measured_at, weight_kg, body_fat_pct, lean_mass_kg, water_kg, bone_kg, bmr_kcal (composition only from Health Connect), source, `external_id` (HC dedup), `hc_record_id` (copy written by the app). The onboarding weight is the user's first row.
- `body_circumferences` (site, value_cm, measured_at). `health_sync_state` (last sync per user; `last_auto_sync_date` date, nullable, written only by `mark_health_auto_sync`).
- Watch data (T-140, [E11](epics/E11-health-connect-daily-sync.md)), all owner-only (RLS enabled and forced, select/insert/update/delete own with `(select auth.uid())`, `on delete cascade` from `auth.users`):
  - `daily_activity`: unique `(user_id, day)`, `steps` 0-1000000, `active_kcal` and `total_kcal` numeric(8,2) 0-100000, all value columns nullable.
  - `sleep_sessions`: unique `(user_id, external_id)`, `started_at`, `ended_at` (> started_at), `minutes` 1-1440, `stages` jsonb array (`[{stage, started_at, ended_at}]`).
  - `resting_heart_rate`: unique `(user_id, day)`, `bpm` 20-250, `external_id` (informational).
  - RPC `import_health_activity(p_daily, p_sleep, p_resting_hr) -> {daily, sleep, resting_hr}` (rows written; max 400 per array, `22023` otherwise; upserts, last duplicate wins; does not touch `health_sync_state`). RPC `mark_health_auto_sync(p_day)` upserts the state row and sets only `last_auto_sync_date`. Both `security invoker`, `authenticated` only.
- `notification_settings` (T-135, US-57): `(user_id, kind)` primary key, `enabled`, `updated_at`; owner select/insert/update (no delete), client upserts on `(user_id, kind)`. **A missing row means enabled.** Reminders are derived on the client from the latest weight and circumference rows, never stored.
- `exercise_discomforts` (T-147, US-67): `id`, `user_id` (default `auth.uid()`, cascade), `exercise_id` (cascade), `logged_at`, `level` smallint not null (check 1-5, T-152/ADR-81; immutable after insert), `note` text 1-200 chars (nullable, never interpreted), `resolved_at` (check >= `logged_at`); index `(user_id, exercise_id, logged_at desc)`. RLS enabled and forced, owner select/insert/update, no delete (history for E13); update grant only on `resolved_at`. The 7-day open window is evaluated in the client. pgTAP covers isolation and constraints.
- `weekly_check_ins` (T-136, US-59): `(user_id, week_start)` primary key, `week_start` is an ISO Monday (check), `energy` smallint 1-5 (check), `notes` text <= 1000 chars, `created_at`, `updated_at` (trigger). RLS enabled and forced, owner select/insert/update (no delete), `(select auth.uid())`; pgTAP covers cross-user isolation.
- `profiles.check_in_weekday` (T-136): smallint 1 (Monday)-7 (Sunday), default 7, check 1-7; the only new column the client may update (column grant).

## 5. Training
- `exercises`: catalogue rows hold only `key`, `muscle_group`, `secondary_muscles`, `equipment`, `metric_type`, `per_hand`, `movement_pattern` (names/text/images come from the client bundle, ADR-38/39); custom rows (`is_custom`, owner) have a name. T-150 (ADR-78): `movement_pattern` is enum `movement_pattern` (squat, hinge, lunge, horizontal_push, vertical_push, horizontal_pull, vertical_pull, carry, core, isolation, cardio, other), nullable; every catalogue row is filled from the reviewed mapping `scripts/exercise-movement-patterns.csv` (generator checks coverage), custom rows may leave it empty and it is only data for the E13 coach (never shown on catalogue exercises). RPC `update_custom_exercise(p_id, p_name, p_muscle_group, p_equipment, p_per_hand, p_movement_pattern default null)` (security invoker, owner only; null clears the pattern). Creating a custom exercise is a plain insert that accepts `movement_pattern`.
- `routine_folders`; `routines` (name unique per user, folder_id, `track_as_routine`, `is_next`, pinned_note); `routine_exercises` (position, superset_group, target_rpe, rest_seconds, legacy summary columns) and `routine_exercise_sets` (planned weight/reps/type per set, ADR-54).
- `training_preferences` (one per user): warm_up_included, previous_values_mode, bar_weight_kg, plate_kg, dumbbell_handle_kg, auto_update_routine (global, ADR-70); "Mi entrenamiento" (T-149, US-65): intention (enum `training_intention`: strength, muscle, fat_loss, recomposition, maintenance; nullable), place (enum `training_place`: home, gym, other; nullable), equipment (`equipment[]`, default empty), days_per_week (1-7, nullable), session_minutes (15-180, multiple of 5, nullable). Saved by a direct upsert of these five columns, not by `save_preferences`.
- `workout_sets` and `routine_exercises` carry `notes text null` (T-148: check 1-200 chars, blank stored as null; set notes are never copied to routines and `update_routine_from_session` leaves routine notes untouched). The live session reads the routine's exercise notes by `routine_id` at load (no snapshot). `workout_sessions`: routine_id (set null on routine delete), name snapshot, status, started_at/ended_at, description, gym, paused_at, paused_total_s, exercise_rests. `workout_sets`: session, exercise, exercise_position, superset_group, set_index, set_type, rpe (6-10), weight_kg, reps, duration_s, distance_m, steps, floors, completed_at (null = pending).
- Rep range (T-159, US-70): `routine_exercises.rep_min/rep_max smallint null` (both null or both set, 1-50, min <= max; legacy `target_reps` untouched) and a snapshot `workout_sets.rep_min/rep_max` copied by `start_workout_session` from the routine exercise (free workouts and `save_completed_workout` leave it null). `save_routine` accepts optional `rep_min`/`rep_max` per exercise (both or neither, else `22023`); `update_routine_from_session` carries the range over.
- `coach_confirmed_values` (T-157, `04` §7, `07` §2): PK `(user_id, key)` with `key` enum `coach_value_key`; `estimate` (server estimate at confirmation: activity factor, kcal, kg per week or experience ordinal 0-2), `uncertainty` (half-width, >= 0), `level_value` (confirmed or edited activity level, only for `activity_level`), `edited`, `confirmed_at`, `updated_at`. RLS owner-only (select/insert/update, no delete); written by `confirm_derived_values`. It is not part of the coach history, so "Eliminar historial del entrenador" keeps it; deleting the account removes it (cascade).

- `coach_usage` (T-160, `07` §11): PK `(user_id, month)`, `month` the first day of the UTC month (check), `input_tokens`, `output_tokens` (bigint >= 0), `cost_eur` numeric(12,6) >= 0, `updated_at`. RLS owner select only, no insert/update/delete privilege for `authenticated`; written only by `coach_record_usage(p_user, p_month, p_input, p_output, p_cost)` (atomic upsert that adds to the row) and totalled by `coach_global_month_cost(p_month)` (one number), both `security definer`, `service_role` only. Removed with the account (cascade).

- `coach_plans` (T-161, `04` §8): `id`, `user_id`, `block_start`, `block_weeks` (1-12, default 4), `intention` (`training_intention`), `nutrition` jsonb object, `outcomes` jsonb array (default `[]`), `method` jsonb object (model, attempts, cost, constants version), `status` (`proposed|accepted|superseded|discarded`, check), `data_version` (1), `created_at`, `accepted_at`, `updated_at`. Partial unique indexes: at most one `accepted` and one `proposed` plan per user. RLS owner select only; written only by the RPCs of §6. `nutrition` (data_version 1): `intention, weight_kg, expenditure_kcal, expenditure_source, rate_pct_week, rate_kg_week, target_rate_pct, limited_by (null|floor|goal_range), floor_kcal, target_kcal, calorie_adjustment, strategy, protein_pct, carbs_pct, fat_pct, protein_g, carbs_g, fat_g, protein_g_per_kg, distribution {per_meal_g, g_per_kg, min_meals}, requires_confirmation, unconfirmed[], edited_by_user, calorie_changes`. `outcomes[]`: `{kind (weight|e1rm), key, target_value, unit, reason, deadline, basis}`.
- `coach_recommendations` (T-161, US-74): `id`, `user_id`, `plan_id` (nullable, cascade), `kind` (`plan|calorie_change`, text + check so later tasks swap the check), `payload` jsonb, `reason` (a code such as `rate_outside_interval`; Spanish text lives in the UI), `input_summary` (the `coach_summary` used), `status` (`pending|accepted|edited|discarded`), `created_at`, `decided_at` (null iff pending, check). RLS owner select only. Both tables are removed with the account (cascade).
- Trigger `nutrition_goals_flag_manual_edit` (after insert or update on `nutrition_goals`, `security definer`): a change of `target_kcal`, `strategy`, `calorie_adjustment` or a percentage made outside the coach RPCs (they set `app.coach_write = 'on'` for their own write) sets `nutrition.edited_by_user = true` on the user's accepted plan (E13 Q8). It covers every Preferencias RPC without redefining them.

## 6. RPC functions (all `security invoker`, `authenticated` only, owner-scoped)
- Profile: `save_preferences` (profile + goals + optional weight, one transaction).
- Weight: `save_body_measurement`.
- Training session: `start_workout_session`, `pause_/resume_workout_session`, `finish_workout_session`, `discard_workout_session`, `delete_workout_set`, `set_session_rest`, `last_performance`, `save_completed_workout`, `save_workout_as_routine`, `update_routine_from_session`.
- Routines: `save_routine` (jsonb with per-exercise planned sets, `target_rpe`, supersets share set counts).
- Records and stats: `exercise_history`, `weekly_muscle_volume`, `exercise_session_records`, `personal_records`, `training_summary`, `weekly_set_counts`, `muscle_group_sets`, `exercise_set_counts`, `weekly_records(p_from, p_to)` (records set in the range by UTC session date, from `personal_records`, without cumulative `total_reps`; rules in `04` §4.8, §4.11, §6).
- Food: `create_personal_food`, `update_personal_food`, `personal_food_in_use`, `most_eaten_foods`, `food_diary_summary`, `cooking_impact`.
- Meals and comidas: `save_meal_structure`, `list_meal_slots_in_use` (legacy `save_meal_slots`, `delete_meal_slot`), `save_meal_template`, `save_meal_as_comida`, `save_meal_defaults`, `apply_meal_defaults`.
- Coach (T-157, `04` §7): `coach_derived_estimates(p_today)`, `confirm_derived_values(p_today, p_activity_level default null)`, `coach_summary(p_today)` (jsonb; `22023` when `p_today` is more than one day from UTC today); internal helpers `coach_guard`, `coach_compute`, `coach_activity_estimate`, `coach_weight_trend`, `coach_intake`, `coach_experience`, `coach_basal_kcal`, `coach_activity_factor`, `coach_e1rm`, `coach_week_start`.
- Progression (T-159, `04` §4.14): `progression_suggestions(p_session_id)` returns jsonb `[{exercise_id, rep_min, rep_max, action, base_weight_kg, goal_reps, reason, used_rpe, sets_used:[{session_date, weight_kg, reps, rpe}]}]`; `security invoker`, reads only the caller's sessions, another user's session id gives `[]`.
- Coach plans (T-161, `04` §8; exception to "security invoker": `security definer`, `set search_path = ''`, every statement filtered by `auth.uid()`, because the tables have no write policy): `propose_coach_plan(p_block_start, p_intention, p_nutrition, p_outcomes, p_method, p_input_summary)` -> `{plan_id, recommendation_id}` (supersedes the older proposal and discards its recommendation), `accept_coach_plan(p_plan_id, p_today)` (nutrition only; `55000 derived values unconfirmed` while a gate value is provisional; writes `nutrition_goals`), `discard_coach_plan(p_plan_id)`, `evaluate_coach_calorie_change(p_today)` -> `{status: created|none, reason, recommendation_id?}` (deterministic, idempotent), `decide_recommendation(p_id, p_status, p_payload default null, p_today default null)` (calorie changes only). Extra error code `55000` wrong state.
- Error codes: `28000` unauthenticated, `P0002` not found / not owned, `22023` invalid input, `23505` duplicate name, `23514` check violation.
- The 1RM is computed in SQL with the same formula as the domain; domain and pgTAP tests share the cases.

## 7. Edge Functions (Deno/TS, `_shared/` holds the OFF and Gemini clients)

| Function | Auth | Behavior |
|---|---|---|
| `health` | public | `GET` -> `200 {"status":"ok"}` after `select 1`; keepalive target |
| `delete-account` | JWT | `POST`, resolves the caller from the token, deletes the auth user with the secret key (cascade); `403 account_protected` for `PROTECTED_EMAILS` (ADR-29, ADR-57) |
| `food-search` | JWT | `?q=` (2-60 chars): full-text in `foods`, then OFF (Spain, Spanish name, ADR-46) when < 10 results; normalizes, upserts, returns up to 20 |
| `food-barcode` | JWT | `?code=` EAN-8/13/UPC-A: `foods` first, OFF when missing or older than 30 days; `404` if absent or without kcal |
| `food-photo` | JWT | `POST` JSON `{image_base64, mode: dish\|label\|barcode\|weight, comment?, food?}` -> Gemini -> normalized draft or amount estimate (ADR-59, 64, 72); never stores or logs the image |
| `coach` | JWT | `POST` JSON `{kind: ping\|plan_nutrition\|plan_block\|report\|chat, input}` -> `text/event-stream` (`delta`, `done`, `error`); budget 2 EUR/user and 5 EUR global per UTC month. `ping` and `plan_nutrition` (T-161: input `{today}` only, answers one `delta` whose `text` is the plan JSON `{plan_id, recommendation_id, nutrition, outcomes}`) work; the rest answer `coach_kind_not_available` (501). Errors: `coach_limit_reached` 429 (`scope` user or global), `coach_no_credit` 402, `coach_timeout` 504, `coach_invalid_output` 502, `coach_kind_not_available` 501, `coach_missing_data` 422, `coach_plan_infeasible` 422, plus `UNAUTHORIZED`, `INVALID_INPUT`, `NOT_CONFIGURED`, `PROVIDER_ERROR` |

OFF client: custom `User-Agent`, 8 s timeout, normalization (base unit from `nutrition_data_per`).

## 8. Relationships
`auth.users` 1-1 profiles, nutrition_goals, health_sync_state, food_preferences, training_preferences; 1-n coach_confirmed_values (PK user + key), meal_slots, food_log_entries (n-1 foods, n-1 meal_slots), favorite_foods, meal_templates (1-n items n-1 foods), meal_defaults, diary_default_applications, body_measurements, body_circumferences, daily_activity, sleep_sessions, resting_heart_rate, exercise_discomforts (n-1 exercises), routine_folders 1-n routines 1-n routine_exercises (n-1 exercises) 1-n routine_exercise_sets, workout_sessions 1-n workout_sets (n-1 exercises); foods 1-n food_portions.
