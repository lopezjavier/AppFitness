## Design system showcase decision
Decision: reuse the debug catalog's composables, as a new gallery area "Design system" (not a new set of hand-built entries, not a new entry group under Compartido). Reasons: the catalog already holds one section per component with its states (enabled/disabled/pressed, sizes, tablet where present) and is the place new components must register in (so the showcase stays complete with no second list to maintain); `ComponentCatalogScreen()` is public and `CatalogSection` tags (`catalog_section_*`) and the `catalog_screen` LazyColumn tag are already production tags; zero production change; `CatalogRoute` stays exempt exactly as documented.
Mechanics:
- `DesignSystemGallery.kt`: `designSystemEntries()` scans `feature/catalog/*.kt` (reuse `GalleryCoverage.readSources` and the working-dir `GalleryChecks.SOURCE_ROOT`) for the section tags passed to `CatalogSection(...)` (regex on `"catalog_section_[a-z0-9_]+"`; the developer confirms all 60 calls use literals, otherwise lists the constants). One entry per tag: area "Design system", screen = the tag humanised, state "default", `tall = true`, content `ComponentCatalogScreen()`, `interact = { onNodeWithTag("catalog_screen").performScrollToNode(hasTestTag(tag)) }` (`performScrollToNode` works on the lazy list; `performScrollTo` does not on non-composed items). Because it is derived from the sources, a new catalog section appears in the showcase with no gallery edit.
- `tall`: new `GalleryEntry.tall` flag rendered by a new test class `GalleryTall` copied from `GalleryWide` with `@Config(qualifiers = "w360dp-h2200dp-xxhdpi")`, so a section taller than 640 dp is not cut; `GalleryCapture` and the other classes filter `!it.wide && !it.tall` (update every `.filter { !it.wide }` call in the gallery files: grep `!it.wide`). Sidecar JSON and index need no change.
- Tablet variant: a few entries (buttons, cards, rows, charts) with `wide = true` for the tablet type scale (the only second "theme"; dark is the only colour scheme, say so in the index intro or the entry state name).
- Completeness test in `GalleryCoverageTest` (or `DesignSystemGalleryTest`): the section list is not empty and every `catalog_section_` tag found in the sources has an entry (trivially true, guards the regex rot if the tag convention changes). **Decision (ux-reviewer): ADD the check, in slice 3.** Without it the showcase silently goes stale and R-39 ("a new component retires its ad-hoc copies") has no guard. Shape: `DesignSystemCoverageTest` scans `designsystem/**/*.kt` for public/internal top-level `@Composable fun Name(` (skip `private`, `Preview`, and functions whose name starts with a lowercase letter) and asserts each name appears in `feature/catalog/**/*.kt`, or is in `GalleryManifest.designSystemExempt: Map<String, String>` (name to non-blank reason; same shape and blank-reason test as `exempt`). Same rules as the route check: a stale exemption (name no longer in designsystem or now in the catalog) fails. The developer seeds the exemption map with the real gaps and states its size in the PR; if it exceeds ~25 names, keep the check but list the gaps in the E9 table with an owning task (T-281 to T-284 rounds) instead of exempting them silently. Add a self-test that the check names a synthetic missing component.
