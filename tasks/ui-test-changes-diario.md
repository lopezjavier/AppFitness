# UI test and golden changes, area Diario (input for the repair task)

Visual-first flow: each batch changes only code; the repair task fixes the tests and re-records the goldens. Each batch appends here what it breaks or leaves uncovered.

## Batch 1 (search, sheets, ring, check-in, notices)

Behaviour tests that will fail or need an update:
- Food search host tests (`FoodSearchScreenTest`, `FoodSearchOffFlowTest`, `BarcodeScanFlowTest`, `FoodLoggingFlowTest`, `QuickSearchFlowTest`, `FoodRestorationTest`, `CreateFoodRestorationTest`, `PhotoFlowHost` users): the field has no visible label; the scan is in the field trailing slot (`food_search_action_scan` is now inside the field); "Añadir con IA" (`food_search_action_ai`) and "Crear alimento" (`food_search_action_create`) are top-bar actions; the `Sin conexión` state description on the icons is gone; offline results show `OfflineState` (`offline_state`) instead of the `food_search_retry` error; the partial failure is an inline notice (`food_search_remote_error` + `food_search_remote_retry`) with the text "No se pudo buscar en Open Food Facts." (no longer an `ErrorState`); `FoodSearchScreen` gained `isOnline` (default `emptyFlow()`), `FoodSearchViewModel.isOnline` is new.
- Edit entry and food sheet tests (`food_sheet_delete`, `food_sheet_remove`): now a text-style danger `AppTextButton` with the delete icon; "Guardar" and "Eliminar" are at least 16 dp apart (`AppSheets` secondary slot padding). Tests that look for a `GhostButton` role/tone must be re-checked.
- Add sheet: the commit button reads "Añadir a <comida>" (meal name as typed) instead of "Añadir" (`food_sheet_commit` text assertions); with `pick` or no meal it stays "Añadir". The meal label is "Comida del día" (was "Añadir a:"). The button on a meal card and the search title read "Añadir a Desayuno" (no article): tests with "Añadir al desayuno"/"a la cena" text fail.
- Diario tests: an empty meal card no longer shows the remaining-kcal hint (`diary_section_<id>_empty_hint` removed; `MealSectionUi.showRemainingHint` and `remainingKcal` are now unused by the UI, kept in the state and covered by ViewModel tests); the ring status pill is always present ("Te quedan N kcal", "Objetivo cumplido", "Quedaron N kcal" for a past day) and `stateDescription` changed (`progress_ring_state_within` removed; "%1$s de %2$s kcal, <sentence>"); `ProgressRing` has a `pastDay` parameter. `ProgressRingTest`, `DiaryScreenTest`, `DiaryHistoryScreenTest` ring text assertions.
- Goals prompt: now a `NavigationRow` (`diary_goals_prompt`) with a flag icon and supporting line; the "?" help button (`diary_goals_prompt_help`) and its strings are removed. Tests that open that help fail.
- R-71 swipe: collapsed comida group is one `SwipeToDeleteRow` (`diary_group_<id>_delete`) that deletes all ingredients through `DiaryEvent.DeleteGroup`; expanded it is not swipeable. New tests needed: swipe collapsed group removes all entries (ViewModel + host), expanded group does not arm, ingredient swipe still removes one. `EntryActions` gained `onDeleteGroup`.
- Check-in: the three figures are `MetricTile`s in one row (`checkin_summary_volume|workouts|sets`) with a `TrendPill` delta and one caption (`checkin_summary_delta_caption`); the old per-card delta texts ("vs semana anterior", "Igual que la semana anterior") and the value strings with units are gone. `CheckInScreenTest` assertions on the three cards.
- Centro de avisos: reminders are `NavigationRow`s with per-type leading icons; copy is plural-aware ("Toca pesarte", "Llevas 1 día sin pesarte", "Llevas N días sin pesarte"; measures likewise); "Pendientes" shows no count at 0; loading skeleton is shaped like the rows. Tests asserting "No te has pesado en N días" and the count at 0 fail.
- Energy notice: copy changed ("Las calorías y los macros no cuadran. Declaradas: A kcal; los macros suman B kcal." and the "Parece un error: ..." variant now takes both numbers as arguments; `create_food_energy_warning_wrong` has two placeholders), warning icon added, text colour textPrimary.
- Create food form: nutrient fields are table rows (label start, 96 x 48 dp input with unit suffix, 56 dp rows, "de los cuales" indented); the labels no longer carry the unit ("Calorías por 100 g" keeps its basis, "Alcohol (g)" is now "Alcohol" with a "g" suffix; the spoken labels are unchanged); the two-column grid and its large-font fallback are gone. `CreateFood*Test` label-based finders (e.g. `hasText("Grasas (g)")`) must be re-checked.
- Strings: final periods added to error/offline messages of the Diario area (`diary_error_message`, `food_error_message`, `add_food_load_error`, `edit_entry_load_error`, ..., `checkin_save_error_offline`, `meals_offline_message`, `meal_defaults_offline`); `food_offline_message` removed; the photo mode hint is "Foto de un plato: calorías y macros". Any test asserting the old literals fails.
- Shared components changed (callers to re-check): `AppTextField` (`showLabel`, slot grows past 48 dp), `AppSearchField` (`showLabel`, `trailingAction`; other callers unchanged), `NavigationRow` (`supporting`, `leading`, `onClickLabel`), `AppSheets` secondary action top padding 4 dp -> 16 dp (also `CircumferenceSheet` and `WeightDaySheet` use it), `FoodSheet` Totals (macro letters coloured, numbers textSecondary: `MacroText`), `FoodEntryRow` (kcal titleMedium, macros via `MacroText`), `AppTextButton` (new), icons `ic_flag`, `ic_insights`, `ic_monitor_weight`, `ic_fact_check` (new).

Goldens expected to change (re-record):
- Food search (field without label, trailing scan, top-bar actions), add-food sheet, edit-entry sheet, food sheet totals and entry rows, Diario day (ring pill, empty meal card, add buttons, goals prompt), Diario loading skeleton, food sheet loading skeleton, check-in summary, Centro de avisos (icons, chevrons, skeleton), energy notice, create-food nutrient table, `ProgressRing` catalog entries, sheet footers with a secondary action (edit-entry, circumference, weight day).

Known gaps left for later batches or the repair task:
- R-27 "Escribe un nombre": needs a Blank name error in the comida name flows (core change: `TemplateNameError`, SaveTemplate and TemplateDetails ViewModels); not built in batch 1.
- Guard G19 (plurals in `check-ux-conventions.sh`) is not added here.
- Dead state fields kept: `MealSectionUi.showRemainingHint` and `remainingKcal` (UI no longer reads them).

## Batch 2 (tokens, containers, hero, leftovers)

Behaviour tests that will fail or need an update:
- C-25 `macroFat` is `#A78BFA` (was `energyAmber`): `AppColorsTest` and `MacroDefaultsTest` (macroFat equals energyAmber), `ContrastTest` (add macroFat on surfaceBase, surfaceRaised and surfaceOverlay to the contrast list, text >= 4.5:1 and graphic >= 3:1), `DesignSystemRound0Test`; any golden with a fat figure or bar.
- C-26 `LocalNestedContainer` (`nestedContainerColor()`): inside `AppBottomSheet` the state circle, `InlineNote`, `EnergyWarningNotice` and `SkeletonBox` highlight use `surfaceControl`; outside a sheet they keep `surfaceOverlay`. New test needed: the same `InlineNote` inside and outside a sheet.
- C-27 pinned footers (`AppScreen`, `StepScaffold`, `AppSheetLayout`) draw a hairline and a 16 dp fade through `Modifier.footerEdge`; the sheet footer only while `scrollState.canScrollForward`, `AppScreen` and `StepScaffold` always (they cannot know whether their content scrolls). Goldens of every screen with a pinned footer and of every sheet with a footer change. New test needed for the sheet case (short content: no edge; tall content: edge).
- C-28 `TemplateDetailsScreen` and `TemplateEditorScreen` foods are rows of one `AppCard` (`template_details_rows_card`, `template_editor_rows_card`), no longer separate lazy items: tests that rely on one LazyColumn item per food (scrolling to `template_details_item_<i>`) must be re-checked; the swipe rows are inside the card.
- C-29 `ProgressRing(compact = true)` (132 dp, 10 dp stroke, `headlineMetric` value) and the compact hero (`diary_hero_compact`: ring with stacked macro bars, short labels "Prot." / "Carb." / "Grasa") on phone width and font scale < 1.15; the full ring over three bars otherwise and in the wide two-column layout. `DiaryScreenTest`, `DiaryDashboard` tests that read the macro labels "Proteínas" etc. at default font scale must be re-checked; new tests needed: compact at 1.0, full at 1.15 and 1.3, first meal's `diary_section_<id>_add` displayed on a 360 x 800 dp window.
- C-33 `MonthCalendarGrid` resting days have no fill (only selected and today draw a circle): `MonthCalendarGridTest` background assertions, golden of the calendar and the day picker.
- C-37 `FilterChipRow(edgeToEdge = 16.dp)` in the meal selector, the portion selector, the exercise form sheet and the builder create-exercise sheet: the row bleeds to the sheet edge with 16 dp of content padding. Goldens of those sheets; `FilterChipRowTest` needs a case with `edgeToEdge`.
- C-40 the Diario date navigator (prev, label, next) is capped at 320 dp, start-aligned (`DiaryDateHeader`): tablet goldens and `DiaryDateHeaderTest` width assertions.
- C-41 the caret of `AppTextField` and `NumberInput` is `neonLime` (error colour while invalid) instead of `athleticCyan`: `NumberInputTest` (`NumberInputDefaults.colors(...).cursor`), golden-free.
- R-27 `NameSheet` shows "Escribe un nombre" (`name_sheet_blank`) under the field after the first edit when the name is blank (all callers: save as comida, meal names, folders, routines); `TemplateNameError.Blank` and `TemplateDetailsViewModel.nameErrorOf(..., edited)` show it in the comida editor after the first edit. `NameSheetTest`, `TemplateDetailsViewModelTest`, `TemplateEditorScreenTest`: new cases for blank after edit and no message before the first edit.
- G21 (new guard, R-72). `G19` was already taken by ADR-104, so the plural-count guard is `G21`; the ten existing plain strings with a count (`activity_chart_summary`, `live_calc_warm_up_sets_state`, `builder_warm_up_cap_hint`, `folder_review_result_*`, `folder_block_refused*`, `folder_block_group_option`) are an inline allow-list in `check-ux-conventions.sh` and are migration debt for their own areas. `ux-inline-text-allowlist.txt` lost `diary_remaining_hint` (the string no longer exists).

Not done: V-13 (R-44) was not confirmed by the sweep (no date or number format violation found in the Diario screens read in batches 1 and 2), so it stays PROPOSED.
